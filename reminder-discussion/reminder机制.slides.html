Reminder 机制 · 业界洞察内部代号：notion 方案

定义：agent loop 运行期间，由系统向消息流注入的短小、结构化指令/状态块 —— agent 的二级指令通道。
system prompt 是入职培训（primacy，静态），reminder 是定期备忘录（recency，事件触发）。

◎ 前置契约：在 system prompt 预声明标签语义（系统的话、与所附着消息无关、无需回复）。权威等级：reminder > 用户 > 工具数据，兼具抗注入价值。

解决的四个结构性问题

问题表现reminder 解法
注意力几何lost-in-the-middle，中段指令被淹没关键信息重注入 recency 高注意力区
Context rot~80K token 后指令遵循度下降事件触发式规则刷新，在相关时刻重申
状态漂移基于过期环境状态决策环境增量主动推送（文件变更、模式切换）
缓存失效动态内容改写前缀，全量 miss一律 append 消息流尾部，前缀纹丝不动

注入位置：三种载体，一条铁律 —— 事件发生在哪个时机，就搭哪班车

载体适用时机典型内容
随 user message用户新一轮 query 到来时间/环境等动态上下文、模式切换、检索命中
随 tool resultloop 执行中发生事件（模型决策前唯一的新输入）文件外部被修改、安全提醒、隐私字段标识
合成 user message无自然载体（会话恢复、压缩后、用户插话）上下文块、压缩后目标重申

不能注入的位置：assistant message（伪造模型发言，污染其对自身行为的认知）；凭空的 tool result（必须对应真实 tool_use id，只能"随"不能"造"）；system prompt（缓存原因）。

◎ 铁律：只附着在 append 前沿（当前正要发出的新消息），绝不回头改历史消息 —— 否则其后 KV cache 全灭。

我们的两个实践tool result 侧约束输出行为 · user 侧供给输入语境

两个实践正好覆盖 reminder 的两大载体：tool result 侧约束输出行为（什么不能给用户看），user 侧供给输入语境（此刻用户在哪、现在几点）—— 前缀零改动，缓存全程命中。

实践一 · 随 tool result：隐私字段屏蔽

问题：工具中间结果含隐私字段（标识符、号码等），推理需要用，但不应呈现给用户；逐个改造工具脱敏代价高且切断推理链。做法：框架层随结果附加 reminder，工具零改动：

tool result: { "contacts": [ { "name": "张三", "phone": "13812341234", "uid": "u_8f3a92c1" } ] } <system-reminder> 以上结果中 phone / uid 为中间隐私字段， 仅供你完成当前任务推理使用； 不得在给用户的回复中展示、复述或改写呈现。 </system-reminder>
  • 数据可用、不外泄：数据留在上下文（后续调用可能还要用 uid），只约束呈现行为
  • 就近生效：约束紧贴数据出现的位置，遵循度远高于 system prompt 里泛化的"注意隐私"
  • 权威等级清晰：即使用户要求"把手机号发我"，模型有依据拒绝或走脱敏路径
实践二 · 随 user message：时间与前台应用

问题：用户指代依赖此刻设备状态——"第4张照片"是哪张、"昨天"是哪天；这些每轮都变，进 system prompt 等于每轮全量 cache miss。做法：结构化前缀随当轮 user message 注入：

user: [用户输入时间：Tue 2026-08-25 15:43] [前台应用：图库] 给我详细描述一下第4张照片
  • 指代消歧："第4张照片" → 前台是图库 → 当前视图第 4 张，无需反问、无需先调工具探测
  • 相对时间解析："昨天 / 上周"有了锚点；时间精确到分钟也不破坏缓存（在尾部，不在前缀）
  • 意图路由：同一句话在不同前台应用下路由到不同 skill / 工具链
◎ 设计要点：只随当轮、不回改历史（append-only）；[键：值] 固定模板、字段顺序确定；system prompt 预声明"历史轮的值已过期，以最新一轮为准"；只放高频消歧字段，大体积环境信息走主动加载。
