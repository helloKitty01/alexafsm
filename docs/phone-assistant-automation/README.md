## 核心结论（当前版本）

1. **一切委托统一为 Task = Trigger + Goal + Policy**：普通对话请求只是 `immediate` 触发的特例；
   Goal 保留自然语言原话，只有 Trigger/Policy 结构化。
2. **事件分两层**：系统事件管理器管可穷举事件（订阅制、非 LLM、毫秒级）；
   自定义"盯梢"归约为 `cron 轮询 + LLM 判定`（或降级为可订阅的外部推送源），不发明第三种机制。
3. **双脑 + 任务摘要卡片**：omni 实时模型只当前台秘书，重活全部异步给后台深度模型；
   两脑靠中枢维护的任务摘要卡片（几十 token/任务）会合，前台不读后台全量上下文。
4. **`waiting_user` 是一等状态**：长任务中途澄清 = 挂起 + 结构化澄清请求（必须带默认路径）+
   打扰管理器择机触达；钱/对外发送/删除永不走默认路径。
5. **打扰管理器是主动性的唯一出口**：全双工让"随时插话"技术上免费、体验上极贵，
   所有主动触达按 speak_now / speak_at_pause / push / digest / hold 分级门控，且全部落收件箱可回查。
6. **中枢独立于 LLM 存活**：触发器引擎与任务存储做成系统级常驻组件，LLM 挂了不丢任务。
