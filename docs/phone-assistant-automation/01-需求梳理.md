# 01 需求梳理：手机智慧助手要做成什么样

> 目标：把"基于 Agent 的手机智慧助手"的需求边界理清楚，作为后续概念模型与架构方案的输入。
> 核心假设：我们拥有 **omni 全双工模型**（语音/多模态、可随时双向打断的实时对话能力）。

## 1. 一句话定位

一个常驻手机的**私人秘书型 Agent**：既能随时自然对话，又能接受委托——
到点做事（定时）、见机行事（事件驱动）、长期盯事（自定义监视）、
把耗时的活儿放到后台慢慢干（长时异步任务），干完了或者干不下去了再回来找你。

关键词是**委托（delegation）**：用户交代一件事之后可以走开，
助手负责在正确的时机启动、执行、澄清、交付，而不是每一步都要用户守着。

## 2. 需求全景：五个能力域

| # | 能力域 | 一句话 | 典型例子 |
| --- | --- | --- | --- |
| A | 即时对话 | 全双工自然对话，随问随答，随时可打断 | "明天天气怎么样？"（说到一半改口也能跟上） |
| B | 定时任务 | 到点触发的自动化 | 每天 7:30 汇总新闻 + 今日日程，语音播报 |
| C | 事件驱动任务 | 系统事件（可穷举）触发的自动化 | 到家 → 开空调、播报未读消息摘要 |
| D | 自定义监视任务 | 用户口头定义的"盯梢"，事件不可穷举，由 Agent 自己实现判定 | "盯一下苹果发布会，内容整理成邮件发我" |
| E | 长时异步任务 | 一次委托、后台长跑、可能中途回来澄清 | 批量修图、操控 App 订票、深度研究报告 |

这五个域不是并列的五个功能，而是**同一个任务模型的五种触发/执行形态**（见 02 章）。
A 是入口和总控界面；B/C/D 是"什么时候干"；E 是"怎么干、干多久"。

## 3. 各能力域的需求细化

### A. 即时对话（全双工）

- **全双工语音**：用户说话时助手可以听，助手说话时用户可以随时打断（barge-in）；
  助手也可以在合适时机**主动开口**（任务完成播报、澄清提问）——但主动开口必须受打扰管理门控（见 03/04 章）。
- **对话即控制台**：所有自动化任务都通过对话创建、查询、修改、取消。
  "我让你盯的发布会怎么样了？""修图先停一下，优先把票订了。"
- **对话与任务共存**：用户正在闲聊时后台任务完成了，助手要能自然地择机插入播报，
  而不是粗暴打断，也不是永远憋着不说。

### B. 定时任务

- 一次性定时（"晚上 8 点提醒我"）与周期性定时（cron 式："每周一早上……"）。
- 语义化时间（"下班前""睡觉前"）→ 需要结合用户作息画像解析成具体时刻或事件。
- 到点执行的不只是"提醒"这种轻动作，可以是**任意 Agent 任务**（到点启动一次深度研究）。
- 错过处理策略：手机关机/勿扰期间错过的定时任务，补跑还是丢弃，需按任务声明。

### C. 事件驱动任务（系统事件，可穷举）

- 前提：系统有一个**事件管理器**，维护一张可穷举的系统事件注册表，例如：
  - 位置/地理围栏：到家、离家、到公司；
  - 设备状态：开始充电、电量低、连上车机蓝牙、连上家里 Wi-Fi；
  - 通信：收到某人短信/来电、收到含关键词的通知；
  - 日历/闹钟：日程开始前 N 分钟、闹钟响起；
  - 使用状态：解锁、亮屏、打开某 App。
- 需求：Agent 能**订阅**这些事件并绑定动作；用户用自然语言描述，Agent 负责映射到
  具体事件 + 参数（"到家"→ 地理围栏进入事件，围栏取自用户住址画像）。
- 事件可组合条件："到家 **且** 时间在 18 点后 **且** 今天有未读工作消息"。

### D. 自定义监视任务（事件不可穷举，Agent 自己实现）

- 本质：用户描述一个**世界状态的变化**（"苹果发布会开始/结束了""这个商品降价了"
  "老板回邮件了"），系统事件表里没有现成事件，需要 Agent 自己去"盯"。
- 实现上可归约为两种形态（详见 02 章 §3）：
  1. **轮询 + 判定**：定时去检查（搜索、抓取、查 API），用 LLM 判定"事件是否发生"；
  2. **外部订阅**：能找到推送源（RSS、webhook、App 通知）时转成 C 类事件。
- 判定命中后接一个**后续任务**（往往是 E 类长任务）："整理发布会内容 → 写成邮件 → 发给我"。
- 监视任务有**生存期**：盯到为止 / 盯到某天为止 / 长期盯，防止僵尸监视任务堆积。

### E. 长时异步任务

- 特征：分钟级到小时级甚至跨天；用户不在场；可能失败重试；可能需要中途澄清。
- 典型负载：
  - **批量修图**：算力型，长但基本无需交互；
  - **手机 App 操控**（订票、抢购、填表）：GUI 自动化，路径上随时可能冒出需要用户拍板的分叉（座位选哪个？验证码；支付确认——支付必须回到用户）；
  - **深度研究**：多轮搜索阅读综合，产出报告，可能中途发现题目歧义要澄清；
  - **subagent 编排**：一个大委托拆给多个 subagent 并行干。
- 核心需求：
  1. **任务生命周期管理**：创建/排队/运行/等待用户/暂停/完成/失败，全程可查；
  2. **中途澄清（回拨用户）**：任务挂起 → 生成澄清请求 → 按打扰等级选通道找用户 →
     拿到答复继续跑；用户不回复要有超时默认策略；
  3. **可控性（steering）**：用户可随时插话改需求、暂停、取消、调优先级；
  4. **结果交付**：按任务声明的通道交付（语音播报 / 推送卡片 / 邮件 / 静默存档）；
  5. **断点恢复**：手机重启、进程被杀后任务能从 checkpoint 恢复或安全重跑。

## 4. 用户故事（验收场景）

1. **早报**："每天早上 7 点半，把昨晚的科技新闻和我今天的日程整理一下，我起床后播给我听。"
   → B 定时 + 交付策略"等用户醒来（首次解锁/摘下手表检测）再播报"。
2. **到家模式**："我到家后，如果是工作日晚上，帮我打开空调，然后把今天没读的工作群消息挑重要的念给我。"
   → C 系统事件 + 条件组合 + 轻量执行。
3. **盯发布会**："帮我盯一下这次苹果发布会，结束后把内容整理成一封邮件发我。"
   → D 监视（轮询判定"发布会结束且要点已可获取"）→ 触发 E 长任务（整理 + 发邮件）。
4. **批量修图**："把昨天拍的两百张照片挑一遍，废片删掉，好的调一下色。"
   → E 长任务；中途澄清："有 12 张我拿不准算不算废片，你有空扫一眼？"（低打扰推送，不语音打断）。
5. **订票**："帮我订下周五去上海的高铁，尽量下午，靠窗。"
   → E App 操控；到支付环节**必须**回拨用户确认；如无下午票，回拨澄清"只有上午 10 点和晚上 7 点，选哪个？"。
6. **对话中插播**：用户正在跟助手聊别的，修图任务完成了。
   → 助手等当前话轮告一段落，自然插一句"对了，照片修完了，挑出来 160 张，有 12 张要你看一下"。
7. **进度追问与改单**："研究报告写得怎么样了？——嗯，重点改成只看开源方案。"
   → E 任务可查询、可 steering，改需求后 subagent 带着已有成果继续，而不是推倒重来。

## 5. 非功能需求

| 维度 | 要求 |
| --- | --- |
| 打扰克制 | 主动开口/推送必须分级门控；宁可低打扰积压，不可高打扰滥用（信任一旦失去，用户会关掉主动性） |
| 可靠性 | 定时/事件触发不丢（进程被杀、重启后依然生效）；长任务可恢复；触发与执行有审计日志 |
| 时延 | 对话回合感知时延达到实时对话标准；触发到执行启动秒级 |
| 功耗 | 监视类轮询要有频率预算；优先用系统事件/推送替代轮询 |
| 隐私与安全 | App 操控、读通知、发邮件均为高权限动作，需要权限分级 + 敏感动作（支付、发送、删除）用户确认 |
| 记忆 | 任务解析依赖用户画像（家的地址、作息、邮箱、偏好）；执行结果沉淀回记忆 |

## 6. 明确不做 / 暂缓

- 不做开放的第三方"技能市场"（先把一方能力闭环做好）；
- 自定义监视不承诺任意秒级实时性（受轮询预算约束，给出"预期检查频率"即可）；
- 多设备协同（手表/车机/家居联动作为交付与触发端点可以接，但编排中枢先只在手机）。
