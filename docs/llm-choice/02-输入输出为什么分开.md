# 输入和输出为什么分开计价，以及 Cursor $200 里的 Fable 5.1

核对日 2026-09-23。单价来自当天打开的 [Cursor Models & Pricing](https://cursor.com/docs/models-and-pricing) 和 [Claude Fable 5.1](https://cursor.com/docs/models/claude-fable-5-1)，以及 Anthropic 的 [Fable 5.1 说明](https://platform.claude.com/docs/en/models/fable-5-1/overview)。

## 为什么输入和输出不是一个价

一次请求在 GPU 上是两段活，成本结构不同。

**输入是 prefill。** 提示里的 token 都已经知道，整段一起做矩阵乘法。权重从显存读上来之后，可以摊到这一段里的每一个 token 上。这段是算力打满的，单个输入 token 便宜。

**输出是 decode。** 下一个 token 要等上一个 token 出来才能算。每生成一个 token，都要把全部权重再读一遍，还要读不断变长的 KV cache。芯片大部分时间在等显存，不在做乘法。这段按 token 计，比 prefill 贵。Fable 5.1 的输出价是输入价的 5 倍（$50 对 $10），反映的是这段硬件差异，不是「回答比提问更值钱」。

所以不能把「一百万 token」当成一个价。同一百万 token，全是输入和全是输出，账单差 5 倍。分类、摘要这类活输入多；带思考的 agent 输出少、金额高。合成一个均价，等于用输入补贴输出。

还有两件事让「输出」比屏幕上看到的字更贵：

- **思考算输出。** Fable 5.1 的 adaptive thinking 关不掉，深度只用 effort 调。思考 token、工具参数、可见正文都进 `output_tokens`，按 $50 / 百万计。界面上的一段话，账单上往往还带着几倍的思考。
- **缓存是第三条价，不是输入价的别名。** 前缀的 KV 写进缓存之后，下一轮不用再做那一段 prefill。Fable 5.1 的缓存读是 $0.25 / 百万，是输入价的 2.5%。agent 循环里 token 数量的大头通常是缓存读，金额的大头通常是输出。

Anthropic 把缓存写入再拆成两档：5 分钟 $12.50 / 百万，1 小时 $20 / 百万。写入比普通输入贵，因为除了 prefill 还要留下 KV。读一次会刷新 5 分钟的寿命，连续调用不用反复写。中间停超过 5 分钟（人在看 diff、工具很慢），下一次要重新写。Cursor 的价目表只列了一列 Cache write，Fable 5.1 是 $12.50，对应 Anthropic 的 5 分钟档。

四条价放在一起（每百万 token）：

| 计费项 | Fable 5.1 | 在做什么 |
| --- | --- | --- |
| 输入 | $10 | 没进缓存的新 token，做一次 prefill |
| 缓存写入 | $12.50 | prefill，并把 KV 留下 |
| 缓存读取 | $0.25 | 跳过这段 prefill |
| 输出 | $50 | 逐个 decode；含思考和工具参数 |

Batch 在 Anthropic 是输入和输出各半价。那是排队换价格，不改变「输出比输入贵」这件事。

## Cursor $200 不是 token 包

个人 Ultra 是 $200 / 月。Fable 5.1 不走 Cursor 自己的模型池（Grok 4.7 / 4.6 / 4.5、Composer 2.5 那一池），走 **Other Models**：按上面的 API 单价从一笔美元额度里扣。Tab 补全不占这笔额度。额度按账单月清零，不结转。用完可以按同一单价开按量，请求不会被降级。

这笔额度最后一次印成美元，是每月 **$400** 的第三方模型用量：

- 2026-06-15 的 Models & Pricing 写着 Ultra 含 $400；同一天论坛里对「20 倍用量」的解释是 Pro 的 $20 × 20 = $400，不是 $20 × 20 × 10。Auto / Composer 另计。帖：[How much usage is available on the $200 subscription?](https://forum.cursor.com/t/how-much-usage-is-available-on-the-200-subscription/163309)
- 2026-09-23 打开的 [Models & Pricing](https://cursor.com/docs/models-and-pricing) 和 [Usage and limits](https://cursor.com/help/models-and-usage/usage-limits) 已把这一格改成 Included，不再印美元。

下面的 token 全部按 **$400、按当天的 Fable 5.1 单价** 折算。Spending 页若显示的余额不是 $400，以 Spending 为准，把下面的数按比例缩放。个人方案不收 Teams / Enterprise 那笔 Cursor Token Rate（$0.25 / 百万，加在第三方模型上）。

$400 如果全部花在一种 token 上：

| 全部花在 | token 数 | 这一档在账单里的位置 |
| --- | --- | --- |
| 未缓存输入 | 4,000 万 | 只在前缀还没进缓存时出现 |
| 5 分钟缓存写入 | 3,200 万 | 前缀第一次留下 KV；停超过 5 分钟会再写一次 |
| 缓存读取 | 16 亿 | 循环里数量最大的一档，单价最低 |
| 输出（含思考） | 800 万 | 金额上限最紧的一档 |

真实的一次调用是四项混在一起。输出占 token 的一小部分，占金额的大部分。

## 一次编码调用怎么扣

按一次典型的后续调用估算：缓存读 10 万，新输入 5 千，输出 1 万（思考 + 工具参数 + 可见字）。

| 项 | token | 金额 |
| --- | --- | --- |
| 缓存读 | 100,000 | $0.025 |
| 新输入 | 5,000 | $0.050 |
| 输出 | 10,000 | $0.500 |
| 合计 | 115,000 | **$0.575** |

11.5 万 token 里，输出只占 8.7%，金额占 87%。把输出提到 3 万（effort 拉高、思考变长），同一次调用变成 $1.575，其中输出占 $1.50。

一个任务按 15 次调用：第 1 次把 10 万前缀写入缓存，后 14 次按上表读缓存。

| 输出规模 | 这一任务 | $400 大约够几次这样的任务 | 折合模型调用 |
| --- | --- | --- | --- |
| 每次输出 1 万 | $9.85 | 约 40 次 | 约 600 次 |
| 每次输出 3 万 | $24.85 | 约 16 次 | 约 240 次 |

第 1 次的算法：缓存写 $1.25 + 新输入 $0.05 + 输出。输出 1 万是 $0.50，任务首调用 $1.80；输出 3 万是 $1.50，首调用 $2.80。后续调用分别是 $0.575 和 $1.575。

前缀更长，缓存读的金额几乎不动（10 万已经只值 2.5 美分；拉到 50 万也只是 $0.125），输出金额照旧。把上下文堆长，贵的不是「又读了一遍仓库」，是每一轮都重新生成思考。

同一笔 $400 若改花在 Cursor 价目上的 Opus 5.5（输入 $4、缓存写 $5、缓存读 $0.20、输出 $20），输出 token 是 Fable 的 2.5 倍（2,000 万对 800 万）。缓存读只多 25%（20 亿对 16 亿），因为 Fable 的缓存读相对自己的输入价更低。Cursor 的 Fable 5.1 页写着：输入和输出大约是 Opus 5.5 的 2.5 倍，而 Opus 5.5 在 CursorBench 上现在更高。难任务留 Fable，日常回合用 Opus 5.5 或 Sonnet 5，同一笔额度覆盖的调用次数差这 2.5 倍里的输出部分。

触发安全护栏的请求会被 Cursor 改派到 Opus，那一次不再按 Fable 计价。Privacy Mode 或 Enterprise 要先在后台接受 Fable 的数据保留条款，模型才出现在选择器里：Anthropic 为伤害防范保存输入和输出，不用于训练。
