AGENT VARIABLE SCHEME · V3

透明信封方案
Envelope + Working Memory + ${} 引用替换

工具返回结果原样不动 · 框架统一包信封给模型 · 完整结果按 resultId 存入 Working Memory
下游调用用 ${resultId.path} 引用 · 框架在执行前替换（invoke 值语义 / exec 自动转义）

解决什么

长内容（URL / 路径 / 文件）复述导致的 LLM 增量推理时延与抄写错误

核心特点

工具零改动 · 结果对模型透明可推理 · skill 级引用指引 · 支持 exec 命令替换

生命周期

loop / conversation 作用域 · touch 提升 · TTL / spill / rehydrate · 过期报错自纠

01问题：长内容复述 = 时延 + 出错

没有变量机制

// toolA 返回 246 字符签名 URL，模型调 toolB 时逐 token 复述：
invoke("edit_image", {
  "source": "https://cdn.example.com/imgs/2026/08/10/
    f7c3a91e-7b3e-4e9d-a2c4-91f0e8d7b6a5-4096x1716_v1.png
    ?sig=Kx7Qw9f2nQ9pXw2vYs8rTz5m...&exp=1754800000"
})
  • 输出 80+ tokens，增量推理时延线性放大
  • 签名段抄错 1 个字符 → 403，任务失败
  • 多轮对话中反复复述，上下文膨胀

v3 信封方案

// 模型只复制信封 refs 里的成品引用串：
invoke("edit_image", {
  "source": "${a3f8k2p9.resultDataList[1].img_uri}"
})
  • 输出 ~12 tokens，与内容长度无关
  • 框架执行前替换真实值，零抄写错误
  • 历史中永远只有占位符，替换结果不回写

三代方案：v1 框架侧字段提取 → v2 分层解耦（整体存储 + stub 替身）→ v3 透明信封：结果原文可见可推理，信封 + refs + skill 指引压制抄写

02架构总览：一次工具调用的完整闭环

LLM输出 invoke(args) 或 exec(command)，参数含 ${…} 占位符
→tool call
Resolver（入方向）解析 ${resultId.path}
按落点替换 + 转义
→真实值
工具层原样返回结果
对变量机制零感知
→原始结果
Enveloper（出方向）包信封 · 生成 resultId
阈值瘦身 · 生成 refs

Working Memory（KV）

a3f8k2p9 → { resultData: 完整原始结果,
             meta: { scope, TTL, lifetime, source } }

Enveloper 写入 · Resolver 读取 · 生命周期归框架管，随 checkpoint 持久

Guardrails（错误回喂）

未知 id / 路径不存在 / 列表下标歧义 / 引用过期 / exec 不安全值 —— 一律不执行工具，构造 tool error 回喂，模型复制正确引用自纠

解耦要点：工具只管原样返回；模型只管复制 refs；框架承担存储、瘦身、替换、转义、生命周期全部职责。

03信封结构解剖（模型看到的东西）

{
  "toolName": "image_gen",
  "responseText": "已生成 2 张候选横幅图。完整 URL 已存入
      a3f8k2p9，请复制 refs 中的占位串引用，勿抄写内容。",
  "resultId": "a3f8k2p9",          // 8 位随机 id，跨轮不撞名
  "resultDataList": [
    { "img_uri": { "$preview": "https://cdn.example.com/…_v1.png?sig=Kx7Q…",
                   "$size": 246 },   // 超阈值 → 瘦身
      "createTime": "2026-08-10T04:05:12Z",  // 短值原样保留
      "style": "深色科技风" },
    { …第 2 张（浅色简约风）… }
  ],
  "refs": {   // 成品引用串：模型只复制，不拼装
    "resultDataList[0].img_uri": "${a3f8k2p9.resultDataList[0].img_uri}",
    "resultDataList[1].img_uri": "${a3f8k2p9.resultDataList[1].img_uri}"
  }
}

resultDataList = 工具原始返回

结构不变，模型可对内容推理（如按 style 选图）；只有超阈值叶子瘦身为 $preview + $size

refs = 抄写风险的终点

8 位随机 id 也有抄错风险 → 框架直接给成品引用串，模型复制即可，出错率低一个量级

瘦身阈值是策略参数

阈值 = ∞ → 全文透明；阈值 = 0 → v2 的 stub 形态。按类型配置：base64 强制瘦身、URL 200、文本 1000

Skill 级显式指引（v3 的遵循率关键）

// 下游工具（skill）描述中固定话术：
参数 source 通常来自上游工具结果。请直接复制上游信封 refs 中
的 ${...} 占位串作为参数值，不要抄写 URL/路径的具体内容。
框架会在执行前自动替换为真实值。

全局 system prompt 只留一条兜底规则；细则随 skill 走——工具作者最清楚自己的参数来源。指引下沉到调用现场，遵循率显著高于全局规则。

05入方向管线：${} 解析替换（按落点转义）

① LLM 输出invoke(args) / exec(command)
含 ${resultId.path}
→
② 解析 + 校验JSON 解析、schema 校验
占位符按字符串通过
→
③ 查 Working Memoryid → 路径寻址 → touch 续期
spilled 则 rehydrate
→
④ 按落点替换invoke：值语义保类型
exec：自动 shell 转义
→
⑤ 执行工具收到真实值
替换结果不回写历史
落点（sink）替换语义转义规则
invoke() JSON 参数值语义，保留类型无需转义（JSON 序列化天然安全）
exec(command)文本内插自动单引号包裹，内部 ' 转义为 '\''；含换行/控制字符直接拒绝
最终回复文本（扩展）文本内插Markdown 转义

安全硬防线：工具结果内容不可信（间接提示注入）。凡进 shell 必须框架转义；可再加白名单——exec 只允许 [A-Za-z0-9_-./:?&=%] 字符集的值，否则只准走 invoke 或落盘传路径。模型和 skill 都不承担转义责任。

07关键流程 A：列表歧义 → 报错回喂 → 自纠

模型首次输出（省写下标）

invoke("edit_image", {
  "source": "${a3f8k2p9.img_uri}",
  "op": "crop", "ratio": "16:9"
})

resultDataList 有 2 个元素 → 语法糖不成立。规则：不猜，不执行。

框架回喂（tool error）

{ "error": "ambiguous_index",
  "message": "a3f8k2p9.resultDataList 含 2 个元素，
   须显式下标。候选：
   ${a3f8k2p9.resultDataList[0].img_uri}（深色科技风）
   ${a3f8k2p9.resultDataList[1].img_uri}（浅色简约风）" }

模型自纠（复制候选串）

invoke("edit_image", {
  "source": "${a3f8k2p9.resultDataList[1].img_uri}",
  "op": "crop", "ratio": "16:9"
})

Resolver 值语义替换 → edit_image 收到完整 246 字符 URL（工具零感知）

错误处理全家桶（一律不执行 + 回喂 + 自纠）

unknown_result_idunknown_pathambiguous_indexreference_expiredunsafe_exec_value复制检测（软）
回喂可用 resultId 清单回喂该 id 的全部 refs回喂各下标候选串回喂过期时间 + 重取建议建议改 invoke 或落盘提醒改用引用，不阻断

08关键流程 B：exec 命令替换与自动转义

模型输出（占位符直接写进 shell 命令，约 14 tokens）

exec(command="curl -sS -o /tmp/banner_169.png ${k2m9x4qt.resultDataList[0].img_uri}")
↓ Resolver：识别落点为 exec → 白名单检查 → 自动单引号包裹

实际执行的命令

curl -sS -o /tmp/banner_169.png 'https://cdn.example.com/imgs/2026/08/10/9d1f…_crop169.png?sig=Tz5m…&exp=1754800000'

为什么必须框架转义

URL 里的 & 不转义会把命令截断成后台任务；模型手写转义既费 token 又不可靠。

为什么这是安全问题

工具结果可能被间接提示注入污染（如 ; rm -rf ~）。单引号包裹使其只能作为字面量，无法逃逸执行。

加严选项

exec 落点只允许安全字符集的值；含特殊字符的值只准走 invoke()，或先落盘成文件后传路径。

09生命周期：作用域、冷热分层、过期

loop（默认）信封生成即 loop 作用域
本轮 agent loop 内有效
→被引用 touch-to-promote
conversation跨轮可引用
TTL：N 轮未引用淘汰
→LRU / 容量
spilled（冷层）降级磁盘，留 tombstone
再引用 → rehydrate
→TTL / lifetime 过期
淘汰 / 过期引用时报错回喂
附原因与重取建议

Turn 2（次日）跨轮引用示例

<available_results>  // user message 末尾 append，保护前缀缓存
  a3f8k2p9  image_gen   2 张候选原图   conversation(spilled)  URL 已过期
  k2m9x4qt  edit_image  16:9 裁剪图    conversation           URL 已过期
</available_results>

// 模型引用 ${k2m9x4qt…img_uri} → meta 中签名已过期：
{ "error": "reference_expired",
  "message": "签名已于 08-10T12:00Z 过期。本地文件
   /tmp/banner_169.png 可能仍存在，或重新调用 edit_image。" }

随机 id 的优势

8 位 base36 全局唯一：跨轮、跨分支（对话回退重放）不撞名，优于序号命名

checkpoint 一致性

Working Memory 随 agent 状态一起快照；只恢复历史不恢复 KV，所有 ${…} 都会悬垂

续期粒度

引用任一子路径为整个 resultId 续期（KV 粒度 = 结果粒度，接受粗粒度）

10三代方案对比与 token 收益

v1 框架侧提取v2 分层解耦v3 透明信封
工具改动需声明 exportable零改动（可选 $export）零改动
模型能否看到结果内容只见 preview只见 preview原文可见可推理（超阈值瘦身）
引用出错率记语义名复制 stub $ref复制 refs 成品串 + skill 指引
exec 命令落点未定义未定义自动转义 + 白名单
输入 token最省最省取决于瘦身阈值（可调到与 v2 等同）

输出侧收益（本示例实测口径）

  • 裁剪传参：80+ tokens → 12 tokens
  • exec 下载：100+ tokens → 14 tokens
  • 抄写错误（403 / 命令截断）→ 结构性消除

选型建议

三版共用同一套 Working Memory 与替换管线，差异只在"给模型看什么"（stub ↔ 信封）与指引位置（全局 ↔ skill）。推荐 v3 作为默认形态，瘦身阈值按内容类型配置，即可在透明与省 token 之间连续调节。

11落地模块清单与安全约定

模块职责关键接口
Enveloper包信封、生成 resultId、阈值瘦身、生成 refs、responseText 兜底wrap(toolName, rawResult) → envelope
WorkingMemoryKV 存取、作用域/TTL/LRU、spill/rehydrate、checkpointput / get / touch / end_of_loop / snapshot
Resolver${} 解析、路径寻址、按落点替换与转义resolve(argsOrCommand, sink) → resolved
Guardrails六类错误检测与回喂、exec 白名单、复制检测check(…) → ok | error_envelope
Skill 规范依赖上游结果的参数附固定引用指引话术文档约定

安全约定

  • 只在参数值 / 命令字符串位置替换，工具名与参数名不替换
  • 工具结果原文中的 ${ 字面量入库时转义，防伪造引用与二次展开
  • exec 落点强制框架转义 + 字符白名单
  • 子 agent 不共享 Working Memory，跨 agent 显式解析传值

实施顺序建议

  • ① Enveloper + WorkingMemory + invoke 替换（核心闭环）
  • ② Guardrails 六类错误回喂（自纠能力）
  • ③ exec 落点转义与白名单（安全）
  • ④ 生命周期完整版：TTL / spill / lifetime 过期 / checkpoint
