# 为什么决策模型可能比同规模生成模型更省钱

> 区分官方已披露事实与通用推理原理。未查到 Jev 官方参数量或严格同参数量实验，不能以“Jev 很小”为事实前提。来源见[来源索引](./04-来源索引.md)。

## 1. 参数量不是请求成本

即使模型参数量相同，请求成本也受输入长度、输出长度、推理步骤、精度、架构、缓存、批处理和硬件利用率影响。

三个指标必须分开：

- **延迟**：用户等待多久。
- **资源成本**：处理请求消耗多少 GPU 时间、显存等资源。
- **API 价格**：服务商的收费政策。

并行可以缩短延迟，但不必然同比例降低总计算；价格还包含部署策略、利润与可能的补贴。

## 2. 自回归输出的开销

常规自回归 LLM 的 prefill 阶段处理输入，decode 阶段继续逐 token 生成。KV cache 避免重复计算历史 token 的键值，但每个新增 token 仍需经过模型计算。解码常受显存带宽约束。[S19][S20]

概念上可以写成：

```text
生成式模型任务成本 ≈ 输入处理 + 后续逐步解码 + 服务开销
决策模型任务成本   ≈ 状态与问题处理 + 决策计算 + 服务开销
```

这只是分解框架，不是 Jev 的 FLOPs 公式，也不表示 Jev 没有内部多层计算。

当任务需要输出意图、参数、多个候选的概率时，生成模型通常要把这些值编码成一串 token。Jev 官方描述的是并行输出概率与决策，省去逐 token 写出这些结果的路径。[S1]

接口响应仍可以是 JSON，但 JSON 可由普通服务代码序列化。不能从网络响应格式推断模型内部使用了自回归生成。

## 3. 多题共享状态的收益与边界

官方接口允许同一 state 上并行判断意图、参数、适用性和质量等独立问题。[S3][S6]

工程推断：这可能减少重复输入处理、串行解码和中间状态管理的部分开销。但问题与候选仍占输入和计算资源，不能理解成增加任意多问题都免费。

具体注意力结构、缓存方式、参数规模和硬件优化未在本次资料中得到完整披露；不能据此断言 Jev 是某种特定 encoder、只做一次廉价分类头计算，或完全不使用缓存。

## 4. 单 token 分类是必须比较的基线

如果任务仅为四选一，可以让小 LLM 输出单 token 标签，而不是长 JSON、解释与推理。这会大幅削弱“省去长输出”带来的优势。

能访问 logits 的部署还可以读取候选标签分数，但标签 token 设计、候选限制和分数校准需单独处理；普通词表概率不自动等于业务正确率。

因此公平实验至少比较：

1. 规则或专门训练的小型分类器。
2. 小 LLM 的短标签输出，关闭非必要推理与解释。
3. 小 LLM 的业务实际结构化输出。
4. Jev 的原生决策接口。

若任务要求完整概率分布，应让各基线都提供对应结果；若只要一个类别，就不要强迫 LLM 输出冗长概率表。专用分类器也可以避免自回归生成，因此“决策输出更经济”不是 Jev 独有的原理。

输入很长、输出极短时，输入处理可能占主导，收益需实测；不能根据输出 token 数直接推算整次请求加速倍数。

## 5. RLCD 与成本之间的关系

官方把 RLCD 定义为面向决策与校准概率的训练目标。[S4]

合理推断是：训练让直接判断更可用，从而减少对生成式推理文本的依赖。但它不自动使相同架构的单次前向计算更便宜，训练成本也不同于在线服务成本。

## 6. 报价不是底层成本证明

官方价格是每百万输入 token $0.042，输出免费。[S6] “免费”是计费政策，不表示计算成本为零。TypeSafe 在发布说明中也承认，无法仅凭当前价格证明不存在补贴，可持续性需要时间验证。[S1]

公开的百倍性能宣传并不是同参数量、同硬件、同准确率的严格消融实验，不能用来证明 Jev 比所有同规模 LLM 更省钱。

## 7. 业务评估方式

对意图与参数识别，应该计算：

```text
总费用 = 候选检索与抽取 + Jev 判断 + 回退模型 + 重试与人工处理
单位成功成本 = 总费用 / 正确完成的业务请求数
```

延迟单独统计整个链路的 p50/p95，包括串行依赖、检索和回退；自部署时另统计吞吐、GPU 利用率与资源成本。

实验固定业务数据、正确性标准、候选范围与硬件条件（能够控制时），报告缓存、并发、量化、输入长度、输出要求和模型版本。

对只选一个意图的短任务，小 LLM 或传统分类器可能足够经济；多项判断且需要概率分布时，Jev 更值得验证。采用依据应是端到端结果，而非参数量或宣传倍数。
