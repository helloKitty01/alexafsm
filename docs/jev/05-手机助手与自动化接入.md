# Jev 对手机助手与自动化系统的启示

> 2026-09-24 合并整理自原 `jev-insight/04`。以下是工程建议，未实现或线上验证；原稿保存在 [history](./history/README.md)。

## 1. 对照本仓库的架构

相关设计为 [手机助手](../phone-assistant-automation/README.md) 与 [OpenClaw 自动化](../openclaw-automation/README.md)。前者讨论中枢、后台深度模型和打扰管理，后者在 v4 将创建任务收敛为有限模板。

Jev 可以承担其中的窄语义判断：通知是否紧急、哪个模板适用、检索是否相关、已完成轨迹是否满足标准。任务存储、触发、权限和执行状态仍由普通代码维护。

## 2. 三个候选接入点

### 打扰分级

用 Jev 评估事件紧急程度与相关性，作为打扰管理器的输入。代码结合用户状态、渠道和策略决定 `speak_now / speak_at_pause / push / digest / hold`。

不建议逐音频帧调用；先通过事件聚合、去重和确定性条件筛选，再判断有价值的事件。低单价叠加高频率仍会扩大费用。

### 创建期模板选择

固定模板适合 Choice，封闭参数可拆成独立题；对象 ID 从查询得到，日期与数值在代码中验证。提醒文案等开放字符串使用用户原文或生成模型。缺失参数和不确定意图进入澄清。

意图与参数必须对应同一任务，不能因多个独立问题各自高置信就认定整条调用正确。具体机制见 [02-意图识别与参数填槽](./02-意图识别与参数填槽.md)。

### 轨迹和工具结果验收

将证据与明确标准提供给 Jev，评估相关性、依据充分性和完成条件；先作为回归与在线抽检信号。确定性条件直接写代码；开放式复杂评审可转强模型或人工。

LangChain 的小规模实验只能证明该组固定案例上的表现，不能替代自有业务标注。验收失败后的重试、澄清和停止由工作流定义，不由裁判改写策略。

## 3. 边界：概率不是许可

工程建议：置信度可帮助选择处理路径，但不能绕过现有批准卡、standing grant、权限与业务校验。对外发送、支付、删除等动作按既有策略执行；是否需要新确认取决于已有授权，不能只因高分自动放行，也不应无视有效授权一律重复确认。

网页、邮件等不可信内容可影响 Jev 的答案。模型评分不能作为提示注入已被消除或工具调用已获授权的证明。算术、计数和日期比较留在代码，长推理与自由文本留给合适的模型。

## 4. 中文评测与运行保障

- 采集真实中文口语、通知和模板描述，覆盖省略、纠正、指代、多任务及域外输入。
- 观察整任务准确率、拒识与回退、自动处理覆盖率；阈值按动作和字段分别校准。
- 固定已评测的模型版本并记录响应版本，避免别名更新后沿用未经验证的阈值。
- 对超时、429 和不可用制定预先定义的回退；例如非紧急通知暂缓或聚合，不让外部推理阻塞核心状态机。
- 按调用渠道核对数据保留与计费；不能把网关或企业计划的条款自动套到另一个集成。

相关官方约束见 [Models](https://docs.typesafe.ai/models)、[Confidence](https://docs.typesafe.ai/confidence) 和 [Jev 1.13 limitations](https://docs.typesafe.ai/model-jaggedness/jev-1.13)。

## 5. 账目与采用条件

分开记录 Jev 判断、候选检索、开放参数抽取、生成模型回退以及人工处理的成本，再合成单位成功任务的总费用。调用变便宜后新增的大量检查，也要算入总量。

先选一个高频、标准清楚、可人工标注的节点做对照实验。只有在端到端质量、延迟和费用满足要求后再扩大接入；暂不把 Jev 变成中枢可用性的前置依赖。
