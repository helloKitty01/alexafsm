# Jev：定义、热度与典型应用

> 资料截至 2026-09-24；未自行运行 API 实验。来源编号见[来源索引](./04-来源索引.md)。

## 1. 原始定义

TypeSafe AI 于 2026-09-15 发布 Jev，称其为首个公开的 System One Model。官方定位是输入情境与有类型的问题，返回程序可消费的决策及概率，而非生成自由文本。[S1][S2]

System One 借用《思考，快与慢》中快速判断的概念；Jev 的名字来自 William Stanley Jevons，表达效率提高可能扩大智能使用需求的设想。这是产品命名与愿景，不是已证明的经济结果。[S1]

接口由三个部分组成：

```text
state（当前情境）+ questions（具体问题和候选标准）
  → 类型化答案
  → 程序组合结果、校验并执行
```

- **Choice**：选择一个候选，返回选择结果、候选概率分布及 confidence。
- **Score**：按有序描述性量表评分，返回分数、分布及 confidence；不用于精确数值计算。
- **Noul**：判断一个命题是否成立，返回 0–1 的“是”概率，无独立 confidence 字段。

同一请求中的问题独立评估。若后续问题需要前一步答案才能构造，应由程序发起后续请求。[S2][S3]

## 2. 训练目标与概率的含义

官方将其训练方法称为 RLCD（Reinforcement Learning for Calibrated Decisions），强调决策和概率校准。[S4]

“校准”的理想含义是：在大量被预测为 80% 概率的事件中，约 80% 实际成立。这是样本群体的统计性质，不能保证单次结果，也不保证跨领域与语言后保持不变。

`confidence` 是对概率分布集中程度的统计摘要；它不等于单次答案正确率。例如 confidence=0.9 不能直接解释为业务正确率 90%。应在自有标注数据上评估阈值。[S5]

## 3. 为什么受到关注

以下是结合产品定位与实验的分析：

1. **高频需求明确**：Agent 不断做路由、筛选、验证；每个窄判断都调用完整生成模型，会累积延迟与费用。
2. **接口便于集成**：把允许的结果写进问题，程序直接读取选择和分数，易于组合与追踪。
3. **成本与速度存在平台实验支持**：不仅是宣传，但收益随任务、基线和质量要求变化。
4. **传播主张清晰**：开发者容易演示“语义判断进入普通代码”的效果；媒体报道进一步扩大关注。

TechCrunch 于 09-18 报道团队与发布反响；VentureBeat 于 09-21 关注决策环节的提示注入风险。[S15][S16] 截至整理日公开发布仅九天，不能把早期关注当成长期生产成熟度。

## 4. 如何读性能证据

**官方声明**：主页的 193.6 倍快、444.6 倍便宜源自特定工作流。官方披露其中存在任务选择、参考答案来自其他模型、对照输出方式等限制，不能外推为通用收益。[S1]

**平台实测**：OpenRouter 在 2026-09-22 公布 Banking77 分类实验，使用 3,080 条测试样本、77 个意图、8 并发。[S13]

- Jev 1.13：准确率 81.0%；p50 延迟 175 ms；每千请求费用 $0.11。
- Claude Opus 5：准确率 84.4%；p50 延迟 2,266 ms；每千请求费用 $2.42。
- 两者格式无效响应均为 0；Opus 使用严格 JSON schema 和提示缓存。

这说明该实验中存在速度、价格与准确率取舍：约快 13 倍，费用约为 1/22，但准确率更低。数字为来源展示的舍入值，不应据此过度精确推算差值。OpenRouter 是服务平台，实验不是独立审计，也不代表所有业务。

## 5. 典型场景

### 客服分流

识别意图、紧急程度与负责团队；代码分流，生成模型撰写回复。边界清楚且容易收集人工标签，适合作为早期验证节点。[S14]

### Agent 工具与技能选择

评估候选是否匹配当前请求，再由主 Agent 使用工具或技能。官方有技能筛选 cookbook，体现“先筛选，再读取详细信息复核”的组合模式。[S12]

### RAG 段落筛选

检索召回候选后判断相关性，减少进入生成模型的无关文本。最终综合答案仍由生成模型完成。[S11]

### 在线质量检查

在证据已提供、标准明确时，判断答案是否有依据、是否符合要求。开放式评审和复杂长文综合判断需要另行评测，不能默认替换 LLM judge。[S17]

### 批量分类与评分

工程建议：用于文档归类、商品标签、线索筛选等。将宽泛评价拆成具体维度，再在代码中组合。应用构想不等于已验证客户部署。

## 6. 边界与当前规格

“输出范围固定”减少了无效类别与格式错误，但仍会在合法候选里选错。官方列出的弱项包括算术、计数、日期比较、多跳判断、无关长上下文和对抗性文本。[S7]

不能让概率判断替代确定性的权限、业务约束与精确计算。

当前官方模型页列出 Jev 1.13：文本输入；每百万输入 token $0.042，输出免费；请求总预算 64k token，state 加最长问题预算 32k token。英语效果最好，中文需单独验证。[S6]

## 7. 对 Agent 架构的启示

工程推断：当窄判断足够便宜，质量检查可能从最终抽查扩展到检索后、动作前、生成后的多个节点。但是否有收益，取决于错误率、回退和整体调用量。

建议先验证技能路由、RAG 筛选或明确标准的结果检查；保留规则、小型分类器及小 LLM 基线。衡量每个正确业务结果的成本，而非只看单次 API 报价。
