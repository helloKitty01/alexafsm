整理日期：2026-09-24。沉淀三轮讨论：Jev 是什么、如何做意图识别与参数填槽、为什么可能比生成模型更经济。

## 结论与证据口径

- Jev 适合作为工作流中的语义判断组件；生成、精确运算和执行控制由其他组件承担。
- 255 是单个 Choice 的选项上限，不是全系统意图总量上限，也不是准确率保证。
- 意图与参数分开建模；可枚举的参数做选择，开放值先抽取候选或交给生成模型。
- 参数量不是每次请求成本的充分指标；省去长输出的自回归解码可能降低成本，但单 token 分类是必须比较的基线。
- 未查到官方公开参数量，不能将“小模型”或“同参数量必然更省钱”作为已证实结论。
- 文档区分**官方声明、平台实测、工程推断与建议**。未自行调用 Jev API 复测；规格和价格均为整理时查阅值。
