02架构：一台 VM，许可在模型外面安全文：让所有人能用的工作量，大部分花在这一页

运行时单元格 会吃到不可信数据systemd-nspawn · 单元格 root ≠ 宿主机 root

  • Hatch daemon 核心 harness。工作区、终端、自写工具、subagent、cron 都在这里。
  • 完整 Debian 根，虚拟网卡。无 io_uring，无 CAP_SYS_PTRACE / CAP_NET_ADMIN。
  • 浏览器 subagent 只拿无障碍树，不拿 DOM，不能在页面里跑 JavaScript。
  • 只持有替身令牌。 内置连接器的 CLI 只解析参数、交出文件描述符，业务逻辑不在单元格里。
  • 和单元格外的通话走 Unix socket，SO_PEERCRED + peer ACL，没有可偷的共享密钥。

单元格外 模型关不掉独立 systemd 单元 · 攻击者关不掉分类器

  • Sentinel 另一个 agent。连接器动作和一切出网的唯一许可权威。Muse 提议，它批准、拒绝或询问。
  • authd 保管 OAuth、密码、支付材料。凭证在这台 VM 的隔离容器里，不进 Meta 中心化库。
  • privsep worker 按 cgroup 识别，凭证允许列表是显式的。日历 worker 不能改参数去要邮件凭证。
  • hatch-safety 独立模型和分类器，检查进出核心推理的内容，以及浏览器上的外带 / 注入 / 高风险表单。
  • Postgres 放持久状态，与单元格和凭证库分开。推理和遥测只走受约束代理。
Simon Willison 的 lethal trifecta：私有数据 + 不可信内容 + 对外通信。Muse 的前提是模型会被说服、也会被攻击。三层同时在，不靠提示词单独扛住。
模型层 Spark 1.3 抗注入接近当时 SOTA，并被训过「什么算不可逆」。
harness 层 外部数据进上下文即标成不可信。分类器在单元格外并行，可独立于主模型升级。
出网层 把数据送出 VM 必须经 Sentinel。底下还有单元格、privsep、ACL，不依赖模型是否被说服。
心智模型：一台盒子上两个安全域，不是一个有 root 的 LLM。客户端（App / 网页）经安全传输直连这台 VM。关掉 App，电脑还在。来源：Tarek Sheasha《How We Built Safety Into Muse》09-08。

03边界：秘密、出网、浏览、付款同意是能力，不是对话里的一句建议

Sentinel 问人 不走对话

  • 决策是询问时，执行停住。对话框由 Sentinel 直接发给客户端，答复直接回到 Sentinel。
  • 授权绑连接器、目的地、用途。一次 / 会话 / 任务 / 时限 / 永久。后续调用必须精确命中。
  • 只读、已允许、可证明低风险的可以不打断。他们写明这个平衡会随真实用户调。
  • 设计上要避开条幅疲劳：什么都弹，人就会全点允许。浏览默认可做，难撤销的停。

替身凭证 模型看不见

  • 单元格里的代码只拿 authd 签发的 surrogate。放行之后，Sentinel 在网络边界换成真凭证。
  • 被提示注入逼着「把密钥念出来」，念出来的也不是真的。
  • 三权分开：privsep 决定碰凭证的代码在哪，authd 决定这个调用者能拿哪份，Sentinel 决定能不能做。
  • 邮件连接器用规则加分类器剥掉验证码、重置链接、魔法登录。连上邮箱 ≠ 连上所有用它找回的账号。

污染出网 读了就变脏

  • 每个工具进程起步是干净的，读了用户数据就变脏。
  • 干净、且落在很窄的自动允许里、URL 也通过的请求，可以不打扰人。
  • 脏的或无法核验的，失去自动放行，回到正常审批。
  • eBPF：cgroup 上拦截并归属进程，LSM 钩子上传播污染。SSRF：看起来是公网主机、解析后打到内网，也拦。

浏览器与钱 每次人批

  • 密码从客户端 UI 直进 authd。填表或用户接管时，agent 暂停，读不出刚注入的密码。
  • CDP 在单元格外的 broker。DevTools 关闭。用户能看见浏览并随时接管。
  • 结账页每次人批。未存卡的站点走 Stripe Link 单次卡：商户 + 金额 + 时效。Shop Pay、1Password 在后。
  • Link 给这个 agent 做了购买保障。已知恶意站点名单在 VM 内匹配，直接挡住导航。
错仍然会发生。提示注入被写成行业开放问题。设计目标是伤害有界，并且人不被审批淹没。Bug bounty 公开，最高 30 万美元；成功的、影响到一名用户的提示注入最高 13 万。Confidential VM（整机用只有用户持有的密钥加密）计划年内，发布时还不是这个：今天员工访问靠运营策略，Meta 在支持与安全需要时仍能进数据。
和「同一个 agent 弹个确认」的差别：放行权不在模型的工具列表里。模型可以叙述、可以撒谎、可以被网页说服，按钮的语义由它碰不到的程序核对。

06现有产品：仓库、工单、生活是三种单位模型可以共用，成功定义不能共用 · 九题衡量的是工单

Code 仓库

  • 成功 能合进去的 diff。用户被假定能审计。
  • 计算机 你的机器，或用完即弃的沙箱。拉式：你打开它才工作。
  • 记忆 仓库里的 AGENTS.md / CLAUDE.md，写的是项目规程。
  • 代表 Claude Code、Codex、Cursor、Muse Code。
  • 破坏半径默认是仓库加上这个 shell。个人 agent 里出现代码，是为了做出开支看板。

Work 工单

  • 成功 一份可核验的产出：文档、草稿、停在下单前的候选。
  • 计算机 常常随会话生死。Grok 的多个 Bot 共享一台 Firecracker 的文件和登录态，Bot 之间不是安全边界。
  • 同意 多半仍是同一个 agent 在要批准，可以 always-allow。
  • 代表 ChatGPT Work、Claude Cowork、Manus、Grok Bot 的干活面。
  • 主动性是「做完了」或一条定时任务，不是生活呼机。扩展靠插件目录或模板商店。

Personal 生活

  • 成功 本来会漏的事被接住，且不可逆动作经过同意。设计示范是登机前抓住 12 小时后截止的选拔报名。
  • 计算机 每人一台长期活着的 VM。聊天是视图。
  • 记忆 这个人。未经提示的建议从这里来。Goals 把长期目标收成一页。
  • 同意 另一个程序。模型不见密钥。批准不走对话。
  • 代表 Muse、OpenClaw。Instinct 用 iMessage 当产品本身，架构未公开，关系表面同类。

同一场九题为什么不能裁决物种 09-16 · 晚餐 / 理线器 / 暂停的周五摘要 / 隐藏指令 / 形近账户

观察到的分裂工单读法生活读法
Muse 不打开公开的订位页失分。公开页不需要 approved，下单才需要。「不可逆先问」校准过头。分界应在主机侧的动作类，不在模型临场发挥。
Grok / Work 留下可检查的暂停任务持久化这一项他们更完整。Muse 复用了禁用 cron。机制在产品里，状态不一定干净。过夜五家都没有。

07商业：卖的是零配置的信任不是广告位，也不是模型榜 · 信任的密码学一半还没交货

谁付钱 算力，不是信息流

产品买卖
Muse免费档 + 20 / 100 美元月费。对话和 VM 数据不进广告系统。付费理由是重用户的算力。
副作用代理浏览表现为用户自己的访问。商家仍可能据此在 Instagram 投广告；订位、Marketplace 也可能间接影响广告。
OpenClaw开源 runtime。模型费用户自付。换供应商不用迁移「那个人」。
Work / GrokWork 是 Plus 及以上里的模式，无单独 SKU。Grok Bot 捆在付费 Cursor 或 SuperGrok，无免费 Bot 席位。

分发为什么快 只有 Meta 有的上下文

  • WhatsApp 是已经在用的关系面。 App 才放得下日志、Goals、记忆编辑和审批。纯聊天记录放不下确定性别控制。
  • 生活图谱是演示，也是壁垒。 把 Instagram 上存过的菜谱变成采购清单，再记住朋友的饮食忌口。别的 agent 要先把这些连接器做出来。
  • 冷启动是一页建议。 能力大到用户不知道从哪开口。Ideas、引导提示、按目标主动调整。工单产品不需要这个，因为用户自带题目。
  • 没有插件商店。 头一批连接器（邮件、日历、家、车、Meta 系、Stripe）要和对方一起做，并写成会用的技能。这是供给，不是再装一个社区技能。

信任卖到哪一步 一半在路上

  • 今天能解释的一句：它不能自己到达互联网，密码它看不见，花钱和发信会停下来给你看。
  • 今天不能承诺的一句：Meta 也看不见。Confidential VM 给外部审计、计划年内持续可检查。发布时明确写了，运营需要时公司仍能访问。
  • 训练：轨迹先去掉关键身份信息，设置里可以完全退出。退出训练 ≠ 退出运营访问。
  • 权限大于社交网络历史上要过的任何权限。 安全架构是回答，不是已经被时间证明的回答。下载说明愿意试，不说明愿意把全部账号交出去。
商业上做成的是一个单独的个人 agent SKU：零配置、可对非工程师讲清出网权在另一个程序里、并用算力而不是信息流标价。没做成的是密码学隔离，以及「可以无人值守过夜」。这两件都还在产品外面。

08用法：抄围墙和分界，不抄下载曲线给已经在做 agent 的人 · 手机现场和 OpenClaw 官方语义都还在

判断已经成立 继续

  • 主动只有一个出口，门槛是产品。 Muse 是「值得打断才发」，且可调。全双工下还要分级：插话几乎免费，体验极贵。只读和公开页不要走批准。
  • 不可逆不走默认路径。 钱、对外发送、删除停住。Muse 的购买和发信每次都停。
  • 任务比一轮对话活得久。 Goals、cron、关掉 App 还在跑。聊天是视图，任务存储才是记录。
  • 固定动作不要让模型写 job。 选模式、填参数、程序生成。Muse 的出网同样不自由。这条没有被「agent 会自己写工具」推翻。

结构要补上 围墙

  • 批准由中枢投递，不由模型的下一句携带。按钮语义由中枢校验。模型只看见结果，避免同一条上下文里二次劝说。
  • 真凭证不进上下文。 读过邮件、网页、截图的执行过程，失去自动发送权。事件驱动任务正是把 trifecta 接全的入口。
  • 两条车道。 模板车道：定时、单事件、已授权的固定动作。沙箱车道：调研、草稿、一次性小工具，出网仍走中枢。长尾不要撑破模板库，沙箱也不要变成默认 cwd。
  • 冷启动是一页建议，由中枢维护，不写进每轮提示。

不要抄 物种错位

  • 不要用云 VM 替换手机上的现场：来电、到家、电量、相册、全双工。这些 OpenClaw 用本地节点接，Muse 的云电脑默认没有。
  • 不要用二元「发不发」替换分级打扰。 全双工会把这个门槛用坏。
  • 不要用装机或「像一个人」当可靠性。 Muse 的两列是反向的。
  • 不要假设模型会自己确认。 Spark 是被训过的。没有同样的训练目标，提示替代不了模板车道和中枢批准。
  • 不要为了「更像后台」离开已有的官方调度语义。 Muse 能从零写调度，是因为它拥有整台 VM 和 Sentinel。
两域

执行进程和许可进程分开。放行权不在模型的工具列表里。

两车道

不可逆走模板。可逆的长尾进围起来的沙箱，密钥仍在外面。

两张成绩单

物种有没有人要，和这一次终态对不对，分开记。下载不验收可靠性。

两刀

时延和话权是一刀，伤害半径是另一刀。Muse 只做了第二刀。全双工前台它还没有。
