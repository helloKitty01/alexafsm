# 04 对我们系统的启示

对照的是两份已有设计：[phone-assistant-automation/](../phone-assistant-automation/) 的秘书型手机助手（全双工前台、非 LLM 中枢、深度模型后台、打扰管理器），以及 [openclaw-automation/](../openclaw-automation/) v4（模型在创建期选模式填参数，运行时落回 OpenClaw 官方 cron / stream）。Muse 不是要我们改去抄的规格，它把几件已经在做的事和几件还没分开的事照得更清楚。

## 已被印证的判断

**主动性只能有一个出口，而且门槛是产品。** Muse 的规则是：后台做完，先判断值不值得浮出，只有「有意义的新情况」或「需要输入」才通知；用户能把主动消息关掉或调档。我们的打扰管理器把出口收成 speak_now / speak_at_pause / push / digest / hold，并且全部落收件箱。这比 Muse 的二元「发不发」更细，全双工下也更有必要——插话在技术上几乎免费，在体验上极贵。保持「唯一出口」。Muse 加的一课是：门槛会校准错。bake-off 里它把公开网页当成需要批准。我们的分级如果没有「只读 / 公开 / 可逆」与「对外 / 花钱 / 难撤销」的分界，会走到同一个过度打扰。

**不可逆动作不走默认路径。** 我们把钱、对外发送、删除放在 `waiting_user`，澄清请求必须带默认路径，但这三类永不走默认。Muse 的购买和发信每次都停，结账用单次卡。方向相同。差别在停的那一下由谁执行，见下节。

**任务比一轮对话活得久。** Task = Trigger × Goal × Policy，中枢不依赖 LLM 存活。Muse 的 Goals、VM 里的 cron、关掉 App 还在跑，是同一句话的消费产品版。聊天是视图，电脑（在我们这边是任务存储 + 触发器）是记录系统。

**模型不写 job，程序生成 job。** v4 把创建期收成「5 选 1 模式 + 填参数 + 回读」，脚本、权限、冷却由模板生成。Muse 的消费路径看起来更自由（agent 自己写工具），但**出网和连接器动作并不自由**。v4 的收敛没有被 Muse 推翻。被标出来的是：自由应该留在哪一条车道，见下。

**全双工前台不是 Muse 已经解决的问题。** 他们的关系表面是文字和稍后的眼镜，没有「永远有人在听」的第一时钟。我们的 omni 前台 + 深度后台，切的是时延和话权。Muse 的单元格 / Sentinel，切的是伤害半径。两刀都要，不能并成一刀。

## 要补上的结构

### 1. 许可是另一台计算机，不是对话里的一句请求

Muse 把这件事做到了进程边界：Sentinel 在单元格外；审批卡由它直接发给客户端；用户的允许直接回到它；后续调用必须精确命中授权范围（连接器、目的地、用途；一次 / 会话 / 任务 / 时限 / 永久）。模型可以叙述、可以撒谎、可以被网页说服，但放行权不在它的工具列表里。

我们现在的 `waiting_user` 和审批，如果仍由执行中的模型在对话里「问一句」，就还是同一个 agent。全双工里这句话还会和闲聊、插话混在一条地板上。应对齐的是：

- 批准卡由中枢生成并投递，不由模型的下一条回复携带。目的说明可以让模型起草，但按钮的语义（允许哪一个动作、范围多大）由中枢校验，不由模型复述。
- 模型看不到「用户刚刚点了允许」的原始通道，只看到中枢给的结果。避免它在同一条上下文里对用户进行二次劝说。
- 永久允许必须绑对象和动作类，而不是绑「以后都别问」。这和 v4 里 standing grant 的方向一致；Muse 多强调的是范围要可核对到后续每一次调用。

### 2. 真凭证不进上下文

替身令牌、边界替换、连接器逻辑与 harness 分离、邮件里的验证码和重置链接先剥掉。原则一句话：模型不需要看见的秘密，就不要出现在它能读到的地方。

手机助手的高危面是发消息、付款、家居控制、以及任何能「代表用户去别的 App 点一下」的通道。这些工具的令牌应留在中枢或独立 worker，模型侧只拿与本次动作绑定的句柄。截屏、网页、对方发来的消息是不可信输入；读过它们的执行过程不应再自动获得出网或发送权。Muse 用 eBPF 污染做这件事。我们不一定要同一层内核机制，但**「读了不可信内容 → 失去自动放行」**这条状态要有，否则事件驱动任务（一封邮件、一次来电、一张截图）就是把 trifecta 接全的入口。

v4 已经规定：固定动作在创建期授权，需要确认的走 agentTurn + approval，script payload 不能中途问用户。这条保持。不要为了「更像 Muse」让脚本里的模型临时拿到凭证。

### 3. 两条车道，而不是一个更大的模板库

Muse 的长尾是：表单、一次性看板、没有官方连接器但有 API 的服务。这些靠「自己写工具」完成，而且写在没有真凭证的单元格里。我们的 v4 用五个模板覆盖晨报、条件提醒、到家开灯、指定来电、低电量。路线图里的抢票、交易、持续领先被明确挡住。

两边合在一起的分法：

| 车道 | 谁来写动作 | 适合 | 不适合 |
| --- | --- | --- | --- |
| 模板车道 | 模型只选模式、填参数。程序生成官方 job | 定时、单事件、简单条件、已授权的固定动作、本人提醒 | 开放网页、临时工具、看情况改计划 |
| 沙箱车道 | 模型可以写代码、读公开网页、起草。出网与发送仍走中枢 | 调研、草稿、一次性小工具、需要浏览器但停在提交前的步骤 | 付款、对外发送、家居不可逆动作、任何要真凭证的调用 |

没有第二条，模板库会被迫吃下所有长尾，模型负担回到 v4 想去掉的那种。没有第一条，沙箱里的模型会变成另一个 OpenClaw：默认 cwd，不是默认隔离。Muse 的工程量主要在第二条的围墙，不在让模型更会填 crontab。

### 4. 冷启动是一页建议，不是空输入

设计文把「能力太大以至于无人开口」写成早期测试的意外问题。解法是引导提示、Ideas、以及基于目标的主动调整，而不是更长的系统提示。

手机助手如果同时有对话、定时、事件、监视、长任务，空唤醒词会遇到同一个停顿。值得有一个不进主提示、由中枢维护的「现在能帮你做什么」——从已连接的能力和最近的失败 / 成功里来，而不是让模型每轮自由发挥一份菜单。这和 Ideas 同构，也避免菜单文本破坏缓存。

### 5. 关系表面和控制表面分开

WhatsApp 是关系，App 是日志、目标、记忆编辑和审批。纯聊天记录放不下确定性别控制。我们的全双工语音是关系表面；卡片、收件箱、`waiting_user` 是控制表面。不要把批准说成下一句 TTS，也不要为了「像跟人说话」把活动日志藏进对话流。用户不能看见的后台，就不会被信任。Muse 把头像下的「正在做什么」和完整活动日志当成信任的一部分，是对的。

## 不要抄的部分

- **不要抄「一人一台云 VM」当作手机助手的前提。** 我们的现场在手机上：来电、地理围栏、电量、相册、全双工。这些事件 OpenClaw 用本地节点接，Muse 的云电脑默认没有。把大脑全搬到云上，会丢掉 v4 首版真正要做的那几条（到家、来电、电量）。云沙箱只服务上表第二条车道。
- **不要抄 Muse 的主动消息文案门槛来替换分级。** 「值得打断」没有 speak_at_pause 和 digest。全双工会把二元门槛用坏。
- **不要用装机或「像一个人」当可靠性指标。** Muse 两周下载和 9 月 16 日的九题是反向的。我们的可靠性指标保持：不可逆动作的精确同意、注入后的不外带、事件任务的终态可回放。依恋和留存单独记。
- **不要假设模型会自己确认。** Spark 是被训过「不可逆先问、含糊就问、认得出自己做不到」的。我们的线上模型如果没有同样的目标，提示替代不了模板车道和中枢批准。v4「模型不写 job」就是这个替代，保留到模型真的具备那种校准为止。
- **不要把官方 cron 对象换成一套自创调度，以便「更像 Muse 的后台」。** v4 已经把这个坑填上。Muse 能从零写调度，是因为它拥有整台 VM 和 Sentinel。我们拥有的是 OpenClaw 的官方语义，偏离它就是重新发明失败语义。

## 两套分开的度量

| 度量 | 问的问题 | Muse 现在的位置 | 我们应对齐哪一列 |
| --- | --- | --- | --- |
| 物种有没有人要 | 零配置下，人愿不愿意把一件生活上的事交出去 | 下载说明愿意试。信任负债和 Confidential VM 未发货，说明还不敢把全部账号交出去 | 不追下载。追「用户愿意把哪一类权限打开」，以及打开之后关掉的比例 |
| 事情有没有做对 | 终态是否可核验；该停的时候停了没有；错的时候伤害是否有界 | 九题垫底；隐藏指令和形近账户守住了；公开页误停、自我评分失真 | 对齐这一列。模板车道的轨迹推演（v4 已有四条）继续当验收，不接受「模型说做完了」 |

Muse 证明的是需求侧：个人 agent 这个物种，在有人把运维和权限都包下来之后，普通人会装。它还没有证明无人值守可以把生活交出去。我们的设计如果守住「中枢批、模型不见密钥、不可逆走模板、可逆走围起来的沙箱、主动只有一个出口」，就是在用 Muse 还没跑完的那张成绩单约束自己，而不是在追它的下载曲线。
