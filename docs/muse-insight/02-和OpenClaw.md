# 02 和 OpenClaw

早期用户让 Muse 读自己的工作区，它自称和 OpenClaw 的系统文件「不是巧合，是匹配」。Friedman 不否认文件名和 `SOUL.md` 正文几乎相同，否认的是「底下就是 OpenClaw」：从零写的 harness，产品严重借鉴。OpenClaw 作者 Peter Steinberger 在 2026 年早些时候加入 OpenAI。下面按「直觉 / 文件契约 / 盒子」三层拆，避免把借鉴说成换皮，也避免把重写说成无关。

## 同一套产品直觉

OpenClaw（前身 Clawdbot、Moltbot）把 agent 定义成一台长期开着的电脑上的一个循环，而不是一轮聊天：

- Gateway 是唯一长期进程，占住各消息通道（WhatsApp、Telegram、Slack、Discord、Signal、iMessage 等）。控制面客户端和节点走 WebSocket。一台主机一个 Gateway。
- 每条会话是一条序列化的 run：收消息 → 装配上下文 → 推理 → 执行工具 → 流式回复 → 落盘。会话车道防止工具和转录互相踩。通道可以选择 steer / followup / collect / interrupt 把新消息送进这条车道。
- 工作区是家，也是默认 cwd。每次会话注入 `AGENTS.md`（怎么干活、怎么用记忆）、`SOUL.md`（人格、边界、语气）、`TOOLS.md`（用户写的工具备忘，不决定工具是否存在）、`IDENTITY.md`、`USER.md`、`HEARTBEAT.md`。`MEMORY.md` 可注入；`memory/YYYY-MM-DD.md` 不自动注入，靠 `memory_search` / `memory_get` 按需读。空白文件跳过，过大则截断。
- 技能是带路径的短清单。模型用 `read` 打开 `SKILL.md`，而不是把几千个工具 schema 全塞进提示。Steinberger 的公开说法是：技能是一句「这里有个 CLI」，CLI 可以管道组合，模型本来就擅长 Unix。MCP 在这个判断里是次要的。
- 心跳和 cron 让它在没人说话时也跑。该沉默时用精确的 `NO_REPLY`。子 agent 用裁过的 system prompt（去掉技能、记忆召回、自我更新、心跳等）。
- 模型可换。OpenClaw 把 Meta 做成官方外部插件，默认 `meta/muse-spark-1.3`，走 `https://api.meta.ai/v1` 的 Responses API。也就是说：**可以用 Muse 的模型跑 OpenClaw，那仍然不是 Muse 这个产品。**

Muse 拿走的就是这套直觉：一个人一台电脑；人格和用户是文件；技能按需读；后台会自己醒；聊天是入口；agent 可以改自己的文件和工具。设计文里的「它有文件系统和终端，所以能自己写代码、做任务需要的工具」，和 OpenClaw 的自我修改是同一句话。

## 被原样拿走的文件契约

值得抄、而且他们承认抄了的，是**工作区作为记忆与人格的接口**，不是 Gateway 的运维方式。

| 文件角色 | OpenClaw | Muse 上被观察到的 |
| --- | --- | --- |
| 人格与边界 | `SOUL.md`，每会话注入 | 同名，正文被指几乎相同。产品层又加了用户起的名字和头像——文件定义行为，头像定义「在跟谁说话」 |
| 用户是谁 | `USER.md` | 记忆文件用户可直接编辑，并有「忘掉这一条」 |
| 怎么干活 | `AGENTS.md` | 系统提示以「让用户的生活更好」起头；具体操作指令的公开全文未见，不能断言与 `AGENTS.md` 逐段相同 |
| 工具备忘 | `TOOLS.md` 是指导，不是工具开关 | 内置连接器是 privsep worker；agent 仍可为有 API / CLI 的服务自己写连接器 |
| 何时自己醒 | `HEARTBEAT.md` + cron | VM 里的 cron，加上「做完要不要浮出」的判断。bake-off 里看到的是一个被复用的禁用 cron，说明机制在，产品状态不一定干净 |
| 每日记忆 | 按需检索，不进每轮提示 | 公开材料只确认记忆是可编辑文件、会用于未经提示的建议。是否分层成「策展长期 / 按日日志」没有官方说明 |

这个契约为什么能被原样拿走：它把「模型没有跨会话记忆」写成了文件协议。新会话是新人，读过文件才记得。人格、用户事实和操作规程因此可以版本化、可删、可被人审，而不是埋在权重或一条无限变长的聊天里。Friedman 说 Peter 做对的，指的是这个，不是某段提示词的文采。

## 被重写的盒子

OpenClaw 文档自己写明：工作区是默认 cwd，**不是硬沙箱**。绝对路径仍然够得着主机别处，除非打开 `agents.defaults.sandbox`。凭证在 `~/.openclaw/credentials/`。工具能不能跑，靠工具策略和 `before_tool_call` 这类钩子；钩子在进程内，和模型同一侧的运营边界里。通道要自己配对、自己保活。技能市场（ClawHub，社区技能数千）是扩展面。

Muse 把预算花在盒子上。对照如下。

| 轴 | OpenClaw | Muse |
| --- | --- | --- |
| 谁运维 | 用户。Mac、VPS、甚至更小的板子。Gateway、密钥、频道、技能、更新都是用户的事 | Meta。打开 App 即有一台 VM。用户不 SSH，但可以读、改、下载里面的文件 |
| 隔离的默认值 | 可选沙箱。不配就是主机上的一个 cwd | 默认两个安全域。运行时单元格预期会吃到不可信数据；许可、凭证、分类器、数据库在单元格外 |
| 模型 | 任选，包括把 Spark 当供应商 | 产品锁定 Spark，并且模型是对着这类 harness 训的。API 上的 Spark 谁都能接，那不是 Muse |
| 通道 | 十几个，用户自己接。WhatsApp 会话由这台主机上唯一的 Gateway 占住 | 一等公民是 Muse App 和 WhatsApp。没有公开的「再接一个 Telegram」 |
| 出网与密钥 | 工具进程通常看得到环境里的令牌。策略可以限制，模型仍可能被骗去读 | 模型永远不见真令牌。替身在边界替换。连接器逻辑在 privsep worker，凭证允许列表按 worker 而不是按提示 |
| 谁说了算 | 同一条 agent 循环上的策略、审批卡、standing grant（cron 文档里的官方机制） | 另一个 agent。审批 UI 不在对话里。模型不能把 Sentinel 说服成放行，因为放行权不在它的循环里 |
| 不可信数据 | 技能和提示里的约定，加上用户自己的钩子 | 进入上下文即标注；单元格外分类器；浏览器只给无障碍树；邮件连接器剥掉验证码和重置链接；eBPF 污染让「读了用户数据」的进程失去自动放行 |
| 扩展 | 安装技能 / 插件，社区市场，工作区技能覆盖同名内置技能 | 没有 bot 商店。官方连接器 + agent 自己写。技能留在这台 VM |
| 自动化 | cron 的 `at / every / cron / stream`，脚本与 agent 回合是官方对象。用户或上层产品决定 job 长什么样 | 日程和相关事件由产品驱动；浮出与否再判一次。用户不写 crontab |
| 沉默 | `NO_REPLY` 是模型输出的精确令牌；该回复的回合即使模型沉默，主机仍要求有答案 | 主动消息有产品级门槛，用户可调。bake-off 说明「该不该停」仍会判错（公开页被当成需要批准） |
| 子 agent | 裁剪后的提示，省掉记忆和心跳 | 安全文写明会拉起一群 subagent。浏览器任务用专门的浏览器 subagent，指令里写明哪些内容可能是对抗性的 |
| 计算机在谁那里 | 默认在用户自己的机器上。数据不出这台机器，是 OpenClaw 的隐私论点 | 在 Meta 的云上。用户之间隔离；员工访问靠策略；Confidential VM 才是「Meta 也打不开」。今天还没到 |
| 商业 | 开源 runtime，模型费用用户自付 | 免费档 + 20 / 100 美元月费买算力。对话不进广告系统 |

一句话：OpenClaw 是**你住进去的 runtime**。Muse 是**你给它发消息的一个人**，他的电脑你不登录，他的出网权在另一个程序手里。

## 为什么重写的是盒子，不是循环

循环没有秘密。OpenClaw 作者自己的说法也是：理解了 agent loop，就理解了范式；技能、记忆、心跳、自我修改都是循环外面的接线。Meta 从 1 月的 Mac mini 集群上确认接线是对的，然后发现这条接线**不能原样扩到不会运维的人**：

- 不会运维的人不能为沙箱、频道和密钥负责。默认不隔离，等于默认把 lethal trifecta 交给提示词。
- 通道和 Gateway 是能力，也是失败面（会话被占、配对、重连、事件不重放——官方不变量写明事件不重放，客户端发现缺口必须自己刷新）。几十亿人的产品不能把这些留给用户。
- 技能市场是构建者的扩展性。生活 agent 的头一批连接器（邮件、日历、车、家、Instagram、Facebook、Stripe）需要和对方一起做 API，并写成会用的 SKILL。这是供给问题，不是「再装一个社区技能」。
- 模型可换是构建者的自由，也是行为不可复现的来源。产品要把「不可逆之前确认、含糊就问、一条线程里认任务」变成稳定行为，就得锁模型并参与训练。OpenClaw 接 Spark，得到的是模型，得不到 Sentinel、替身令牌和 WhatsApp 里的那个人。

所以「像 OpenClaw」是产品规格，「从零写」是安全规格。两者同时为真。

## OpenClaw 仍然更强的地方

这些不是 Muse 的落后功能，是物种里留给构建者的那一半：

- **数据在自己的磁盘上。** 不依赖 Meta 的运营策略，也不必等 Confidential VM。代价是主机本身的安全变成用户的问题。
- **模型和通道可换。** 同一套工作区可以换供应商；Spark 降价或变差时不必迁移「那个人」。
- **技能与钩子是开放的。** `before_tool_call` 可以阻断，`agent:bootstrap` 可以换掉注入的 `SOUL.md`，工作区技能覆盖内置。Muse 的策略在 Sentinel 和连接器策略里，用户调的是读写范围和谨慎程度，不是任意代码钩子。
- **它就是本仓库 openClaw 自动化所对接的那套官方对象**（`at / every / cron / stream`、`trigger.script`、approval card、standing grant）。Muse 的 cron 是产品内部的，没有这套可依赖的外部契约。
- **本地节点。** 手机摄像头、屏幕、位置可以作为 `role: node` 连上 Gateway。Muse 的云 VM 看不见用户手里的那台手机，除非服务商做了连接器。

构建者选 OpenClaw，是因为要住在 runtime 里。普通人选 Muse，是因为只要给一个人发消息。用 Spark API 把 OpenClaw 接起来，两头都不是对方。
