Agent 变量方案 v5

工具结果原样存入 Working Memory 并包信封给模型 · 模型用 ${resultId.字段名} 引用 · 框架在执行下游工具前替换为真实值

背景 · 解决什么问题

  • toolA 结果常含长值（绝对路径、签名 URL），toolB 依赖它
  • 模型逐 token 复述：增量推理时延随长度线性放大（246 字符 ≈ 80+ tokens）
  • 抄错一个字符即失败（403 / 路径不存在），多轮对话反复复述使上下文膨胀

方案原则

  • 工具零修改：A 原样返回，B 收到真实值，两端对机制零感知
  • Agent 系统不感知业务：框架只认 resultId 与 ${} 协议标识，不理解任何字段含义
  • 模型零抄写：只写引用不复述内容（skill 描述中一句指引）

关键规则

  • 替换时机：schema 校验之后、工具执行之前；真实值不回写对话历史
  • 落点转义：invoke 值语义注入；exec 自动 shell 单引号包裹（防截断/注入）
  • 出错回喂：id / 字段不存在、已过期 → 不执行，附可用字段清单，模型自纠

③④ 信封 = 原始结果 + 元信息（resultData 原样，无任何加工）

{
  "toolName": "image_gen",
  "responseText": "已生成图片。引用字段请写 ${a3f8k2p9.字段名}，勿抄写内容。",
  "resultId": "a3f8k2p9",        // 框架生成，8 位随机，跨轮唯一
  "resultData": {                  // 工具原始返回，一字不改
    "img_uri": "https://cdn.example.com/imgs/2026/08/10/f7c3a91e-…-4096.png?sig=Kx7Qw9f2…&exp=1754800000",
    "createTime": "2026-08-10T04:05:12Z"
  }
}

⑤⑥ 引用与替换（两种落点）

// invoke：值语义注入，保留类型
invoke("edit_image", {"source": "${a3f8k2p9.img_uri}", "op": "crop"})

// exec：框架替换时自动 shell 转义
exec(command="curl -o /tmp/img.png ${a3f8k2p9.img_uri}")
// 实际执行 → curl -o /tmp/img.png 'https://cdn.example.com/…&exp=…'

嵌套/数组结果按路径引用：${a3f8k2p9.items[0].url}； 工具结果原文中的 ${ 入库时转义，防伪造引用。

生命周期

创建：默认 loop 作用域→ 被引用 提升 conversation · 每次引用续期→ N 轮未引用 TTL 淘汰（大值可先降级磁盘）→ 物理失效 过期：引用报错 + 提示重取 ·随对话 checkpoint，恢复后 ${…} 不悬垂

收益

B 调用传参 80+ tokens → 8 tokens；抄写错误结构性归零；对话历史中长值只出现一次
