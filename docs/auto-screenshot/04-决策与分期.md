# 04 决策、核实与分期

> 02/03 把「能做、怎么做」说完。这里留下需要产品 / 客户端拍板的点和一期边界。

## 1. 建议拍板（D1–D6）

### D1 · 热路径不上模型（建议锁定）

判定 = 分块差 + 稳定门 + 本场 pHash。模型只允许出现在会后（起名、PDF、非课件过滤）。
理由：隐私、功耗、可测试性。若以后要加模型，也是对**已经落盘的正集**跑，不进采帧循环。

### D2 · 默认「最终态」而不是「每一步动画」（建议锁定）

对应 01 的 Dup-B。稳定门 `dwell ≈ 800 ms`。另给高级开关「捕获每一次明显变化」。
两套行为不要合成一个灵敏度。

### D3 · 去重范围 = 本场会话，不是终身图库（建议锁定）

回翻只查这一次会议的哈希表。昨天那堂课的同一张封面，今天再上应该再存。
终身去重会误伤「每周例会同一模板」。

### D4 · 采集范围默认「能窗口就窗口」（建议锁定）

PC 默认前台窗口；Android 14+ 默认引导单应用投影；iOS 只能整机 + ROI。
整屏作为显式选项，不当默认（iOS 除外）。

### D5 · 落盘位置（待选，建议 A）

| 选项 | 含义 | 后果 |
| --- | --- | --- |
| **A. 应用私有目录 + 本场相册入口** | 默认不进系统相册 | 隐私更好，分享要走导出 |
| B. 直接进系统相册专辑 | 和系统照片 App 在一起 | 备份/iCloud 可能把会议资料同步走 |

建议一期 A，导出动作再进相册。会议截图误同步到云是事故。

### D6 · iOS 是否进一期（待选，建议「二期」）

同一套判定纯函数可以复用，但 ReplayKit 扩展、审核话术、系统红条会占掉一截体验预算。
建议 Windows + Android 先过 01 的黄金样例，再接 iOS。

## 2. 动手前核实（V1–V6）

| # | 核实什么 | 怎么核实 | 若失败 |
| --- | --- | --- | --- |
| V1 | 目标会议 App 窗口能否被 WGC / 单应用投影单独采到，而不是黑屏或空表面 | 腾讯会议 / Zoom / Teams 各试一次共享 PPT | 退回整屏 + ROI，并在 UI 上说明 |
| V2 | 共享区是否含硬件叠加层（鼠标激光、远程光标）导致「画面已变但缓冲区没变」或反过来 | 共享中动激光笔 | 脏矩形失效则强制走分块差 |
| V3 | Android 14 单应用投影 + 前台服务在目标机型上的存活时间（30–90 min 课） | 真机上课长度 | 被杀则补唤醒策略或接受「中断后可续场」（目录会话 id） |
| V4 | 头像小窗在常见布局里运动统计能否稳定标成忽略格 | 左右布局、悬浮小窗、画中画各 1 段 | 失败则进入模式强制让用户画一次忽略框 |
| V5 | 默认阈值在「动画很多的页」vs「两页模板极像」上会不会互斥 | 准备这两类样例各 1 段 | 不能同时过则「严格/标准」分档，默认保「少存」 |
| V6 | iOS 扩展内存上限下 2 fps pHash + JPEG 编码是否会 jetsam | 真机 60 min | 不行就只在扩展里写分析尺寸图，回前台再超分——清晰度会差，要提前认 |

## 3. 分期

### 一期：最小可关的自动截图

- 用户手势开/关，可见指示器，权限失败有文案；
- Windows 窗口采集 + Android `MediaProjection`；
- 02 四段管线默认档 + 三档预置 + 「捕获动画」开关；
- 进入时可框选区域；运动 ROI 有则开，没有就靠框选；
- 本场文件夹、缩略图、删除、手动补当前帧；
- 用录像回放跑判定纯函数的回归（黄金样例）。

### 二期：体验与会后

- iOS ReplayKit Adapter；
- 自动课件矩形、非课件回收站；
- 会后 OCR 文件名、导出 PDF；
- 与 [照片搜索 × 相册整理](../photo-search-album/README.md) 对接：「把今天自动截的课件建册」；
- 续场：进程被杀后用同一会话 id 接着去重。

### 三期（按需，不承诺）

- 端侧小模型标 `not_slide`；
- 浏览器扩展作为 PC 第三 Adapter（仅网页课）；
- 和会议 SDK 的共享流对接（按厂商单独评估）。

## 4. 风险排序

| 风险 | 严重度 | 缓解 |
| --- | --- | --- |
| 会议头像导致狂截 | 高 | ROI + 指定窗口；黄金样例卡住发布 |
| 动画页被拆成一堆近似图 | 高 | 稳定门默认开；D2 锁定 |
| 两页极像模板被合成一张 | 中 | 「严格」档；用户手动补 |
| 系统收回录屏权限 / 锁屏停 | 中 | 按设计属于正确行为，做好 S9 收口 |
| iOS 看起来像在偷录 | 高（若硬上一期） | D6 放到二期；文案与系统指示器共存 |
| 清晰度不足（虚屏开太小） | 中 | 虚屏用内容分辨率，分析再缩小 |
| 隐私事故（默认同步 iCloud） | 高 | D5 选 A |

## 5. 和仓库其它主题怎么接

- **不是** openClaw 那种 `cron` 自动触发。这是用户当场打开的长任务，对应手机助手里「用户触发的长时任务」：有明确开始/结束，中途可停。
- 判定**不要**做成 `trigger.kind = agent` 看图。那会把每 0.5 s 一次变成一次模型 round-trip，和 02 的 D1 冲突。
- 会后整理可以是一个独立 skill：正集已经是普通图片，走现有图库工具即可。

## 6. 一句话给实现的人

先把判定写成**可回放的纯函数**（小图序列 → 保存时间点列表），用黄金样例把 Dup-A/B/C/D 调过；
再挂 Windows 与 Android 两个 Adapter。
采屏 API 会吵、会变、会要前台服务，但那部分不该反过来污染判定。
