# 02 核心管线：采屏 → 变化 → 稳定 → 去重

> 结论先行：**能做，而且应该做成端上四段管线，不要做成「定时盲截 + 模型挑选」。**
> 业界从课录像里抽幻灯片的开源工具（AutoSlides-Extractor、slides-extractor 一类）
> 已经把同一套判别用熟了：SSIM / 分块差找切点，等停稳再取清晰帧，pHash 做近重复删除。
> 我们要做的是**实时版**——输入从「事后视频」换成「正在进行的屏幕采集」。

## 1. 先否定的两条路

| 方案 | 做法 | 为什么不作为主方案 |
| --- | --- | --- |
| 定时盲截 | 每 2 s 存一张，会后再人工删 | 一场课几百张；没解决「重复不要」 |
| 每帧送模型 | 多模态模型看「这页新不新」 | 会议内容出端、费用、功耗、时延全部不可接受；判定也不比哈希更稳 |

模型可以留在**会后**：给正集起名、排版成 PDF、判断某张是不是「老师特写」。
热路径（每秒几次）必须是确定性视觉算法。

## 2. 推荐架构

```text
用户打开「自动截图模式」 → 拿到平台 Capture Session
        │
        │  分析轨：低分辨率、1–4 fps、灰度
        │  保存轨：仅在「通过去重」时要一张原分辨率
        ▼
┌───────────────────────────────────────────────────────────┐
│ ① Capture Adapter                                         │
│    窗口 / 整屏 / 单应用投影 → 两路帧（分析小图 + 按需原图） │
└───────────────────────────┬───────────────────────────────┘
                            ▼
┌───────────────────────────────────────────────────────────┐
│ ② Change Detector                                          │
│    先套 ROI 掩膜（忽略头像、时钟、鼠标）                      │
│    分块平均差 或 DXGI 脏矩形                                  │
│    未过阈值 → 丢弃本帧（可把采样再降一档）                    │
└───────────────────────────┬───────────────────────────────┘
                            ▼
┌───────────────────────────────────────────────────────────┐
│ ③ Stability Gate                                           │
│    变化发生后，连续 K 帧彼此 dHash 很近，且再保持 dwell 毫秒  │
│    期间又变化 → 重置计时（动画还没演完）                      │
│    目的：Dup-A 过渡、Dup-B 逐条出现，默认等到最终态            │
└───────────────────────────┬───────────────────────────────┘
                            ▼
┌───────────────────────────────────────────────────────────┐
│ ④ Unique Filter（本场哈希表）                               │
│    对稳定帧算 64-bit pHash（可再加 dHash）                    │
│    与本场已保存的每一条比 Hamming 距离                        │
│    min_dist < T_dup → Dup-C / Dup-D，跳过                    │
│    否则拉原分辨率、JPEG 落盘、把哈希追加进本场表               │
└───────────────────────────────────────────────────────────┘
```

四段各答一个问题：

| 段 | 问题 | 失败时的用户观感 |
| --- | --- | --- |
| 采屏 | 采得到用户正在看的那块吗 | 权限弹窗、黑屏、截到自己的悬浮条 |
| 变化 | 现在和刚才是不是同一页 | 头像一动就狂截，或真翻页却毫无反应 |
| 稳定 | 这一页演完了吗 | 半透明过渡帧、bullet 出到一半 |
| 去重 | 这一页本场见过吗 | 回翻目录反复存 |

## 3. 算法怎么配（默认档）

全部在 CPU 上对 **320×180 左右灰度图**做。手机上这个量级每帧远低于 1 ms，不必上 GPU。

### 3.1 变化检测：分块差，不要一上来 SSIM

对分析图划 `M×N` 网格（建议 8×8 或 16×9）。每格算平均灰度。
与上一分析帧比，**被 ROI 标成「可忽略」的格子直接跳过**。
剩下格子里，`|Δ| > blockDelta` 的比例超过 `changedRatio`（默认约 0.12–0.18）→ 认为「有内容变化」。

这比整图 SSIM 便宜，也比「整图像素差」更能抗单点噪声。
Windows 若走 DXGI Desktop Duplication，可把 `GetFrameDirtyRects` 当零成本预检：
脏矩形为空就不做视觉计算；脏矩形全落在忽略区也跳过。

整图 SSIM 留作备选校准，不要当热路径默认——课录像离线可以慢慢算，实时没必要。

### 3.2 稳定门：连续相似 + dwell

伪代码：

```text
on_frame(small):
    if not changed(small, last_small, roi):
        maybe_slow_down_sampling()
        return
    # 进入「等待停稳」
    stable_count = 0
    last_change_at = now
    while mode_on:
        f = next_small_frame()
        if hamming(dhash(f), dhash(prev)) > T_stab:   # 还在动
            stable_count = 0
            last_change_at = now
        else:
            stable_count += 1
        if stable_count >= K and (now - last_change_at) >= dwell:
            consider_save(f)   # 用停稳后的那一帧，不要用刚检测到变化的那一帧
            break
```

默认建议：分析 2 fps，`K = 3`（约 1.5 s 内连续相似），`dwell = 800 ms`。
对 Dup-B：最后一条 bullet 出现后还要再等这一小段，才会存「最终态」。
若用户打开「捕获每一次明显变化」，把 `dwell` 降到 0、`K = 1`，稳定门几乎关掉。

**不要存变化发生的那一帧。** 那一帧经常是淡入 30% 的过渡。业界离线抽页甚至会「在下一次切点往回 1 秒」取图；实时场景没有未来切点，用「停稳后再取当前帧」是同一意图的因果版本。

### 3.3 去重：本场 pHash 表，不是只跟上一张比

- 算法：64-bit pHash（DCT 低频）。对缩放、轻度压缩、JPEG 再编码稳。
- 相邻几乎一样用 dHash 也可以，但 **Dup-D 回翻必须查整张本场表**。
- 64-bit 汉明距离：默认 `T_dup = 8`（约 12.5% 位不同）。更严 → 更容易存出「只差一个图标」的两张；更松 → 可能把两页相似模板判成一张。
- 本场 200 张以内，对每条 `popcnt(h ^ saved[i])` 即可，不必上 HNSW。
- 同时保留 dHash：pHash 与 dHash **都**说「几乎一样」才合并（slides-extractor 的做法），避免某一哈希偶然撞。

保存时写入 sidecar（或同名 `.json`）：`phash`、`dhash`、时间戳、来源窗口、所用阈值。方便事后重放调参，不必对着 JPEG 猜。

### 3.4 空白 / 非课件

稳定之后先做两个超便宜的否决：

- 灰度方差过低 → 黑屏、白屏、纯色休息页，不进正集（可进「已忽略」回收，方便用户捞回）；
- 可选二期：端侧小分类器（MobileNet 级）标 `slide / maybe / not_slide`。一期用规则就够。

## 4. ROI：会议场景能不能用的关键

只靠全局哈希，S1 会失败——右上角 1/8 的头像一直在动，全局差永远过阈值。

三层，按实现成本叠：

| 层 | 做法 | 何时够用 |
| --- | --- | --- |
| 用户框选 | 进入模式时让用户画「只看这块」或「忽略这块」 | PC 窗口已经很干净时甚至可以不做 |
| 系统排除 | 采屏 API 排除光标、排除自己的悬浮条 | 所有平台都应该开 |
| 运动统计 | 过去 ~10 s 每格的运动能量：持续高运动 = 视频/头像/弹幕；大部分时间静止、偶尔整块跳变 = 课件 | 会议 / 网课默认开 |

运动统计的用法：变化检测和 pHash **只在「课件格」上算**。
头像格从哈希里挖掉（填中性灰）再 pHash，回翻判定才不会被「换了个说话的人」带偏。

进阶（二期，非必须）：找「最大的低运动矩形」当课件区，相当于自动裁掉会议控件。
裁切只用于判定；落盘仍存用户选定的窗口全图，避免把标题栏裁没。产品也可提供「只保存课件区」。

## 5. 自适应采样与功耗

| 状态 | 分析帧率 | 说明 |
| --- | --- | --- |
| 刚检测到变化 / 稳定门未过 | 4 fps | 抓紧抓住停稳时刻 |
| 正常盯着一页 | 2 fps | 默认 |
| 连续 >20 s 无变化 | 1 fps | 老师在讲、页没动 |
| 连续 >60 s 无变化 | 0.5 fps | 仍要醒着，防止漏下一次翻页 |

原分辨率帧**默认不取**。只有 `consider_save` 通过 Unique Filter 才向 Adapter 要一张大图
（或从环形缓冲里取最近的全分辨率帧）。分析轨可以一直是缩小的 `ImageReader` / 缩放后的 BGRA。

编码：JPEG 质量 85 左右；同一场分辨率固定。不要存 PNG 无损，一场课体积会差一个数量级。

## 6. 和「截视频课事后抽页」的差别

| | 事后抽页（开源工具已熟） | 我们要的实时自动截图 |
| --- | --- | --- |
| 输入 | 完整 mp4 | 正在进行的屏幕流 |
| 取清晰帧 | 可以「下一次切点往回 1 s」 | 只能等停稳，不能看未来 |
| 全局去重 | 可以两遍扫 | 必须在线维护本场表，效果等价 |
| 采样 | 可跳帧、只看 I 帧 | 自己决定 fps，Windows 还可跟脏矩形 |
| 主干扰 | 编码器噪声、片头片尾 | **头像小窗、本机 HUD、通知** |

所以：算法家族可以直接搬，工程重点搬到 **Capture Adapter + ROI + 权限/指示器生命周期**。

## 7. 参数预置（给产品的三档，而不是把每个阈值暴露给用户）

| 档 | 适用 | changedRatio | T_dup | dwell |
| --- | --- | --- | --- | --- |
| 严格 | 模板高度相似的正式 PPT | 略低（更敏感） | 6 | 800 ms |
| 标准（默认） | 会议共享 + 网课 | 0.15 | 8 | 800 ms |
| 宽松 | 板书、网页滚动 | 略高 | 12 | 400 ms |

「捕获动画步骤」是独立布尔，不要塞进这三档。

调参方式：用 01 章的 20 分钟黄金样例回放分析轨（不必真采屏），看正集张数和漏页。
阈值是产品资产，写进配置，不要写死在代码里。
