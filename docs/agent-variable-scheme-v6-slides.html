Agent 变量方案 v6 · 1/2 方案

工具结果原样存入 Working Memory 并包信封给模型 · 模型用 ${resultId.字段名} 引用 · 框架在执行下游工具前替换为真实值

背景 · 解决什么问题

  • toolA 结果常含长值（绝对路径、签名 URL），toolB 依赖它
  • 模型逐 token 复述：增量推理时延随长度线性放大（246 字符 ≈ 80+ tokens）
  • 抄错一个字符即失败（403 / 路径不存在），多轮对话反复复述使上下文膨胀

方案原则

  • 工具零修改：A 原样返回，B 收到真实值，两端对机制零感知
  • Agent 系统不感知业务：框架只认 resultId 与 ${} 协议标识，不理解任何字段含义
  • 模型零抄写：只写引用不复述内容（skill 描述中一句指引）

关键规则

  • 替换时机：schema 校验之后、工具执行之前；真实值不回写对话历史
  • 落点转义：invoke 值语义注入；exec 自动 shell 单引号包裹（防截断/注入）
  • 出错回喂：id / 字段不存在、已过期 → 不执行，附可用字段清单，模型自纠

③④ 信封 = 原始结果 + 元信息（resultData 原样，无任何加工）

{
  "toolName": "image_gen",
  "responseText": "已生成图片。引用字段请写 ${a3f8k2p9.字段名}，勿抄写内容。",
  "resultId": "a3f8k2p9",        // 框架生成，8 位随机，跨轮唯一
  "resultData": {                  // 工具原始返回，一字不改
    "img_uri": "https://cdn.example.com/imgs/2026/08/10/f7c3a91e-…-4096.png?sig=Kx7Qw9f2…&exp=1754800000",
    "createTime": "2026-08-10T04:05:12Z"
  }
}

⑤⑥ 引用与替换（两种落点）

// invoke：值语义注入，保留类型
invoke("edit_image", {"source": "${a3f8k2p9.img_uri}", "op": "crop"})

// exec：框架替换时自动 shell 转义
exec(command="curl -o /tmp/img.png ${a3f8k2p9.img_uri}")
// 实际执行 → curl -o /tmp/img.png 'https://cdn.example.com/…&exp=…'

嵌套/数组结果按路径引用：${a3f8k2p9.items[0].url}； 工具结果原文中的 ${ 入库时转义，防伪造引用。收益：B 调用传参 80+ tokens → 8 tokens，抄写错误结构性归零。

Agent 变量方案 v6 · 2/2 端到端示例与 Skill 引导

示例任务："生成一张横幅图，裁剪成 16:9，下载到本地"

端到端示例 · 六步走完

1. 模型调 Ainvoke("image_gen",
{"prompt": "产品横幅"})
→
2. 框架包信封A 返回 246 字符 URL
→ 原样存为 a3f8k2p9，信封给模型
→
3. 模型调 B（引用）invoke("edit_image", {"source":
"${a3f8k2p9.img_uri}", "ratio": "16:9"})
→
4. 替换执行B 收到完整 URL 裁剪成功
新结果存为 k2m9x4qt
→
5. 模型 exec 下载exec(command="curl -o /tmp/b.png
${k2m9x4qt.img_uri}")
→
6. 转义执行框架单引号包裹后执行
curl -o /tmp/b.png '…&exp=…'

出错自纠（第 3 步若写错字段名）

invoke("edit_image", {"source": "${a3f8k2p9.imgUri}"})   // 字段名拼错
// 框架不执行，回喂 → {"error": "unknown_field",
  "message": "a3f8k2p9 无字段 imgUri，可用：${a3f8k2p9.img_uri}、${a3f8k2p9.createTime}"}
// 模型复制正确引用重试，成功

全程效果

模型两次传参共输出 ~16 tokens（无变量方案约 160+ tokens）； 246 字符 URL 从未被模型复述过，对话历史里只在信封中出现一次； 第 5 步 exec 中 URL 的 & 由框架转义，命令不会被截断。

Skill 如何引导 · 参数描述里写明（调用现场，遵循率最高）

name: edit_image
description: 裁剪/缩放图片
parameters:
  source:
    type: string
    description: >
      图片地址。该参数通常来自上游工具结果：直接填写上游信封中的
      ${resultId.字段名} 占位符（如 ${a3f8k2p9.img_uri}），
      不要复制粘贴 URL 内容，框架会在执行前自动替换为真实值。

三处引导，口径一致

  • 参数描述（如左）：写在依赖上游结果的参数上，调用现场提醒
  • system prompt 一条兜底："工具结果信封含 resultId；引用其字段时输出 ${resultId.字段名}，禁止抄写字段内容"
  • responseText 随信封提醒："引用字段请写 ${a3f8k2p9.字段名}，勿抄写内容"

边界：模型自己创作的内容（如新写的文案、自定的本地路径 /tmp/b.png）直接内联，不引用；只有"来自上游结果的值"才用 ${}。

生命周期
