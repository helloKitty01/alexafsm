## 深挖一：Muse 的电话不是那台 VM

Reuters 看到的内部帖子把链条写清楚了。8 月员工开始狗食外呼，产品发布后几天逐步给 Muse 用户。用户可以让它打美国商家的电话：理发、问库存、向承包商询价。商家听到是 AI 会挂断。于是上周给大约一半员工打开 human agent calls：Muse 把请求交给受过训练的人，由人把电话打完。不想参加的员工可以进退订组。对外没有对等的披露。

负责人在内部帖子里同时说了两件不能拆开的话：不披露就测是失误，功能先回滚；他们仍在 “hillclimbing AI calling”，因为人工能把成功率做到 95%–98%，纯 AI 外呼明显更低。发言人 Daniel Roberts 的公开口径是员工反馈「 overwhelmingly positive」，目的是上线前补安全和隐私，只会在准备好并披露之后再推。股票叙述也在同一篇里：发布后涨超 20%、市值增加超过 2000 亿美元（Reuters 引 Sensor Tower 的下载仍是 250 万以上）。周二股价回落 0.6%。

这和安全文里的 Secure VM 是两套边界。VM、Sentinel、替身令牌管的是模型能不能自己把数据送出那台电脑。电话一交给承包商，数据离开的路径是人耳和呼叫中心工单，不是 eBPF 能标脏的那个进程。员工原话是 “one bug away from unnecessary information being leaked to human callers”。另一通谈宽带账单的电话里，转写出现种族相关用语。安全卖点被自己人指为被这项测试挖掉。

十年前 Messenger 里的 M 后来被媒体估计大约七成任务其实是人做的。Reuters 把这次测试放回那条谱系，不是比喻：商家拒绝和机器说话时，产品会用人类把「agent 办成了」补完。对手机助手，外呼如果存在，必须在创建任务时就说清接听方是模型、人，还是先模型失败再转人。转人是一次新的许可，不是外呼工具的内部实现。成功率不能当成把披露往后放的理由。

回滚是今天的状态，不是这个通道已经安全。公开说法仍是会和商家一起把呼叫功能做完，披露之后再发。

## 深挖二：ContrAgent，轨迹上的合同，不是每一次调用的白名单

[arXiv:2609.18128](https://arxiv.org/abs/2609.18128)，Yifeng Xiao、Pierluigi Nuzzo（UC Berkeley EECS），2026-09-16 投稿。

论文把 agent 定义成工具调用的迹：每次调用有 call 和 return 两个事件。要守的性质经常跨多步（先读了不可信内容就不能再发送、一天只能对外一次、委托之后身份不能换）。逐调用的规则看不出这些。事后用 LLM 打分则每次结论不一样。

ContrAgent 用有限迹上的线性时序逻辑写假设–保证合同，编成确定有限自动机。同一个自动机干两件事：在线时挡住会使合同失败的下一步；离线时给整段轨迹一个确定裁决（空闲 / 生效 / 失败）。合同库不绑某个模型，同一任务域里可以换 agent。文中点名的框架包括 OpenClaw、HermesAgent、LangChain。摘要里的结果是：四个基准上对齐当时的 LLM 裁判和规则护栏，在线每步延迟低几个数量级，裁决可复现。正文没有在摘要里给出「攻击成功率从多少降到多少」这种单一数字，这里不补。

和我们已有设计的关系：

- 它守的是工具迹，不是模型的意图句。这和「批准卡由中枢核对动作，不由模型复述」同向。
- 它解决不了 Muse 电话那种出界：人打出去的电话根本不在工具迹上，自动机看不见。
- 它也解决不了工具幻觉论文里的第一步。幻觉调用指向注册表里没有的名字，合同的原子命题如果只对已知工具定义，这条调用在进自动机之前就要被解析层拒绝。两篇 9 月 16 日的论文因此是前后两级：先闭世界解析（2609.19425），再对真实工具做轨迹合同（2609.18128）。
- 手机助手里「读过不可信内容则失去自动发送」是一条跨事件的保证，适合写成这种合同，而不是写进某一轮的提示。
