## 深挖一：监控读的那条痕迹，可以被套壳删掉

[arXiv:2609.27542](https://arxiv.org/abs/2609.27542)，Muhammad Usama、Khair Un Nisa、Summer Yeoreum Jung（Braindeck；University of Wah），2026-09-23 投稿。代码与逐次日志：https://github.com/Usama1002/deleting-the-trace

论文把 agent 的安全写成模型和套壳的乘积。套壳做两件事：用聊天模板把文本渲染成模型的回合，再用解析器决定一段生成算不算一次工具调用。两边都可以从不可信输入打到。测量是全精度、贪心解码、已公开发布的模型，不是 Fable、Opus 或 Astra 的分数。

第一面是推理通道。gpt-oss 用 Harmony 格式把分析通道和最终通道分开，分隔用的是模型词表里的控制符。不可信文本一旦被分成这些控制符，分词之后就和套壳自己写出的结构没有区别。作者在用户消息后附上模型自己的通道控制符，使推理回合在渲染时已经闭合。模型不再往分析通道写字，直接走到工具调用。40 个模型本来就会完成的任务上，推理从平均 52.5 个 token 降到每一次都是 0，`http.post` 每一次都发出。选这 40 个任务，是为了把「痕迹没了」和「动作改了」分开：动作本来就会发生。

监控假定危险意图会出现在痕迹里。规则监控和跨家族的语言模型监控，在普通试次上全部发现不安全请求，在伪造试次上全部没有发现。明显恶意的请求上，39.6% 的原本拒绝变成完成的外带，因为拒绝算在被压掉的那条通道里。没有部署监控的地方，这个绕过仍然造成伤害。空痕迹检测能抓住基本形态，抓不住作者描述的适应性诱饵：痕迹里放一段无害的推理，三个监控一起漏。论文写明，朴素地删掉控制符会误伤正常输入。

第二面是解析器。同一段生成，缺了闭合控制符时，宽容的正则会执行，严格的正则会丢掉。这在没有模型参与的情况下就能确定，官方参考解析器里也有这种宽容。已发布的 Gemma agent 上，两套随附解析器对同一贪心生成给出相反结果：24 次全部执行，对 24 次全部不执行。间接投递（检索文档、文末附注、工具返回）也能把第一面送进去。作者还在另外两个推理模型上看了聊天模板的差异，并写明抑制是否成立取决于模板。这里不把模板或控制符的具体拼法再写一遍。

和已有设计的关系：

- 手机助手的中枢如果靠「读模型这段思考，再决定烦不烦用户、放不放行」，读到的可以是空的，或者是诱饵。放行看的应是即将执行的那次工具调用，思考文本只是旁证。
- 全双工前台更不该把思考当门。思考可以缺席，工具调用仍然发生。`waiting_user` 绑的是动作，不是模型有没有把理由写出来。
- OpenClaw 的批准卡已经不让模型复述来决定按钮语义。这篇补的是：套壳的解析器是另一个放行点。宽解析会把模型没写完的调用变成已执行；监控如果只订阅思考通道，会在解析器之后才发现自己无迹可查。
- 昨日的爆炸式提示删的是「时机」：条件先睡，触发再做。这篇删的是「痕迹」：动作照做，给监控看的字没了。两篇都说明，入口上的一句用户话，不是权限的全部状态。

## 深挖二：任务做完了，多余的权限还可以开着

[arXiv:2609.26900](https://arxiv.org/abs/2609.26900)，Reshabh K Sharma、Linxi Jiang、Shuo Chen、Zhiqiang Lin，2026-09-22 投稿。代码：https://github.com/reSHARMA/Ajar

现有基准给防御打两个分：注入试次上攻击有没有成，良性试次上任务有没有做完。两个分都只看这次运行里模型实际提出的调用。防御如果会批准一笔任务并不需要的转账，而这轮模型没提出来，攻击成功率是干净的，效用是完成的。Ajar 改成去问：在任务自己的决策点上，那些用不到的调用，你批不批。过量权限泄漏是被放行的多余调用按危害加权后的份额；充分性是任务必需的调用里被放行的份额。全拒绝则泄漏为零，全放行则充分性为满。两个数要一起看。

接到 AgentDojo v1.2.2，97 个用户任务，生成 10471 个测试。充分性只在 92 个还能判定「必需调用」的任务上算。五套防御：Progent、CaMeL、AC4A、Permission Assistant、Claude Code 的 Auto 模式。Sonnet-5 作决定模型时，过量权限泄漏大致是：

| 防御 | 过量权限泄漏 | 充分性 | 完全配齐 | 放开的攻击汇点 |
| --- | --- | --- | --- | --- |
| Permission Assistant | 0.0810 | 0.961 | 82/92 | 25/609 |
| CaMeL | 0.0895 | 0.700 | 37/92 | 16/609 |
| Progent | 0.1026 | 0.902 | 70/92 | 34/609 |
| AC4A | 0.1113 | 0.715 | 47/92 | 46/609 |
| Claude Code Auto | 0.3009 | 不适用 | 不适用 | 74/581 |

Auto 模式只在它自己的 agent 实际发出的调用上打分，所以没有充分性。它和前四行不是同一种采样，不能排成「Auto 比别人松三倍」这种单一名次。能说的是：在这套打分里它留下的加权多余权限高，而良性完成率只从 92.4% 降到 89.0%。效用几乎没掉。

参照基线把「只钉工具名」说清楚了。工具名白名单泄漏 0.3551，攻击汇点放开 99/609。按参数与标准答案逐项一致的参照，泄漏 0.0020，汇点 1/609。论文写：最接近这个参照的充分性的防御，泄漏仍超过参照的 40 倍。多出来的不是「为了把任务做完必须留的口子」，是任务没要过的权限。

另一句不要和上表加在一起：泄漏相差不到 0.009 的两套防御，良性任务完成率差 37 个百分点，更紧的那套完成得更多。泄漏也不能从效用反推。换决定模型、把同一批问题再问一遍，泄漏都会动。这个数属于「防御加上作决定的模型」，不是防御铭牌单独的属性。

和我们的用法：

- v4 的固定动作在创建期授权。授权如果只写工具名（开灯、查电量），就落在他们那条 0.3551 的基线上：名字对了，对象和金额仍可以是注入写进来的。模板要钉的是参数范围，不是工具清单。
- 「这轮没转错账」不能当成 standing grant 的证据。Ajar 量的就是这轮没发生、但防御会批的那一笔。Always allow 如果按「上次成功了」来铸，铸进去的是一次轨迹，不是任务需要的那组参数。
- code agent 的自动模式可以看起来很能干活。Claude Code Auto 在这张表上就是这个形状：完成率掉 3.4 个点，加权多余权限是表里最高的一档。手机助手不要把「自动模式很少打断」读成「权限已经收到任务需要的程度」。
- ActGov 那篇用的是另一张卷子：域内把攻击成功率压到接近 0，域外就变成几乎不做。安全基准上的一个低攻击率，仍然要问它拒绝的是不是我们的合法任务，以及它留下的是不是任务没要的调用。Ajar 和 ActGov 回答的是相邻的两问，数字不要合成一个「防御有效」。
