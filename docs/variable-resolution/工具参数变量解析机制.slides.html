工具参数变量解析机制方案

openClaw · 用 ${app.抖音.bundleName} 消除多余 loop 与标识符幻觉 · 工具零改动

${ app . 抖音 . bundleName }

namespace . entity . attribute 三段式；命名空间经 Resolver 注册表扩展（未来支持 contact / device / result）；转义字面量写 $${。

问题与约束

  • 两次 loop：模型须先调 getAllInstalledApps 查 bundleName，再调 forbidPermission(bundleName, 权限)
  • 幻觉风险：模型凭记忆填写 bundleName 可能编造（如 com.douyin.app）
  • 硬约束：工具不可修改；带 bundleName 的工具很多，无法逐个改造

目标

  • 正常路径 1 次 loop 完成调用
  • 工具零改动，同类工具自动全覆盖
  • 模型只表达"哪个应用"，真实标识符永远来自查表

核心组件：框架层 Pre-call 拦截器

# 工具分发统一入口，递归替换 args 中的 ${...}
RESOLVERS = {"app": AppResolver()}   # 新命名空间只需注册

class AppResolver:
    def resolve(self, entity, attr):
        canonical = alias_table.get(normalize(entity), entity)  # ① 同义词归一
        return static_table.get(canonical, {}).get(attr)        # ② 查静态表

# 解析失败 → 短路抛错，绝不把 ${...} 字面量透传给工具

两张表：静态表 {"抖音": {"bundleName": "com.ss.android.ugc.aweme"}}（高频应用）＋ 同义词表 {"douyin"→"抖音"}（查表前 normalize）。

执行路径 · 提示词分层 · 实现要点

三条执行路径

正常路径 · 1 次 loop
模型输出
${app.抖音.bundleName}→ 拦截器查表
同义词 + 静态表→ 替换真实值
com.ss.android...→ 执行工具
自愈路径 · 仍 1 次 loop（模型无感知）
解析失败→ 框架自调
getAllInstalledApps→ 增量更新缓存→ 重试命中→ 执行工具
兜底路径 · 2 次 loop（仅应用不存在 / 名字错误）
重试仍失败→ 已安装列表 + 错误
作为 tool result 返回→ 模型纠正应用名重试

提示词分层（两层都写，职责不同）

SystemPrompt
通用机制		 声明变量语法与 app 命名空间；约束"优先用变量、禁止凭记忆编造标识符"
Skill
具体用法		 落到具体工具参数 + few-shot：
forbidPermission(bundleName="${app.抖音.bundleName}", permission="麦克风")

实现注意点

  • 替换后校验参数 schema，避免类型静默出错
  • 自愈缓存为 session 级；静态表只放高频，长尾靠自愈补
  • 记录"原文 → 求值结果"日志，防禁错应用
  • Resolver 只读查表，不执行表达式，防提示注入
  • 扩展：${result.tool[0].x} 引用前序输出，进一步压缩 loop
◎

方案不变量：模型永远只表达"哪个应用"，真实标识符永远来自查表 —— 幻觉被结构性消除，绝大多数情况 loop 压到 1 次。
