90% 为什么可达（不激进）

结构性依据
Agent 输入输出比约 100:1，会话内第 2 次推理起历史前缀本应几乎全命中——排布正确后 90% 是自然结果，不是激进目标。
60% 的漏点
命中率被以下三处人为破坏：
① 动态 skill 进 system prompt每个 query 改写前缀最前部，其后缓存全量失效（主因） ② 历史压缩改写从远到近重写消息流前端，近似一次全量 miss ③ 路由分散 / 缓存逐出同会话请求散落多实例；容量不足时被逐出
L1 上下文排布
设计已有
静态前缀 + 动态内容出前缀（收益最大）：skill/检索/环境随消息流渐进进入，消息流只追加不修改；序列化确定性（键序固定、无随机 ID、时间戳最多到天）；显式缓存断点。业界：Anthropic cache_control、OpenAI/vLLM 自动前缀缓存的官方最佳实践
L2 缓存感知路由
第二主因
会话粘性 / prefix-aware 调度：同一会话固定路由到同一推理实例，本地 KV 才可复用；随机负载均衡会让排布收益归零。业界：vLLM production-stack、SGLang router 内置前缀感知调度
L3 容量与生命周期
解决留存
分层 KV 存储：GPU HBM → CPU 内存 → SSD 三级下沉，有效容量放大几个量级，解决会话间隔久被逐出的 miss；TTL/逐出策略按会话间隔分布调优。业界：vLLM+LMCache、Mooncake（Kimi）、DeepSeek 磁盘上下文缓存
L4 引擎侧进阶
按需选用
块级复用与架构优化：RadixAttention 前缀部分变化也能命中公共段；prefill/decode 分离部署降低 TTFT 抖动；KV 量化（FP8/INT4）与 MLA 小 KV 架构提升同容量留存。业界：SGLang、Mooncake 分离式架构、DeepSeek MLA
◎ 结论：先修 L1 排布 + L2 路由拿到 90%（排布正确后的自然结果），典型任务 13s → 9s；模型切换 ds-v4 以真实 trace 上"工具调用正确率 × 时延"评测为门槛（正确率下降会以多付 loop 轮数反噬），通过后再降到 ≈7s。
