时延方程与逐项优化方案

按第 1 页时延构成逐项展开 · 收益为估算值，待埋点校准
T ≈ k × TSkillLoad + Σi=1..M ( T推理,i + T执行,i ) + TTFTFinal

与第 1 页三阶段一一对应：k = SkillLoad 次数（0~3）、M = loop 轮数（1~3）、Final 只计首 token。k 与 M 是乘数，其余是加数。

SkillLoad 次数 k
现状 0~3 次 × 2s+/次
预加载压到 0：检索高置信时框架预取正文、随当轮 query 注入（不进 system prompt，不破坏缓存）；skill 索引常驻稳定前缀，模型一次 load 对，消掉 search 与重载。
−2~6sk → 0
推理 · 首 token
1.3s × 每次推理，全链路 2~7 次
KV cache 排布：动态内容（skill 等）移出 system prompt、消息流只追加不修改，前缀命中后首 token 可望降到数百 ms——每次推理都受益，收益随次数放大。
−3~7s全局，第一梯队
推理 · 增量生成
均值 35tk ≈1.1s；长尾 300tk → 9s
长尾削峰：变量方案 ${app.抖音.bundleName} / 短句柄 f1 替代长路径与长标识符，框架拦截器查表还原——顺带结构性消除标识符幻觉（联动减 M）。
−8s仅命中长尾该轮
工具执行（含安全校验）
校验 0.5s + 执行 0.5~2s，× M 轮
校验分级 + 并行：只读/幂等工具免同步校验（改异步审计），高危保留；参数在输出流中完整出现即开始校验，藏进解码时间；结果缓存复用。长耗时工具异步化（任务句柄）。
−0.5~1.5s纯框架改动，确定性
Loop 轮数 M
现状 1~3 轮 × 3.4~4.9s/轮
减轮数：消幻觉（封闭词表选名 + 错误信息自带纠错线索，纠错一次到位）；高频序列合并为复合工具 / 批量参数；并行工具调用（一次输出多个独立调用、框架并发执行）。
−3.4~4.9s每减一轮，单位收益最高
整体架构（长期）
现状：高频简单任务也走全链路
快慢双系统：高频单意图任务路由到小模型 function call（快系统），慢系统处理长尾并沉淀成功轨迹作为快系统训练数据（数据飞轮）；失败回退慢系统，路由阈值保守。
