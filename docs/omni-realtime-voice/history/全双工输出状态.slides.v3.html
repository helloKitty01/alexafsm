议题 1HOLDING → SPEAKING 续说的时延归属

转换 ⑥ 写"tool_done → 续说（经 PREPARING 语义但不换态）"。但 tool_done 之后还有生成 + TTS 首帧的时延——这段超了 T1 怎么办？计时器重置，还是承认 HOLDING 里有个 resume‑preparing 子段？（P10 左）

议题 2REPAIR / BACKCHANNEL 的存在理由不是播放事实

两者期间系统都在出声，按"锚定播放事实"就是 SPEAKING；它们的特殊性全在 floor 语义与记录属性。要不要重构为"播放 3 态 × floor × 记录属性"的正交分解？（P10 中）

议题 3T1 filler 出声后还算 PREPARING 吗

C2 说"超 T1 出声占位是 PREPARING 的 filler 子阶段"——但 filler 一出声就有 playout_started，按锚定原则应转 SPEAKING。"filler 子阶段"与方法论自相矛盾，严格轨迹应为 PRE→SPK(filler)→HOL→SPK，与 D6 同构。（P10 右）

共同根源："锚定播放事实"与"具名状态"两条原则打架时听谁的——议题 3 最轻、议题 2 最重

议题 1HOL→SPK 续说时延

问题：D6 里 tool_done 后还要"结果 → 生成 → TTS 首帧"，这段时延算谁的？超了阈值出什么填充？

方案做法代价
A 计时器重置HOL 的 T1/T2 在 tool_done 时重置，续说超时走 HOL 同款填充无新节点；填充话术要区分"还在查" vs "在组织语言"
B 子段建模HOL 内加 resume‑preparing 子段，复用 PRE 的填充配置状态图膨胀，违背三分类原则
倾向 A：计时器重置 + 事件 resume_pending 供日志观测；节点数不变。

议题 2REPAIR / BCK 的存在理由

问题：两者期间都在出声，播放事实上就是 SPEAKING；差异全在 floor 与记录语义。P6 覆盖矩阵显示 BCK/REP/MUT 各仅 1 个场景支撑。

方案做法代价
A 保留具名态维持 6+3+2；BCK/REP 定义为"出声的非 SPEAKING 态"与锚定原则有张力，需在文档里明说例外
B 正交分解播放 3 态（静默/出声/停播中）× floor × 记录属性（主干/元对话/附和），BCK = 出声∧floor不转移∧附和，REP = 出声∧元对话推导更干净、UI/产品文档引用不直观，迁移成本
建议折中：对外接口保留具名态（可读性），内部实现按正交分解推导，具名态是分解结果的别名——两层各取所长。

议题 3T1 filler 出声归属

问题：C2「PRE 的 filler 子阶段」违反播放锚定——filler 一出声就有 playout_started。严格轨迹：

PRE ─T1→ SPK(filler) → HOL → SPK(实质)

与 C4 / D5 / D6 全部收敛为同一个 SPK→HOL→SPK 模式。

方案做法
A 遵守锚定filler 出声即 SPK，加内容属性 speech_kind = filler / substantive 区分字幕与记录处理
B 保留子阶段PRE 允许出声——锚定原则要开口子，状态含义变模糊
倾向 A：状态照播放事实走，"说的是不是实质内容"用属性表达；Agora 三时钟（应答起点 / 实质起点 / 完成）恰好需要这个属性来度量。
