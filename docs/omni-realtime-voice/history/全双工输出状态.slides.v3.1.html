Three Design Principles (三条设计原则)

These keep the state machine small, verifiable and stable as features are added (保证状态机小、可验证、可扩展)

P1Anchor states on what the user hears (以用户听到的为准)

SPEAKING begins when the first audio frame enters the playout channel, not when the model starts generating. Subtitles follow playback progress. After an interruption, conversation history is truncated to the millisecond the user actually heard.

Verified in practice: LiveKit Agents × OpenAI Realtime does exactly this (truncate by played milliseconds). Anchoring on generation progress mis-aligns subtitles and truncation. (LiveKit 源码验证)

P2Latency is a timer, not a state (时延不是状态)

Whether the system is generating, calling a tool or waiting for a large model, it is simply PREPARING or HOLDING for longer. Inside those states three thresholds shape the experience: T0 ≈ 0.5 s silent and unnoticed · T1 ≈ 1.5 s play a filler ("let me check") · T2 ≈ 8 s apologise and fall back.

Result: continuous latency becomes three designable segments; thresholds are configured per state and tuned from interruption and abandonment rates. (三档阈值按状态分别配置)

P3Tools and delegation add no states (工具与委托不建态)

The interaction layer cares about two things only: who holds the floor and what is in the user's ear. A running tool is PREPARING if nothing was said yet, HOLDING if the system announced it. Tool start / done / failed are events, not nodes. Delegation to a large model is identical, plus one step: the result is spoken on its behalf by the full-duplex model.

Payoff: retrieval, device control, any future async action — the diagram does not grow. (异步动作再多，节点数不变)
One classification rule underneath all three: only interaction states become nodes. Judgement windows (short, timed, collapse to a state) live on edges; decision events (instantaneous) are edge labels. Most state diagrams explode because windows and events were drawn as nodes. (三分类：交互态 / 判定窗口 / 决策事件——只有交互态画成节点)

P0 Nine Must-Have Scenarios (九个必做场景)

The minimum viable loop. Two of them are make-or-break (red). (最小可用闭环，红框为命门)

A · Opening2 (开场)

  • A1 Session start. User puts on earbuds and hears "I'm here" within 1 s; the half-sentence spoken during warm-up is buffered, not lost. (1 秒内应答，不丢先说的半句)
  • A2 Both silent. Nobody speaks for 5 s after opening; the system stays quiet, does not nag. (安静不催促)

B · Listening3 (听用户说)

  • B1 Onset confirmation. A 0.3 s cough is not speech; "Oh, by the way…" is confirmed within ~200 ms — and this is where the external ASR trigger fires. (起音确认，外挂 ASR 触发点)
  • B3 Pause ≠ finished. "Book me a ticket… (1.2 s thinking about the date) …to Shanghai on Friday." The system must not answer at the breath. Judged by silence length AND semantic completeness together. (换气处绝不抢答 — 全场最重要)
  • B4 Endpoint. 600 ms of silence and a complete utterance → committed, floor passes to the system. (端点确认，话轮交接)

C + D · Answering4 (系统回答)

  • C1 Fast path. "What time is it?" → "Ten twenty" within 0.4 s; everything in between is invisible to the user. (半秒内出声，用户无感)
  • D1 Subtitles follow playback. On-screen text tracks what has actually been played, not what has been generated. (字幕跟播放进度)
  • D3 Real interruption. Reading the news, user says "Stop — international instead." System is silent within 300 ms, and history keeps only the half-sentence the user actually heard. (300 毫秒闭嘴，只留听到的半句 — 打断体验底线)
  • D9 Ask and hold. "Which day do you want to leave?" — after speaking, the system does not release the floor; it is marked expecting an answer. (提问后不撒手)
If B3 and D3 fail, nothing else matters. One is the cost of cutting the user off; the other is the cost of not stopping when told to. (这两个做砸了，其他都白搭)

D4False interruption (假打断)

P2 Ten Deliberately Deferred Scenarios (十个有意暂缓的场景)

Deferred for one of two reasons: the industry cannot do it well yet, or it is low-frequency. Deferring is a decision, not an omission. (业界做不好 / 低频；暂缓是决策不是遗漏)

Capability-limited4 (受模型能力限制)

  • B2 System backchannel. "Mm, got it" at a semantic boundary while the user talks for 20 s. Instruct-FD shows industry compliance of 0–50 % — the weakest capability across all systems. (系统主动附和，全行业最弱)
  • B7 Multi-party. Two people chatting in a car with commands mixed in; "Were you talking to me?" when unsure. Needs external ASR and speaker identity. (多人在场，依赖声纹)
  • D5 Speak while calling. "I'll read the news while checking traffic" — tool call and audio in the same frame (model requirement R1). (边说边调，依赖模型能力)
  • C7 Speculative pre-generation. Generate during the user's 1.2 s pause; play instantly on commit. Negative latency; correctness depends on B3 being solid first. (预提交，先把 B3 做稳)

Low-frequency6 (低频)

  • A3 Away and check-in. 15 s silence → away; 30 s later a soft "Still there?" (离开与关怀重启)
  • A4 System-initiated. 19:00 reminder fires: "Time to call your mother." Gated by the interruption manager. (主动提醒)
  • B6 Very long speech. 60 s without an endpoint → forced segmentation, incremental understanding. (超长说话强制分段)
  • X2 External event mid-speech. Reminder arrives during navigation → wait for the sentence boundary, then insert. (等句尾再插)
  • X3 System interrupts the user. Gas alarm while the user is talking → hard interjection. Disabled by default; alerts only. (硬插话，默认禁用)
  • X4 Non-voice input in parallel. User taps "Cancel" on screen mid-conversation; must not corrupt floor semantics. (屏幕操作并行)
Completeness check: all 34 scenarios are expressible with the 11 system states, 4 user states, 4 judgement windows, the event vocabulary and floor — no additional state was needed; and every state is exercised by at least one scenario — no orphan state. (双向覆盖检查：场景无遗漏、状态无孤儿)

The Hardest Judgement: Three-Way Interruption (最难的判定：打断三分)

The user makes a sound while the system is speaking. One window, three outcomes — and the strategy is a product choice. (一个窗口三种出口，策略是产品选择)

Interruption windowspeech_started while SPEAKING (打断判定窗)

Real interruption → YIELDING (真打断 → 让出)

"Stop — international instead." Contains a new intent. Stop playback ≤ 300 ms, truncate history to what was heard, open a new turn. Metric: stop latency.

Backchannel → keep talking (附和 → 继续)

"Mm-hmm", "right", "okay". Short, no new intent. Floor unchanged, no new turn, speech continues uninterrupted.

Noise / not for me → pause, then resume (噪声 → 暂停待判 → 恢复)

A bang, background voices, someone else in the room. Pause up to 0.5 s; if no valid transcript, resume from the pause point. Metric: response latency.

Strategy is a parameter (策略取向可配置)

Repair-first (快让出)Continuity-first (重连贯)
BiasYield quickly; accept some false takeoversKeep talking; accept slower yields
FitsCustomer service, task executionCompanionship, tutoring, reading aloud
EvidenceGPT-4o Realtime: responds to real interruptions 0.78, but also to bystanders 0.91Gemini / Sonic: high resume, lower interruption response

Full-Duplex-Bench v1.5: no strategy wins all four overlap scenarios. The window's thresholds must be a configurable profile. (没有全局最优，阈值做成 profile)

Where the industry stands: GPT-Live judges this inside the model (yields ~500 ms slower, but rejected 30 / 30 background voices in Agora's test). Second-generation APIs (OpenAI / Qwen Realtime) still treat any user speech as an interruption unless configured. Our design keeps the judgement explicit so it can move from system heuristics to the model over time. (判定显式化，产地可从系统迁移到模型)

Latency, Tools and Delegation Inside PREPARING / HOLDING (时延、工具与委托的容器)

Two waiting states, one before the first sound and one after; every async action lives inside them as events. (出声前等 vs 出声后等)

Latency tiersfrom the user's last word to the system's first frame (时延三档)

≤ T0 (~0.5 s)Silent. Unnoticed. Fast path (C1). 无感
> T1 (~1.5 s)Play a filler: "Hmm, let me check…" (C2 / C3 / C4). 出垫话
> T2 (~8 s)Fallback: apologise, degrade, or convert to an async task (C6 / D8). 兜底
playout_startedFirst frame → SPEAKING 首帧

Thresholds are configured separately for PREPARING and HOLDING, by scenario type (chat / retrieval / delegation), and tuned from interruption and abandonment rates after launch. (按状态、按场景类型分别配置)

PREPARING vs HOLDINGsame wait, two experiences (同是等待，两种体验)

PREPARING (备答)HOLDING (持轮等待)
DefinitionFloor taken, nothing audible yetHas spoken, keeps the floor, waiting
TypicalGenerating; tool before speaking; delegation"Let me check" then waiting; in-turn pause
Filler goalBreak the silenceMaintain presence — do not sound disconnected
If user speaksMerge / discard / keep (C5)Cancel / hurry / unrelated (D7)

Tools & delegationevents, not states (工具与委托是事件)

  • invoke_tool (kind = tool / escalate) → tool_done / tool_failed drive entry and exit of PREPARING or HOLDING. They never change the state themselves.
  • Delegation to a large model is structurally the same as a tool, plus one step: the result text is voiced by the full-duplex model ("spoken on its behalf"). The large model is invisible to the interaction layer. (大模型对交互层透明)
  • Every "announce → wait → continue" case — filler (C2), delegation (C4), speak-while-calling (D5), "let me check" (D6) — collapses to the same pattern: SPEAKING → HOLDING → SPEAKING. (全部收敛为同一模式)
Mirror of GPT-Live's split: the voice model decides whether to speak; the application server owns delegation, turn splitting and persistence — exactly our dual-brain architecture. (与双脑架构分工一致)

Four-Layer Protocol and Control-Plane Vocabulary (四层协议与控制面词表)

Each layer depends only on the one below. States are a read-only projection computed from events. (状态是事件的只读投影)

④ Interaction states (交互状态层) — 11 system states, 4 user states, floor. Single writer (the orchestrator); UI and product docs read from here.
↑ pure-function derivation (acceptance criterion)
③ Events = control-plane vocabulary (事件层)
Perception: speech_started (prearm / confirmed) · speech_stopped · speech_cancelled · playout_started · playout_done · tool_done / failed · away · session close / error
Decision: committed · respond / reject / defer · invoke_tool · interrupt / pause / resume · backchannel · filler (T1) · timeout (T2) · floor transfer
Outbound: asr_prearm / asr_start / asr_stop / asr_cancel
↑ windows collapse into events
② Judgement windows (判定窗口层) — onset confirmation endpoint (VAD hangover + semantics) interruption pause-and-judge + latency tiers T0 / T1 / T2. Timers and classifiers in the orchestrator.
↑ raw signals enter windows
① Signal sources (信号源层) — device VAD energy · model control tokens (turn / intent heads) · playback callbacks (first frame / done) · tool and large-model callbacks · external events (reminders, alerts).

External ASR triggernew requirement (外挂 ASR 外部标识)

The system must emit a signal that starts an external ASR (which also serves other purposes). It hangs on the entry and exit edges of the judgement windows — proof that layer ② must be explicit.

asr_prearmSuspected onset → ASR warms up its stream, absorbing start-up delay
asr_startOnset confirmed → segment_id + timestamp back-dated to the onset, not the confirmation
asr_stopEndpoint committed → end timestamp
asr_cancelWindow judged false alarm → withdraw prearm
Generalised as a segment-level co-processing trigger: payload = segment id + time window + audio route. ASR is the first subscriber; rejection review, compliance recording and hot-word detection reuse the same signals. Producer may later move from system VAD to model tokens — protocol unchanged. (泛化为 segment 级协处理触发，产地可迁移)

Five requirements on the model (对模型输出的五条需求)

  • R1 Tool-call fields and audio in the same frame (speak while calling).
  • R2 Accept async results injected in any state; the model chooses when to continue.
  • R3 An "escalate" control signal; large-model text voiced on its behalf.
  • R4 Fine-grained intent fields: voice_intent (silence / speak / backchannel / yield), floor_intent (keep / release / take), rejection — beyond the industry's binary listen / speak.
  • R5 Shared time base: every output carries segment_id + intra-frame offset.
