关键抽象不是第三套 Session 类型

  • Realtime 实现 llm.RealtimeModel 接口，塞进 llm=。
  • AgentSession 发现类型后走 _rt_session 双向音频，否则走 STT→LLM→TTS。
  • SpeechHandle 队列、工具、多 Agent 交接，三条管道共用。
  • 半级联是对 OpenAI 已知坑的绕过：灌长历史后模型爱改用纯文本回答。

和三代架构对齐

LiveKit 今天交付的是第二代 S2S 的产品化，外加可插拔第一代级联。

没有第三代全双工模型，也没有 GPT‑Live 的说/想双时钟。OpenAI 在这里出现四次（Realtime / Chat LLM / STT / TTS），不要混成一条管道。

打断 = cancel + 按播放头 truncate

这是第二代 S2S 能做“假全双工”的关键
模型仍是轮次制，系统层把没说完的尾巴从上下文剪掉

1. speech_startedOpenAI 服务端 VAD
或本地 VAD（若模型 VAD 已关）

2. interrupt()response.cancel
停当前生成，不改历史

audio_end_ms = 用户听到哪
→
4. listeningagent_state 切回
下一轮上下文已对齐耳朵

细节

  • audio_end_ms == 0 则直接 item.delete。
  • 半级联只有 text：改本地 chat_ctx 再同步回去。
  • 不可打断时 discard_audio_if_uninterruptible 仍生效，丢掉缓冲，避免回声堆积。

不要配一半

硬错误：服务端 VAD 开着时 interruption.enabled=False 直接 ValueError。

create_response=False 但 interrupt_response 仍为真会警告：两边都会取消响应，LiveKit 以为自己在管，OpenAI 也在管。

轮次检测：必须只有一个主人

这是整套集成最值得抄的一条
允许两种实现，同一时刻只许一个做主

默认 · 模型做主semantic_vad

  • Agent 原样转发音频，不在本地做 EOT。
  • speech_started → 框架立刻 interrupt()。
  • InterruptionOptions 几乎全部忽略。
  • server_vad 可调 threshold / padding / silence（电话示例 0.7 / 400 ms）。
  • semantic_vad.eagerness：low / medium / high。

备选 · LiveKit 做主TurnDetector

  • 必须 RealtimeModel(turn_detection=None)。
  • 文本端点模型跑在转写空间；Realtime 用户转写往往晚于开口。
  • 所以官方示例强制并行 Deepgram STT：音频复制进两条路径。
  • 源码守卫：capabilities.turn_detection 为真则 _interrupt_by_audio_activity 直接 return。
级联上的 TurnHandlingOptions 默认不作用于 Realtime 服务端 VAD 路径。自适应打断、假打断恢复、抢跑生成、动态 endpointing —— 都是客户端策略。Realtime 路径刻意不假装拥有它们。

对照 10 态：LiveKit 实现的是系统事件层

公开状态机比 06 章粗得多 · 打断是边沿事件，不是一等状态

LISTENING有 · agent_state=listening
HOLDING无 · 默认交给 eagerness
THINKING半有 · 含“还没出声”；工具无独立态
BACKCHANNELRealtime 默认无 · 级联 adaptive 才有意图
SPEAKING有 · 首帧回调才进入
YIELDING事件不是状态 · cancel+truncate
RESUMING级联有 · 服务端 VAD 下被忽略
INTERJECTING无 · 只有用户打断模型
MUTED弱 · away / 关麦 / 丢帧
REPAIR无 · 靠 prompt / 工具

阴影态

  • 委托中：工具执行；max_tool_steps=3 用尽再要一轮口头总结。
  • 切换中：handoff 时 _scheduling_paused，新 realtime generation 被丢掉。
  • 分轮暂定：无 GPT‑Live 双视图；chat_ctx 按 item 追加。
落点

10 态如果要长在这种框架上，不能指望 agent_state 变成十个枚举。要在 TurnHandlingOptions + 模型 turn_detection + 自管 SpeechHandle 上长出来。

做对了什么，和 GPT‑Live / Instruct‑FD 差在哪

第二代 S2S 的产品外壳 · 不是第三代全双工

可直接借鉴

  • 单一 Session，三种管道是插件不是产品分叉。
  • Turn taking 所有权显式互斥；关打断是硬错误，不是静默失效。
  • 打断按已播放毫秒 truncate，上下文与耳朵对齐。
  • 重连当一等操作：重放配置，丢弃 in-flight，item_id 随连接丢弃。
  • capabilities 比特：新提供商实现同一接口，编排不用改。
  • 假打断 / 抢跑 / 动态 endpointing 做在级联侧 —— 清楚这些是客户端策略。

没做，也不该误会他们做了

  • 不是全双工：输出仍是一轮 response；重叠只来自 barge-in。
  • 没有说/想分离：thinking = 音频还没到；工具会卡住或另起 response。
  • 没有 Instruct‑FD 输出策略指令：可控的是 VAD 参数，不是“现在允许附和”。
  • 字幕天然滞后；需要实时转写就加独立 STT。
  • 纯 Realtime 不能 say(精确稿件)，要念稿走半级联。
  • 插件假设一次 response 一条 message。

对我们的建议接同样的栈时

叠在 05 / 06 章之上 · 专门针对 LiveKit 这类编排层接 OpenAI Realtime

1先选管道，再谈状态

还在 Realtime API 这一代上，产品状态机就按 listening / thinking / speaking + 打断边沿。BACKCHANNEL / INTERJECTING / RESUMING 能做多少，取决于有没有把 turn taking 从模型手里拿回来。

2默认把 VAD 留给模型

与 LiveKit 官方一致。只有需要自适应打断、假打断恢复、或更好的语义 EOT 时，才 turn_detection=None + 并行 STT。

3禁止双检测器

配置校验做成启动失败，不要运行期互抢。半开的 create_response / interrupt_response 同样禁止。

4truncate 按播放头

用户听到哪，历史就剪到哪。不要按生成头或整句 item 删除，否则下一轮会引用没说完的句子。

5半级联当逃逸舱

品牌音色和念稿用它。不要和“全双工”混谈：它解决输出可控，代价是延迟回到级联量级。

6工具离开活跃音频路径

max_tool_steps 只是止血。要对齐 GPT‑Live，在编排之外加委托会话（第二时钟），前台只说“我去查”。

一句话：LiveKit × OpenAI = WebRTC ↔ Realtime WS 适配器 + 一条可切换主人的轮次状态机。所谓自动处理打断，是 speech_started → response.cancel → item.truncate，不是全双工输出状态。
