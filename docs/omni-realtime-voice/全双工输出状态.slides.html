层一：会话现象——人类是怎么组织轮次的

Sacks, Schegloff & Jefferson 1974 · Skantze, Computer Speech & Language 2021 · Voice Activity Projection / TurnGPT

1974 最简系统学三个动词

  • TCU：构成轮次的语言单元（词 / 短语 / 从句 / 句）。
  • TRP：可能换人的位置，与句法、韵律、语义边界重合。
  • 在 TRP 上只有三种动作：hold 持有 / yield 让出 / abandon 放弃。
  • 系统目标是最小化间隙与重叠，但重叠占真实口语 10–20% 时间（Moshi 引 Çetin & Shriberg 2006）——重叠是常态。
洞察：所有工程状态最终都要映射回 hold / yield / abandon 三个动词，否则就是在发明没有语言学依据的状态。

多模态线索人类靠什么判断 TRP

线索hold 信号yield 信号
语言句法未闭合、"然后…"句法完整、问句
韵律平调 / 升调、拉长音降调、音量下降
呼吸吸气准备继续呼气结束
注视 / 手势看向别处、手势未收回看对方、手势收回

纯音频系统只能拿到前三类——这是"是对我说的吗"（设备指向性）在音频系统里格外难的原因。

Skantze 2021 综述对话系统需要建模的四类事件

End‑of‑turn 检测轮内停顿（hold）vs 轮间停顿（shift）在声学上不可分，必须用连续预测
用户打断处理停、截断、回应新意图
轮次线索生成系统自己发出 hold / yield 信号（韵律、填充语）
多方交互谁在对我说话

VAP / TurnGPT最小公分母：四类事件

事件定义对系统输出的含义
turn‑yielding（shift）说话人让出发言权系统可以开口
turn‑holding（hold）停顿但仍持有系统必须继续沉默
backchannel不夺发言权的短反馈，多发生在重叠里独立状态：既不是"说"也不是"沉默"
interruption夺取发言权系统要么让出，要么主动发起
洞察：VAP 直接预测未来 2 s 双方语音活动分布，事件是派生的；TurnGPT 从文本预测轮次完成概率。韵律 + 语义两路并用是学界共识——单靠静音阈值（VAD）只是最粗的替代物。

洞察四条设计脉络

  • "要不要说"与"说什么"是两步。 Moshi 把 EPAD（结束填充）与下一个词分开预测，论文明说是"拆成两步"；BayLing 用 [ASSISTANT] 单独标记"开口"事件。
  • 沉默不是一种状态，至少三种。 BayLing 区分 [SILENCE]（没轮到我）与 [PAD]（文本完、语音在播）；Chronological Thinking 把沉默变成思考期。外观相同、内部不同。
  • 打断判定在迁移：声学触发（Freeze‑Omni 靠 VAD + 分类头）→ 语义判定（Unit‑agent 在 speak 态区分附和 vs 真打断）→ 模型内生（GPT‑Live：让出慢 ~500 ms，但 30/30 拒绝背景人声）。
  • 显式 token 的代价是极度不平衡。 Moshi 报告 PAD 占英语对话 65%；BayLing 指出 [SILENCE] 占绝对多数、[ASSISTANT] 每轮一次，必须逐 token 加权 + DPO 单独调"时机"。
粒度是架构参数：Moshi 80 ms 帧 → 160 ms 理论时延；BayLing 0.8 s 块——论文承认块太小则轮次抖动、太大则最小时延超阈值。状态粒度直接决定最小响应时延。
Qwen 系的位置：Qwen3‑Omni 的 Thinker‑Talker 解决的是 THINKING 态首包时延（单路 234 ms，6 并发 1172 ms），不管发言权；原生全双工是 Fun‑Audio‑Chat‑Duplex——自报 turn‑taking 100%，Instruct‑FD 却只有 46.2%（Backchannel 0%、Acknowledge 5.4%）："轮次成功率"不够，必须测状态判定本身。

洞察两种策略取向，没有全局最优

  • repair‑first（快速让出）：GPT‑4o —— 打断响应最好，但对旁人说话、背景人声也 0.9+ 误接管。

时序一个全双工系统至少测五个时间点

  • 用户停 → 系统首音（FDB 响应时延）
  • 重叠开始 → 系统停嘴（stop latency）
  • 重叠结束 → 系统再开口（response latency）
  • 首音 → 实质内容；实质 → 说完（Agora 三时钟）

GPT‑Live 实测：首音仅快 205 ms，但抖动降 5 倍（σ 489→104 ms）；10% 丢包 +314 ms vs AVM +2448 ms。

Instruct‑FD：状态不仅要"有"，还要"可被指令控制"

Tang et al., Boson AI, arXiv 2607.20460（2026）· 912 用例 × 29 场景 × 6 系统 · WebRTC 多轮编排器 + LLM 裁判（88.9% 与人一致）

按"谁持有发言权"划分五条可指令化的轮次策略

Proactive · 用户在说，模型决定是否介入
Listen沉默，不附和不插话，等清晰结束
Backchannel在触发点短应答，不夺发言权
Interrupt触发（矛盾 / 安全错误）时立即夺取发言权
Responsive · 模型在说，用户重叠时如何反应
Continue用户"嗯嗯"视为支持，不让出
Acknowledge用户纠正 / 加约束 / 转向 → 立即承接并调整

同一段对话配多条不同指令 → 隔离"指令遵循"与"对话内容"；对比无指令基线得 ΔIAS（指令敏感度）。人类在同一用例上准确率 89.6%，说明场景自然、指令可执行。

29 个场景其实是一张精细的"触发词典"

Proactive 触发：序列信息口述停顿、"你懂吗？"注意力确认、子句边界、填充词停顿、情感停顿、显式持有发言权信号、事实错误、犹豫、安全错误、自我矛盾、找词、认知停顿、投射停顿、自问自答。

Responsive 重叠：确认 / 认同 / 笑 / 理解 / 继续者（→ Continue）；"等一下""再说一遍""我没跟上""还在吗？"、加约束、转向、缩范围、跳过基础、要摘要、加个人背景（→ Acknowledge）。

洞察四个系统性失败模式

  • 语义合规 ≠ 时序合规。 模型说了对的话，但在错的时刻——该在用户说话中附和，却等用户说完才"嗯"。这解释了为什么听起来配合，却在 Backchannel / Interrupt 上近乎全败。
  • Continue‑default 坍缩。 Fun‑Audio‑Chat / MiniCPM‑o Continue ≈ 100%，Acknowledge ≈ 5%——分不清"用户继续者"与"用户纠正"，一律硬讲下去。
  • 触发层级。 Gemini 对显式触发（"你懂吗？" 100%、持有信号 91.7%）能附和，对隐式触发（子句边界 0%、情感停顿 16.7%）失灵。
  • 指令可能反而破坏。 Fun‑Audio‑Chat 加指令后 Acknowledge 显著下降（−11.2%）；PersonaPlex 比 Moshi 基线好一倍，但 ΔIAS 仍小——基线好 ≠ 可控。
核心判断：主动性状态（Backchannel / Interrupt）是全行业短板——最好的系统 Interrupt 也只有 11.7%。而这恰是我们双脑架构里"打扰管理器 → 主动播报"依赖的能力。

⑤ 该沉默多久THINKING 时长上限 后台进度、已等待时长 沉默是语音里最差的失败态；委托撑不住任意慢的响应 填充语 + 三时钟预算；预建后台会话 + 亲和 + prompt caching；超时兜底话术
洞察 A：①②③ 是响应性判定，业界已有多条可用路线；④⑤ 是主动性判定，学术基线接近于零，产品上只有 GPT‑Live 声称做到、且未公开机制。
洞察 B：Instruct‑FD 证明同一段对话在不同指令下应有不同正确状态——转移守卫不能是常量，必须是可被策略参数化的函数。

总结分析：六条跨来源的结论

从 1974 年的会话分析到 2026 年的 Instruct‑FD，全双工"输出状态"这件事的共识与断层

1状态是一等设计对象，不是 VAD 的副产品

轮次制只有"沉默 / 说"两态；全双工把"要不要出声"变成每秒多次的决策。Moshi 的 EPAD、BayLing 的 [ASSISTANT]、GPT‑Live 的五动作，都把动作决策与内容生成拆成两步。

依据 Moshi §3.4.4（EPAD 拆两步）· BayLing‑Duplex §2.1 · GPT‑Live 公告"many times per second"

2沉默至少三种，附和必须单列

听 / 播放尾音 / 思考——外观相同、内部不同（BayLing [SILENCE] vs [PAD]，Chronological Thinking）。backchannel 发生在重叠里、不夺发言权，是独立状态而非"短的说话"。

依据 BayLing 四 token 定义 · StepFun Chronological Thinking · VAP backchannel 事件 · FDB v1.0 backchanneling 维度

3响应性成熟，主动性是全行业断层

Continue 40–97.5%、Acknowledge 最高 86.3%；而 Backchannel 0–50%、Interrupt 1.7–11.7%（Instruct‑FD）。语义合规常伴随时序不合规——"说了对的话，在错的时刻"。Qwen 系 Fun‑Audio‑Chat‑Duplex 自报 turn‑taking 100% 却 IAS 46.2%：轮次成功率 ≠ 状态判定正确。

依据 Instruct‑FD Table 3 / §4 · Gemini 隐式触发 0% · Fun‑Audio‑Chat 技术报告 Table 7 vs Instruct‑FD Table 3

4没有全局最优策略，状态阈值是产品决策

repair‑first（GPT‑4o：打断响应好、误接管高）vs continuity‑first（Sonic / Gemini：抗干扰好、打断响应差）。Instruct‑FD 进一步证明同一对话在不同指令下正确状态不同——转移守卫必须可参数化。

依据 FDB v1.5 行为表（GPT‑4o 旁人 Respond 0.91 vs Sonic Resume 0.90）· Instruct‑FD 同对话多指令设计

5显式还是隐式：可控性与数据成本的权衡

隐式涌现（Moshi / SyncLLM）需百万小时双通道数据、可控性差；显式 token / 分类头（Freeze‑Omni / BayLing）40 万样本即可、可加权可 DPO，但面对极度类别不平衡（PAD 65%）与合成数据偏差。PersonaPlex vs Moshi 说明训练数据比架构更能改善基线，但仍不带来可控性。

依据 Moshi PAD 65% · BayLing ωsil/ωrole 加权 + DPO · Instruct‑FD PersonaPlex 47.0% vs Moshi 21.1%，ΔIAS 仍小

6状态归属正在从外部迁回模型，系统层仍需一组"影子状态"

第二代 API 由外部信号驱动（Instruct‑FD 因此排除 GPT‑Realtime）；第三代交回模型。但 GPT‑Live 工程文章表明系统层仍要维护委托中 / 切换中 / 分轮暂定等状态，且它们约束模型可做的动作。

依据 Instruct‑FD §3.1 排除 GPT‑Realtime 的理由 · OpenAI 工程文章：委托 / 切换 / 分轮暂定

一句话：全双工输出状态 = 按发言权归属分列的 10 态 + 五个可参数化的转移守卫 + 一组系统影子状态；其中主动性状态（附和 / 插话）的时序正确性是当前最大的技术缺口，也是评测应当最先覆盖的地方。

对我们的建议：把状态做成接口、把策略做成参数、把评测做在模型前

对接 phone‑assistant 双脑架构（前台 omni 全双工 + 后台深度大脑 + 打扰管理器）、latency / kv‑cache / reminder 讨论

1对外接口层一律显式，采用 10 态枚举

模型内部可隐式，但必须能可靠读出当前状态（如 BayLing 的文本通道 / Freeze‑Omni 的分类头）。状态转移事件（尤其 YIELDING / INTERJECTING）进入权威记录，供分轮器、分析与安全审计；reminder 注入点对齐到状态边界。

2状态归属：模型管"说不说"，编排层管"能不能"

模型决定 SPEAKING / BACKCHANNEL / YIELDING / RESUMING / HOLDING；编排层持有 MUTED、INTERJECTING 最终放行、THINKING 超时，并维护委托中 / 切换中 / 分轮暂定三个影子状态。INTERJECTING 的放行就是打扰管理器的 speak_now / speak_at_pause。

3转移守卫参数化：把"策略"做成可下发的指令

借 Instruct‑FD 的五策略（Listen / Backchannel / Interrupt / Continue / Acknowledge）作为策略 profile：客服 = repair‑first、陪伴 / 辅导 = continuity‑first。第二代路线上先落到 eagerness 类旋钮；第三代路线上作为 system instruction 条件化训练目标。

4评测集先于模型：FDB v1.0 + v1.5 + Instruct‑FD + 三时钟

四维度（停顿 / 附和 / 交接 / 打断）+ 四重叠（打断 / 附和 / 旁人 / 背景）+ 五策略指令遵循（IAS / ΔIAS）+ 五个时间点。重点补主动性场景（子句边界附和、事实错误插话），并加真实网络损伤。中文场景需自建（现有基准均为英文）。

5粒度与时延预算一起定

帧级（80 ms）vs 块级（数百 ms）决定最小响应时延与轮次抖动。建议：状态决策粒度 ≤ 200 ms，内容生成可更粗；THINKING 的填充语在首音时钟 < 1 s 内发出；后台大脑会话预建 + prefill（对应 GPT‑Live 委托预算）。

6路线选择：先第二代 + 显式状态，再演进第三代

短期：S2S 轮次制 + 语义 VAD + Easy Turn 式四态判定 + Flux 式投机开口，把 10 态接口与评测集先跑通。中期：Freeze‑Omni / BayLing 式显式 token 训练主动性状态（Backchannel / Interrupt），用 DPO 专调时机。长期：GPT‑Live API 落地后评估"前台接第三方全双工、后台自研"的边界。

最大风险：我们的双脑架构依赖前台"主动播报 / 插话"，而这正是业界 IAS 最低（≤ 11.7%）的能力。若不先在评测集上验证，打扰管理器的 speak_now 决策会落在一个模型做不到的动作上——要么做成"等用户停顿再说"（speak_at_pause 优先），要么专项训练。
下一步：① 定稿 10 态枚举与事件 schema；② 搭 FDB + Instruct‑FD 中文评测子集；③ 在现有 S2S 前台上实现 Easy Turn 四态 + 投机开口，跑出基线；④ 按基线决定主动性状态是训练还是绕开。
