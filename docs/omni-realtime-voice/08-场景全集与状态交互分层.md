# 08 场景全集与状态交互分层（统一状态模型 v2）

本章把 [06 章](./06-全双工输出状态盘点.md) 的"统一 10 态模型（讨论稿）"推进到 v2：
**从交互场景推导状态**（而非从直觉枚举），给出**完整的状态交互图及其四层分层**，
校订一份外部给出的事件词表，并落一个新需求——**外挂 ASR 的外部启动标识**。
v3.3 修订：用**状态 × 事件矩阵**穷举补入 8 个场景（34 → 42），新增第 10 节（矩阵）与第 11 节
（已识别缺口与决策 1–5）。v3.4 修订：C5 / D7 统一为"系统持轮时用户开口"三条不判意图的规则
（缺口 8）。配套幻灯片见 [全双工输出状态.slides.v3.4.html](./全双工输出状态.slides.v3.4.html)。

## 0. 结论摘要

1. **状态从场景来**：一轮交互切成 A 静默 / B 用户输入 / C 响应准备 / D 系统输出 五个阶段
   加 X 贯穿并发，共 **42 个场景**（每条带具体例子与状态轨迹）；按 **P0 最小可用闭环（10）/ P1 体验分水岭（22）/ P2 增强暂缓（10）**
   分级落地。场景里"系统必须在此刻做一个判定"的点才产生状态需求。场景完备性由
   第 10 节的**状态 × 事件矩阵**保证，v3.3 由矩阵补入 8 个场景（B10、D11–D14、X5–X7），
   **未新增任何状态**，只新增事件与守卫规则。
2. **三分类原则**：交互态（稳定、UI 可渲染）/ 判定窗口态（短暂、带计时器、结论出来就坍缩）/
   决策事件（瞬时、驱动转换）。状态图变复杂的根源就是把窗口和事件画成了节点。
3. **v1 → v2 的主要修订**：`THINKING/DELEGATING` 按"是否已出声"拆分——未出声更名
   **PREPARING**（话轮已接、还没开口，v1 的遗漏点：用户说完到系统首帧之间的时延都堆在这里），
   出声后的宣告等待并入 **HOLDING**；`RESUMING` 降级为 SPEAKING 上的瞬态自环；
   工具调用 / 委托大模型**不建交互态**，降级为决策事件。
4. **时延不是状态**：PREPARING / HOLDING 内部用 T0（无感）/ T1（出填充）/ T2（兜底）
   三阈值把连续时延切成可设计的体验分段。
5. **状态图分四层**：信号源 → 判定窗口 → 事件（控制面词表）→ 交互状态。
   外部给出的 7 项词表整体落在事件层，缺窗口层与状态层，且混入了一个状态（`listen`）。
6. **外挂 ASR 标识**挂在判定窗口的进出沿上：`asr_prearm / asr_start / asr_stop / asr_cancel`
   两段式信号（v3.3 补 `segment_merge` 处理端点撤回），并泛化为 segment 级外部协处理触发。
7. **五项待拍板决策**（第 11 节）：HOLDING 续说计时器、BACKCHANNEL / REPAIR 的具名与推导、
   T1 垫话出声归属、**端云时间基准（端侧上报 `playout_position`）**、**轮级时钟管 T2**。
   前三项来自 v3 校验，后两项来自 C4 × D3 链路走查。

## 1. 定义框架

### 1.1 三层定义（承接 06 章三层视角的工程化）

| 层 | 回答的问题 | 验收标准 |
| --- | --- | --- |
| 交互层 | 用户感知到系统在做什么 | 只描述可感知事实；状态锚定在播放事件与 VAD 事实上（LiveKit 的教训：`SPEAKING` 以首帧入播放通道为准，不以模型开始生成为准） |
| 模型输出字段层 | 模型每帧 / 每 chunk 输出什么 | 控制流 + 内容流；交互层状态可由字段 + 播放时间戳**纯函数推导**，不需要额外启发式 |
| 系统需求层 | 系统还额外要模型输出什么 | 工具 / 检索 / 委托大模型 / 外发标识所需的控制协议 |

### 1.2 三分类原则

| 类别 | 特征 | 在状态图里的画法 |
| --- | --- | --- |
| 交互态 | 稳定、UI 可渲染、可被产品文档引用 | 节点 |
| 判定窗口态 | 短暂、有超时、结论出来就坍缩到某个交互态 | 转换边上的"胶囊"标注，不占节点 |
| 决策事件 | 瞬时判定、驱动转换 | 边的标签 |

### 1.3 双通道输出协议（控制面 / 内容面）

```text
控制面：voice_intent / floor_intent / 打断与恢复 / 升级请求 / 外发标识（asr_*）
内容面：├─ 音频流（codec token）
        ├─ 文本流（转写 / 语义，超前音频）
        └─ 工具调用流（结构化参数）
```

硬约束：控制流与内容流**共享时间基准**（帧号 + `segment_id` + 毫秒偏移），
否则打断对账（truncate 到用户实际听到的位置）无法完成；控制信号放在**超前**的
流上，给系统留反应窗口。

## 2. 人机 vs 人人：六条差异及其逼出的机制

| # | 人人对话 | 人机对话 | 逼出的机制 |
| --- | --- | --- | --- |
| 1 | 没有"拒识"，受话人总有反馈 | 误唤醒、旁路收音、多人在场 | 拒识决策事件（respond / reject / defer），全双工下变为**持续判定** |
| 2 | 靠句法韵律预测话轮结束，接话间隙常为负 | 等 VAD 阈值，慢半拍且在换气口抢话 | 用户 `PAUSED`（停顿 ≠ 说完）、语义 endpoint、**预提交**（停顿期预生成不出声，即 Flux Eager 思路） |
| 3 | 听者"嗯 / 对"是自然伴随 | 每个"嗯"都可能触发 barge-in | 打断判定窗（backchannel / 真打断 / 噪声三分） |
| 4 | 被打断者说完当前小句优雅让出 | 立刻闭嘴生硬、不理霸道 | `YIELDING` 显式过渡态 + 截断对账 |
| 5 | 人不会"挂起等待" | 工具、检索、大模型都有秒级等待 | `PREPARING` / `HOLDING` + T0/T1/T2 填充与兜底 |
| 6 | 有视线、张嘴等视觉线索 | 只有音频（或有限视觉） | 起音确认窗、端点窗不可省，窗口大小即体验参数 |

## 3. 完整场景清单（34 个，按优先级分级）

### 3.0 优先级定义

| 级别 | 含义 | 数量 |
| --- | --- | --- |
| **P0 最小可用闭环** | 没有它就不是一个能用的语音对话；先跑通这 10 个 | 10 |
| **P1 体验分水岭** | 全双工区别于"按键式半双工"的核心价值；第二批落地 | 22 |
| **P2 增强与暂缓** | 依赖模型增量能力（R1/R4）或低频场景；有意识地缓 | 10 |

v3.3 新增场景以 **（新）** 标记；对既有场景补充的规则以 **补充规则** 标记。

### 阶段 A：静默期与会话边界

| 编号 | 优先级 | 场景 | 具体例子 | 状态 / 机制 |
| --- | --- | --- | --- | --- |
| A1 | **P0** | 会话建立，模型与音频通道预热 | 用户戴上耳机唤起助手，1 s 内听到"我在"——期间不丢用户先说的半句话 | `INITIALIZING`（边缘态） |
| A2 | **P0** | 双方静默；等待用户 vs 系统主动开场 | 开场后 5 s 没人说话，系统保持安静不催促 | `IDLE`，floor = open |
| A3 | P2 | 长静默 → 用户 `AWAY` → 主动关怀重启 | 双方静默 15 s → away；再过 30 s 系统轻声"还在吗？" | away 判定、重启策略 |
| A4 | P2 | 系统主动发起（提醒 / 推送到达） | 用户没说话，19:00 提醒触发：系统开口"到点了，该给妈妈回电话了" | `INTERJECTING` 温和版，经打扰管理 |
| A5 | P1 | 会话结束（明示 / 挂断）与断连恢复 | 用户"就这样，拜拜"→ 系统收尾；蓝牙断开重连后上下文还在。**补充规则**：备答中的答案、等待中的工具结果在重连后判定时效——仍有效则补播（带"刚才说到"前缀），失效则丢弃 | close / error / resume 事件，状态重建 |

### 阶段 B：用户输入期（9 个，编号无 B9）

| 编号 | 优先级 | 场景 | 具体例子 | 状态 / 机制 |
| --- | --- | --- | --- | --- |
| B1 | **P0** | 疑似起音 → 确认 / 误报 | 用户咳嗽一声（0.3 s）→ 不算开口；用户"哎对了…"→ 约 200 ms 内确认起音并发 `asr_start` | 起音确认窗；**外挂 ASR 标识触发点** |
| B2 | P2 | 用户说话中，系统伴随附和 | 用户讲了 20 s 需求，系统在语义边界轻声"嗯，明白"，不抢话（业界 IAS 0–50%，暂缓）。**守卫约束**：用户 `PAUSED` 超 400 ms 时禁止附和，附和只在用户 SPEAKING 中的子句边界触发——否则用户会把"嗯"当成接话信号而停下，双方互等 | `BACKCHANNEL`（不拿话轮） |
| B3 | **P0** | 停顿 ≠ 说完 | "帮我订一张…（停 1.2 s 想日期）…周五去上海的高铁票"——换气处不许抢答 | 用户 `PAUSED`；后沿窗 + 语义 endpoint |
| B4 | **P0** | 端点确认，用户释放话轮 | 上句说完后静音 600 ms 且语义完整 → `committed`，话轮交系统 | 决策事件 `committed` |
| B5 | P1 | 拒识判定 | 旁边同事对用户说"中午吃什么"——系统判定非对我，保持安静（记 defer 日志） | respond / reject / defer，交互态不变 |
| B6 | P2 | 超长说话无端点 | 用户连续说 60 s 不停 → 强制分段增量理解，防上下文与 ASR 爆 | 强制分段 |
| B7 | P2 | 旁路人声 / 多人在场 | 车内两人聊天夹杂对系统的指令，判不准时问"是在跟我说吗？"。**守卫约束**：同一会话 REPAIR 有频率上限，连续两次判不准直接 defer 静默并把音频交外挂 ASR 复核 | 拒识前置判定 + `REPAIR`；可依赖外挂 ASR |
| B8 | P1 | 用户显式禁言 | "你先别说，听我说完"→ MUTED；"好了你说吧"→ 解除。**补充规则**：禁言期间用户说完（committed）且静默超阈值而未显式解除 → 轻声确认"我可以说了吗？"（走 REPAIR），再无回应则自动解除 | `MUTED` ⇄ `LISTENING` |
| B10 | P1 | **（新）端点误判撤回** | committed 与 `asr_stop` 已发出，用户 300 ms 后接着说"……哦还有一件事"。语义上是同一句，协议上段已关闭 | 撤回窗；`committed_revoked` + `segment_merge`（Deepgram Flux `TurnResumed` 同义）；PREPARING → LISTENING |

### 阶段 C：响应准备期（用户说完 → 系统首帧出声）——v2 新增的核心阶段

时延不建状态：`PREPARING` 用三阈值切分——**T0**（约 0.5 s）内静默无感；
超 **T1** 出填充（"嗯，我看一下" / 背景音）；超 **T2** 兜底道歉降级。
工具与大模型只是让 `PREPARING` 变长的原因。

| 编号 | 优先级 | 场景 | 具体例子 | 状态 / 机制 |
| --- | --- | --- | --- | --- |
| C1 | **P0** | 快路径：T0 内出声 | "现在几点？"→ 0.4 s 内"十点二十" | `PREPARING`（用户无感） |
| C2 | P1 | 慢生成：超 T1 → 出声占位 | "把这段话翻成英文"→ 1.5 s 未出首帧 → 先"嗯…"再出译文 | `PREPARING` 的 filler 子阶段 |
| C3 | P1 | 说话前先调工具 / 检索 | "明天北京天气怎么样？"→ 静默调天气 API（0.8 s）→"明天晴，3 到 12 度" | `PREPARING` + tool_started / done / failed |
| C4 | P1 | 委托大模型 | "帮我规划三天成都行程"→"好，我好好想想哈"→ 大模型跑 6 s → 结果回灌、小模型代言播出 | `PREPARING` + escalation_started / done |
| C5 | P1 | 准备期间用户又开口（改口 / 重复 / 催促 / 放弃都算） | "查下天气"刚说完又补"哦对，是后天的"；或等了 1.2 s 不耐烦把原话重复一遍。**v3.4 三条规则，交互层不判意图**：① 起音不取消备答，继续跑（判定几百毫秒，重生成秒级）；② 新话 committed 时若还没出过声，视同 T1 到期先出垫话"好，马上"（对补充 / 重复 / 催促都合适，噪声到不了 committed 天然排除）；③ 新话进上下文，由模型决定续用旧答还是换新答。任务层只复用一条已有规则：结果携带 segment_id，回来时校验归属，已被覆盖则丢弃 | `PREPARING` 自环（备答不停）→ committed → `SPEAKING`（垫话）→ `HOLDING` → 模型续 / 换；与 D7 共用同一判定；带副作用工具在判定完成前不 commit（D10 已要求确认） |
| C6 | P1 | 准备超时 / 工具失败 → 兜底 | 查询 8 s 无结果 →"这个查得有点慢，出来我马上告诉你"，转异步任务 | T2 超时事件 |
| C7 | P2 | 预提交（负时延） | 用户停顿 1.2 s 时后台已预生成答案，`committed` 后即刻出声 | 对应 [latency-discussion](../latency-discussion/) 与 Flux Eager |

### 阶段 D：系统输出期（14 个）

| 编号 | 优先级 | 场景 | 具体例子 | 状态 / 机制 |
| --- | --- | --- | --- | --- |
| D1 | **P0** | 正常说话，转写随播放 | 系统播报行程，屏幕字幕逐字跟随**实际播放**进度（不是生成进度） | `SPEAKING`，锚定播放事实 |
| D2 | P1 | 用户附和 → 不让出 | 系统介绍方案中，用户"嗯嗯 / 对 / 好的"→ 系统不停顿继续说 | 打断判定窗 → `SPEAKING` 自环（v1 `RESUMING`） |
| D3 | **P0** | 真打断 → 让出 → 截断对账 | 系统读新闻读到一半，用户"停停停，换国际的"→ 300 ms 内闭嘴，历史里只保留已读出的半句 | 打断判定窗 → `YIELDING` → `LISTENING` |
| D4 | P1 | 假打断 → 暂停待判 → 恢复 | 系统说话中背景"砰"一声 → 暂停 0.5 s → 无有效转写 → 从暂停处继续播 | 暂停待判窗 + resume |
| D5 | P2 | 边说边调（双流同帧） | "我先给你念着新闻，同时帮你查着路况…"——说话与工具调用并行（依赖模型能力 R1） | `SPEAKING` + 并行 tool 事件 |
| D6 | P1 | 宣告后持轮等待 | "我查一下哈"（说完）→ 静默 2 s 等 API →"查到了，周五有三趟…" | `HOLDING` + filler 策略 |
| D7 | P1 | `HOLDING` 期间用户开口（叫停 / 催促 / 补约束都算） | 等待中用户"算了，不用查了"→"好的那不查了"，取消工具；"快点"→"还在查"，工具继续。**v3.4：与 C5 同一套三条规则**，只多一个在途工具可取消；显式放弃（模型判定）才 `tool_cancel`；催促不重置轮级时钟 | `HOLDING` 自环（工具不停）→ committed → `SPEAKING`（应答）→ 模型判放弃 → `tool_cancel` → `LISTENING`；否则回 `HOLDING` 续等 |
| D8 | P1 | `HOLDING` 超时 → 道歉 / 降级 | 等待超 8 s →"还在查，稍等我一下"或降级放弃 | T2 同款兜底 |
| D9 | **P0** | 说完去向：释放 vs 提问等答 | 系统"你要哪天出发？"→ 说完不释放，floor 标为等用户答 | floor = open vs agent-expecting-user |
| D10 | P1 | 工具缺参数 → 澄清追问 | "帮我订高铁票"→"要几点出发的？"→ 等答 15 s 没回应再问一次或放弃 | D9 特例（对应 phone-assistant `waiting_user`） |
| D11 | P1 | **（新）用户要求暂停、稍后继续** | 读新闻时用户"等一下……（接电话）……好，继续"。不是新意图，也不是禁言——要记住播到哪 | 打断判定窗判为暂停请求 → `YIELDING`（保留续播锚）→ `LISTENING`（floor = user）→ 用户"继续" → `SPEAKING` 从锚点续播；Easy Turn `wait` 的真正含义 |
| D12 | P1 | **（新）打断后又要回来** | 用户打断问了别的，说完"哦对，你刚才接着说" | 截断时未播内容标记 `unheard` 保留在服务端（不进历史主干）；后续可从锚点续播 |
| D13 | P1 | **（新）系统自我中止** | 说到一半，安全策略 / 内容过滤判定必须停止——系统侧发起的让出 | `policy_stop` → `YIELDING` → 一句收尾话术 → `LISTENING`；不开新轮 |
| D14 | **P0** | **（新）自回声误触发** | 系统说话时自己的声音被麦克风拾回（蓝牙延迟大、外放音量高、回声消除残余），起音确认窗把它当成用户开口 | 起音窗**回声前置判据**：起音信号与播放参考信号相关性高 → 判为回声，不进三分判定、不触发暂停待判；是 AEC 残余的兜底而非替代 |

### 贯穿性并发（7 个）

| 编号 | 优先级 | 场景 | 具体例子 | 状态 / 机制 |
| --- | --- | --- | --- | --- |
| X1 | P1 | 双方同时开口（碰撞） | 静默后系统刚要开口，用户同时开口 → 系统立刻让（用户优先）。**补充规则**：首帧播出后 200 ms 内用户起音 = 碰撞走本条弃答；超过 200 ms = 走 D3 打断判定窗 | floor = contested，让步策略可配；碰撞边界 200 ms |
| X2 | P2 | 外部事件在任意**持轮态**到达 | 导航播报中 / 备答中 / 等待中提醒触发 → 等当前动作完成再插（speak_at_pause）。v3.3 由"说话中"泛化为 PREPARING / SPEAKING / HOLDING 任一 | `INTERJECTING` 放行：speak_now / at_pause / hold |
| X3 | P2 | 系统硬插话打断用户 | 用户在说话但煤气报警 → 系统硬插话（默认禁用，仅告警） | `INTERJECTING` 硬版 |
| X4 | P2 | 非语音并行输入 | 语音对话中用户在屏幕点了"取消"按钮 → 不破坏 floor 语义 | 本章不展开 |
| X5 | P1 | **（新）播放卡顿** | 首帧已播出，网络抖动导致后续帧断续——状态说 SPEAKING，用户听到的却是断断续续的沉默，播放锚定原则在此失效 | `playout_stalled / resumed` 事件；卡顿超阈值按 HOLDING 填充策略处理（提示音 / "网络不太好"） |
| X6 | P1 | **（新）主动插话撞上等答** | 系统问"哪天出发？"等用户回答（floor = agent‑expecting‑user），此时提醒触发——两个"待处理"冲突 | 打扰管理优先级：非紧急排队到本轮 slot 填完；紧急告警先插再"回到刚才的问题" |
| X7 | P1 | **（新）禁言中的告警** | MUTED 期间煤气报警。X3 默认禁用 + B8 禁言叠加后告警没有出口 | `MUTED` 需要**不可禁言级别**：`safety_event` 穿透 → `INTERJECTING` → 播完恢复 MUTED |

### 4.2 v1（06 章 10 态）→ v2 对照

| v1 状态 | v2 处置 | 理由 |
| --- | --- | --- |
| LISTENING / SPEAKING / BACKCHANNEL / YIELDING | 保留 | 主干 |
| THINKING / DELEGATING | **拆分**：未出声 → `PREPARING`；出声宣告后的等待 → 并入 `HOLDING` | 两者填充策略（从静默到开口 vs 维持在场感）与超时兜底话术不同；v1 没有覆盖"用户说完到首帧"的时延堆积段 |
| HOLDING | 保留并扩容：自己的轮内停顿 + 宣告后等工具 + `[PAD]` 尾音 | 都是"出过声、仍持轮、暂无新内容" |
| RESUMING | 降级为 `SPEAKING` 自环上的瞬态标注 | 它无时长、无独立 UI 表现，是打断判定窗的一种出口 |
| INTERJECTING / MUTED / REPAIR | 保留为扩展态 | 行为差异足够大，但不进主干图 |
| （无） | 新增判定窗口层与事件层 | v1 把窗口混在守卫表里，未协议化 |

`PREPARING` 与 `HOLDING` 的区分必须立住：前者"话轮已接但未出声"，
后者"说了一半持轮等待"；两者的 T1 填充与 T2 兜底分别配置。

### 4.3 工具调用 / 委托大模型的处理原则

**不建交互态。** 交互层只关心两件事：系统持没持话轮、用户耳朵里是什么。
工具运行中只有两种交互态归属：未出声 = `PREPARING`（C3 / C4），出声宣告过 =
`HOLDING`（D5 / D6）；工具的开始 / 结束 / 失败作为决策事件驱动进出。
委托大模型与工具同构，只多一个"结果由全双工模型代言回灌"的续接动作
（对应 GPT‑Live 委托与 [phone-assistant](../phone-assistant-automation/) 双脑）；
大模型对交互层透明。好处：以后加多少种异步动作（检索、委托、设备控制），
状态图节点数都不变。

### 6.2 外部词表校订

外部给出的定义（7 项）：`speech_started` 感知用户开口 / `speech_stopped` 感知用户说完 /
`committed` 语义完整 / `listen` 本轮说完 / `speak` 决定响应回复 / `invoke_tool` 工具调用和委托 /
`stop` 判定新的一轮、停止播报。

总评：这是一份**单层的事件词表**，与 OpenAI Realtime 控制面几乎一一对应
（`speech_started/stopped` ↔ `input_audio_buffer.*`、`committed` ↔ commit、
`speak` ↔ `response.create`、`stop` ↔ `response.cancel`）。作为**事件层骨架可用**，
但缺窗口层与状态层，且混入了一个状态（`listen`）。逐项：

| 外部定义 | 归类 | 场景 | 校订建议 |
| --- | --- | --- | --- |
| `speech_started` | 感知事件 ✓ | B1 | 保留；拆两段 prearm（疑似）+ confirmed（确认），供外挂 ASR 与打断判定；补 `speech_cancelled`（误报回收） |
| `speech_stopped` | 感知事件 ✓ | B3 | 保留；语义 = 后沿 VAD，**不等于说完**——与 `committed` 的差就是"停顿 vs 说完" |
| `committed` | 决策事件 ✓ | B4 | 保留；= 端点确认 + 话轮释放；建议 payload 带端点置信度（支持 Eager 投机） |
| `listen` | ✗ 状态混入 | D9 | 移出事件层：改为感知事件 `playout_done` + 状态 `LISTENING`；"本轮说完"还需区分释放 vs 提问等答（floor） |
| `speak` | 决策事件 ✓ | B5 / C | **拆三分 respond / reject / defer**——拒识必须显式（日志、外挂 ASR 复核都要用）；payload 带 expect_reply 写 floor |
| `invoke_tool` | 决策事件 ✓ | C3 / C4 / D5 / D6 | 保留，kind = tool / escalate；补生命周期 done / failed；**不改交互态**，只决定 PREPARING / HOLDING 归属 |
| `stop` | 决策 + 动作，语义过载 | D3 / D4 | **拆 interrupt / pause / resume**：真打断 = 停播 + 截断 + 开新轮；假打断 = 暂停待判；"判定新一轮"与"停止播报"解耦——backchannel 不开新轮 |

补充缺失项：`playout_started`（首帧，`SPEAKING` 的锚点——没有它状态就只能锚在模型
开始生成上，字幕与打断对账全错位）、`playout_done`、backchannel（双向）、hold / filler（T1）、
timeout（T2）、away、floor 转移、`asr_*` 外发标识、session close / error。

## 7. 外挂 ASR 的外部启动标识

需求：系统对外给出一个标识，启动外挂 ASR（另有其他用途）。设计：

- **标识挂在判定窗口的进出沿上**（这正是窗口层需要显式建模的证明），两段式：
  - `asr_prearm`：疑似起音（B1 确认窗开启）即发出，外挂 ASR 预热建流，吃掉启动延迟；
  - `asr_start`：起音确认时发出，带 `segment_id` + 起始时间戳（**含确认窗回溯量**，
    音频从起音点回补，不从确认点开始）；
  - `asr_stop`：端点确认（`committed`）时发出，带终止时间戳；
  - `asr_cancel`：确认窗判为误报或回声时回收 prearm；
  - `segment_merge`（v3.3）：B10 端点撤回时，把已关闭的上一段与新段合并为同一句。
- **泛化为 segment 级外部协处理触发**：载荷 = `segment_id` + 时间窗 + 音频路由；
  ASR 是第一个订阅者，拒识复核（B5 / B7）、合规记录、热词检测挂同一组信号。
- 产地可以是系统 VAD，将来换成模型控制流输出的起音 / 端点声明，**协议不变**。

## 8. 对模型输出的需求与验收

系统需求层对模型侧的五条需求：

1. **边说边调**：工具调用字段与音频字段同帧共存（D5）；
2. **异步结果中途注入**：任意态下接受注入，模型自行决定接续时机（C4 / D6）；
3. **升级信号 + 代言回灌**：能输出"回答不了、请升级"控制字段；大模型文本回灌代言（C4）；
4. **细分意图控制字段**：`voice_intent`（silence / speak / backchannel / yield）、
   `floor_intent`（keep / release / take）、拒识声明、**暂停请求识别**（D11）——这是业界二元
   listen/speak 之外的增量（Instruct‑FD 已证明 Backchannel / Interrupt 是全行业短板）；
5. **共享时间基准**：所有输出携带 `segment_id` 与帧内偏移，并可与端侧上报的
   `playout_position` 对齐（决策 4）。

另：二次委托（C4 被打断后加约束）应携带前次 segment_id 做增量修改，而非从零生成（R2 的延伸）。

验收两条：

- 给定模型输出流 + **端侧播放位置流**，交互层任一状态可**纯函数推导**；
- 六个场景必须跑通：抢话（D3）、假打断（D4）、边说边查（D5）、等待超时（C6 / D8）、
  大模型接管中被打断（C4 × D3）、**自回声不自我打断（D14）**；
- 一组用例覆盖"备答 / 等待期用户又开口"（C5 / D7）：补充、重复、催促、放弃、新话题、噪声
  六种行为，在同一套三条规则下逐一验证表现合理——六分是验收维度，不是判定分支。

### 11.3 链路走查：C4 × D3

验收六场景里最难的一条，一条链路同时踩中缺口 1、3 与场景 D12、D14——说明这些缺口在主干上。

1. 用户"帮我规划三天成都行程" → committed → PREPARING，发 escalate。
2. 1.5 s 无结果 → T1 垫话"好，我好好想想哈" → SPEAKING（垫话）→ 播完 → HOLDING。
   **缺口 3**：HOLDING 计时器重置，总等待失控 → 决策 5。
3. 大模型 6 s 后返回，小模型代言 → tool_done → SPEAKING（代言）。
   **缺口 1**：代言内容从云侧流下，端侧播放位置需上报，否则下一步截断无依据 → 决策 4。
4. 播到第 3 s 用户"等等，只要两天的" → 起音确认窗。**D14**：先排除系统自己的代言回声。
   → 打断判定窗判真打断 → YIELDING。
5. 停播、truncate 到已播出位置 → LISTENING。**D12**：未播出的后半段标记 unheard 而非删除，
   用户接下来说"前面说的第一天可以保留"才接得上。
6. 用户新一轮 committed → 合并"两天"约束 → 再次 escalate，**携带前次 segment_id 做增量修改**。
