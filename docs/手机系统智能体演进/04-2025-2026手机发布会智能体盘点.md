## 2. 共同趋势

1. **「Harness」成为发布会名词**。荣耀 YOYO Harness、vivo 蓝心 Harness、OPPO 端云 Harness，一周内三家把「包裹在模型外面的执行框架」摆到主 keynote。荣耀的定义：它决定模型能感知到什么、如何拆解任务、调用哪些工具、执行中能否实时调整。这与本仓库 harness 三层结构的出发点一致，也说明系统级 harness 的竞争已经从「有没有」进入「谁的更完整」。
2. **能力全部「工具化 / Skill 化 / 原子化」并比数字**：华为 2100+、vivo 6000+、荣耀 700+、小米 260+。数字口径不一（能力项 vs 工具 vs 原子技能），不可直接比较，但方向一致：系统能力先变成模型可调的接口，GUI 只作兜底。
3. **GUI 操控普遍走向「系统级 + 兜底」**：豆包用系统签名做主路径；华为把独立的 GUI 智能体收编进 HMAF 2.0；Google 把 UI 自动化做成平台框架配精选 App；Apple 不做 GUI 自动化。纯 ADB / 无障碍的第三方路线（AutoGLM）保留开源与跨设备优势，但被生态封禁风险最高。
4. **长任务步数与触发型自动化成为指标**：荣耀 100+ 步、40+ 触发条件；华为「长周期任务」入外循环；vivo「长期感知信息、自主规划」。「任务比对话活得久」正在成为共识。
5. **记忆从功能变成底座**：华为「鸿蒙记忆是 AI OS 底座能力」、OPPO 闪记 → 意图判断、vivo 长期记忆与自主学习、Muse 文件式记忆。记忆源全部扩展到系统数据而非仅对话。
6. **安全叙事升级到「Agent 权限模型」**：华为 CLI 风险分级与动态绑定、vivo 身份 / 权限 / 运行 / 审计全流程基座、Google 特权门控、Muse 模型外审批。但**「谁弹确认卡、模型是否在批准循环里」**只有 Muse 公开说清楚；国内厂商公开材料仍是「高风险触发用户确认」的层面。
7. **生态谈判进入协议化**：豆包 SAEP、华为意图即服务 + 天工计划 10 亿元、Google 精选 App 白名单、网页端零售商屏蔽 Muse 而 Shopify / PayPal 接入。技术接口之外，利益分配协议成为 OS 结合的必要组成。

## 3. 差异所在

- **执行主路径**：结构化优先（Apple、华为、Google）vs GUI 优先（豆包、AutoGLM）。国内 App 生态决定了 GUI 兜底不可缺，华为走的是两者兼备且 GUI 开放给开发者。
- **计算机在哪**：端侧为主（所有 OS 厂商）vs 云端为主（Muse、AutoGLM 2.0 云手机）。OS 厂商的独有资产在现场层，云端 Agent 的独有资产在零运维与账号图谱。
- **快慢 / 双循环表述**：只有华为把「快慢自适应」和「双循环」作为架构主叙事公开；其他厂商用 Harness、Multi-Agent、AgentOS 表述，未公开路由与演进机制。
- **全双工语音**：所有厂商都以语音为主入口之一，但公开材料中没有一家把全双工（barge-in、话权、音频焦点仲裁）作为 Agent 架构的一层来讲；这是我们 [omni-realtime-voice/](../omni-realtime-voice/) 与三层 harness 的空档机会。
- **开发者开放程度**：华为（Agent / Skill / MCP / 意图框架 / A2A / A2UI / OpenClaw 接入 / AgentKit）与 vivo（AgentOS 开放 Shell、Python 接口）最开放；荣耀兼容 Skill 生态；Apple / Google 走 schema / AppFunctions 但特权受限；豆包由 App 声明。
