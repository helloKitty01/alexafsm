# 02 八个议题与 Harness 迭代

> 承接 [01](./01-三个方向的判断.md)。讨论进一步收敛为八个议题：长时 / 自动化任务、全模态全双工、OS 深度融合、个人数据与记忆、OS 能力接入、自演进、快慢系统 × Jev、harness 是否迭代。
> 对照对象：Muse（云端个人 agent）、豆包手机助手（系统级 GUI）、小艺（系统级 Skill 化 + 双循环，见 [03](./03-小艺架构与HDC盘点.md)），以及本仓库已有设计 [phone-assistant-automation/](../phone-assistant-automation/)（三层 harness、UAT 接口 v1.3）、[openclaw-automation/](../openclaw-automation/) v4、[jev/](../jev/)。

## 0. 总判断：做第三个物种

| | Muse | 豆包手机助手 | OS 智慧助手（我们） |
| --- | --- | --- | --- |
| 计算机在哪 | 云端 Secure VM，手机只是视图 | 合作 ROM 里的系统应用 + 云端推理 | 手机本机是主体，云端只是一条车道 |
| 主入口 | 文字，App / WhatsApp | 语音 + 看屏 + GUI 操控 | 全双工语音 + 屏幕语义 + 事件触发 |
| 执行方式 | 云浏览器 + 连接器 + 自己写工具 | 虚拟屏事件注入（`INJECT_EVENTS`） | 结构化接口 / 后台虚拟屏 GUI / 云沙箱三路路由 |
| 信任机制 | Sentinel 在模型外批，凭证替身 | 敏感操作确认 + SAEP 由 App 声明边界 | 硬件信任根 + 系统级授权卡 + 预览再提交 |
| 独有资产 | Meta 社交图谱、零运维 | 字节的模型和内容生态 | OS 事件 / 状态 / 传感器、系统应用、后台常驻、生物识别 |

Muse 证明「长期在线、可以委托」的形态有人要；豆包证明系统级 GUI 执行在中国 App 生态里是必须的兜底；小艺证明「系统应用全面 Skill 化 + 双循环自演进」可以作为系统级智能体的主叙事。三者都要借，但壁垒在第三列：**只有 OS 厂商同时拥有现场（事件、状态、传感器）、信任根（硬件、锁屏、生物识别）和分发权（App 接入协议）**。差异化不是「更聪明的助手」，而是「所有 Agent 都必须经过的那一层」。

## 1. 长时 / 自动化任务：方向对，补三件事

现有 Task = Trigger × Goal × Policy、中枢独立于 LLM 存活、打扰管理器唯一出口，不用动。要补：

- **任务成为产品表面**，不只是内部模型。Muse 的 Goals 页把「委托了什么、进展到哪、卡在哪」做成可见的一页；小艺 HDC 2026 也强调「执行过程用户实时可见、随时介入」。我们有 `<active_tasks>` 尾部注入给模型看，用户侧还缺对应视图。
- **两条执行车道**：模板车道（模型只选模式填参数，程序生成 job）覆盖定时、单事件、固定动作；沙箱车道（模型可写代码、读开放网页、起草，出网与发送仍走中枢）覆盖调研、草稿、一次性工具。没有第二条，模板库被长尾压垮；没有第一条，沙箱变成不受控的 OpenClaw。
- **终态可核验**。「做完了」不接受模型自述，要有可回放轨迹和终态检测（订单号、发送回执、文件存在）。这也是自演进的反馈信号来源。

## 2. 全模态全双工：是差异化，要说清赢在哪

- Muse 是「把事交出去」，全双工助手是「此刻陪我一起把事办了」。后者的场景（开车、做饭、走路、边看边问）是手机独有的高频现场。
- 全双工在端侧是 OS 厂商独占：唤醒、音频管线、低功耗常听、barge-in、与来电和媒体的音频焦点仲裁。
- 看屏同时喂像素 + 语义树。小艺的「伴随式 AI」（屏幕静止即识别并主动给出总结 / 待办 / 导航）是这个方向的现成产品样本。
- 模态是前台的事：omni 模型负责听、说、看、指代、创建任务、代收澄清；超过数秒的工作降级为任务。
- 指标：barge-in 时延、误插话率、场景下免手完成率。

## 3. OS 深度融合：壁垒不在权限，在四层原语

把下面四层做成 **OS 级服务**，并允许三方 Agent 接入（收权限、可审计、可收费），别人的 Agent 越多壁垒越厚：

1. **现场层**：事件总线（来电、通知、位置、电量、日程、App 内状态）+ 设备状态 + 环境状态。云端 Agent 永远做不了。
2. **信任层**：授权卡由系统弹出而不是由模型说；一次性凭证，模型不见真密钥；生物识别 / 安全芯片作信任根；「先预览、再提交」作为动作接口规范。小艺的做法可对照：CLI 原子能力按高 / 中 / 低风险分级，权限动态绑定到任务进程、最小权限、高风险触发用户确认。
3. **执行层**：豆包式虚拟屏 + 事件注入，我们天然拥有。要加两样：结构化接口优先（自有 Intents 注册中心，对标 AppFunctions / 小艺 Skill 化），和「读了不可信内容 → 失去自动放行」的污染状态。
4. **分发层**：类似 SAEP 的 App 接入协议，由 OS 出面。App 厂商面对 OS 和面对字节的谈判姿态完全不同；预装、商店审核、流量分成都是筹码。小艺的「意图即服务」把它包装成了给开发者的新流量入口，这是正确的叙事方向。

## 4. 个人数据与记忆：先分类，再决定谁能读

「手机操控记录、当前手机状态、环境状态、屏幕状态」混了几种性质不同的东西：

| 类别 | 例子 | 生命周期 | 注入方式 |
| --- | --- | --- | --- |
| 瞬时状态 | 电量、网络、正在开车、屏幕内容 | 不落盘，实时拉 | context provider 按需注入 |
| 事件 / 操控日志 | Agent 点了什么、用户接管了什么 | 短期保留，append-only | 不进 prompt，作审计和技能提炼原料 |
| 事实记忆 | 家人、地址、常用账户、饮食忌口 | 长期，用户可编辑 | 检索注入 |
| 程序性记忆 | 某 App 某流程的操作手册 | 长期，可版本化 | 按任务加载（即 skills） |
| 目标 / 任务 | 进行中的委托 | 由中枢持有 | 任务摘要卡片 |

小艺的四层记忆（瞬时 / 短时 / 长时 / 全时 → 全局动态画像）与此可对照，但它按时间尺度切，我们按性质与注入方式切；两者都强调记忆源不只是聊天记录，还有系统级数据。

硬约束：
- 记忆写入带来源和置信度；从不可信内容（网页、他人消息、截图）提炼的东西不能自动升级为事实记忆。
- 用户能看见、能改、能删。
- 屏幕状态和操控记录是最高敏感级；验证码和重置链接在进入任何模型上下文之前剥掉。
- 端侧存储、端侧加密，本身就是对云端 Agent 的差异化卖点。

## 5. OS 能力接入：统一能力注册中心，自有 AI 能力也是工具

四类来源（OS 底层、系统应用、自有应用、三方应用）加上助手自有 AI 能力（TTS、修图、翻译、摘要），全部收进一个**统一能力注册中心**，每个能力带元数据：时延契约（决定回复时机三分）、可逆性、敏感等级、是否支持预览、是否离线可用、来源信任级。

「用温柔的音色帮我播报今天的天气」说明两点：
- 自有 AI 能力也要**参数化并暴露为工具**（TTS 带音色、语速、情绪参数），不硬编码在前台。
- **内容层和渲染层分开**：天气查询是一个工具调用，播报是另一个；播报还要经过打扰管理器。

工具会有几百上千个（小艺 2100+ 系统能力、vivo 6000+ 原子能力、荣耀 700+ 工具），全部塞进 prompt 不现实，需要分层检索或路由——接到第 7 点。

## 6. 自演进：三种对象，三种管控力度

| 对象 | 能不能自动改 | 怎么管 |
| --- | --- | --- |
| System prompt 核心部分 | 不能 | 固定，只随版本发布 |
| 用户可见的人设 / 偏好文件（类 `SOUL.md`） | 可以，用户可见可回滚 | 每次变更留 diff |
| Skills（按 App × 任务的操作手册） | 可以，且是主战场 | 离线提炼 → 回放验证 → 灰度 → 回滚 |
| 经验（失败原因、用户纠正） | 可以 | 按 skill 挂载，限量、LRU 淘汰 |

手机比 code agent 更适合做 skill 自演进：App 流程高度重复；同一款 App 有几百万台设备在跑，可做脱敏后的群体学习。小艺帮帮忙的「联网学技能 / 看图学技能 / 手把手教学 → 保存为专属技能」是用户侧显式教学的样本；我们要补的是自动提炼 + 群体下发。

关键在反馈信号。手机任务没有「测试通过」，替代物是：用户确认过的预览、终态检测通过、用户没有接管或撤销。提炼放在充电、夜间做。不做端侧改权重。

## 7. 快慢系统 × Jev：中枢从「非 LLM」升级为「轻决策」

现在中枢定义是「非 LLM 为主」，为了可靠和低功耗。但很多判定是语义的又不需要生成：意图六分类、工具选择、敏感等级判定、打扰分级、watch 判定、澄清是否需要——全是「从有限选项里选一个」，正是 Jev 的形态。

- **中枢升级为「调度 + 轻决策」**：Jev（或单 token 分类基线）承担上述判定，深度模型只负责规划和执行。打扰管理器、watch 轮询这类高频判定成本降一个量级。
- **Jev 作为独立的第二意见**：敏感等级判定若由执行模型自己做，就是「同一个 agent 给自己批」。让一个不在执行循环里的快模型判定「这一步是不是不可逆动作」，与第 3 点信任层一致。
- 遵守 [jev/](../jev/) 的口径：255 是单个 Choice 上限，意图树分层；意图与参数分开建模；成本收益和单 token 分类基线比过再定；执行控制不交给 Jev。

对照小艺：它的「快慢自适应」是把简单任务（打开蓝牙）走快系统、复杂任务路由到慢系统「规划 → 执行 → 反思」多轮调 Skill；路由本身也是一次判定。我们的区别是把「判定」从模型循环里拿出来做成中枢组件，而不是让同一个模型自己决定快慢。

## 8. Harness 要不要迭代：要，加层，不推翻

三层骨架（omni 前台 / 中枢 / 深度后台）和 v1.3 的 UAT 接口站得住，Muse 和小艺都印证了它们（小艺的内循环 ≈ 我们的单 TaskRun agent loop；外循环 ≈ 我们要新增的演进层）。需要迭代五处：

1. **中枢扩容**：从「调度器」变成 调度 + 轻决策（Jev）+ 许可（Sentinel 等价物，授权卡由中枢生成投递）+ context providers（瞬时状态按需注入）。
2. **执行层显式拆三种执行体**：结构化接口、后台虚拟屏 GUI、云沙箱，由路由层按能力注册中心元数据选，模型只表达「做什么」。加污染状态。
3. **记忆层成为一等组件**：按第 4 点五类分开存、分开注入，用户可见可编辑。
4. **新增演进层**：离线提炼器 + 技能库 + 验证与回滚，不在实时链路上。
5. **关系表面与控制表面分开**：全双工语音是关系表面；Goals 页、活动日志、审批卡、收件箱是控制表面。批准不能是下一句 TTS。

再往上一层：把中枢的信任层和现场层**定义为 OS 服务对外开放**，三方 Agent 接入必须经过它。从「一个助手产品」变成「Agent 平台」，壁垒在这一步成立。

### 迭代后的分层示意

```text
┌ 关系表面：全双工 omni 前台（听/说/看/指代；创建任务、代收澄清）────────────┐
│ 控制表面：Goals 页 · 活动日志 · 审批卡 · 收件箱                              │
├ 中枢（OS 级服务，非 LLM 存活）──────────────────────────────────────────────┤
│ 调度 · 触发器 · 事件总线 · 打扰管理器                                        │
│ + 轻决策（Jev / 单 token 分类：意图、敏感等级、打扰分级、watch 判定）          │
│ + 许可（授权卡生成与投递、一次性凭证、范围核验；模型不在循环里）               │
│ + context providers（瞬时状态按需注入）                                     │
├ 记忆层（一等组件）──────────────────────────────────────────────────────────┤
│ 瞬时 / 事件日志 / 事实 / 程序性(skills) / 目标；带来源与置信度；用户可编辑    │
├ 执行层（深度模型 + 三种执行体，路由层选）───────────────────────────────────┤
│ 结构化接口(Intents/Skill/MCP) · 后台虚拟屏 GUI · 云沙箱                      │
│ 污染状态：读过不可信输入 → 失去自动放行                                      │
├ 演进层（离线，不在实时链路）────────────────────────────────────────────────┤
│ 轨迹提炼 → 技能库 → 回放验证 → 灰度 → 回滚；群体学习脱敏下发                 │
└ 能力注册中心：OS 底层 / 系统应用 / 自有应用 / 三方 / 自有 AI 能力，带元数据 ─┘
```

## 9. 借什么、不借什么

- **借 Muse**：Goals 视图、活动日志、许可在模型外、凭证替身、Ideas 式冷启动、主动消息有门槛。不借「一人一台云 VM」当前提，云只做一条车道。
- **借豆包**：虚拟屏 + 事件注入的后台 GUI 执行、全双工语音优先、SAEP 式 App 声明协议。不借「截图 3–5 秒一次全上云」作主路径；不借它的生态谈判姿态，我们是 OS，应由 OS 定协议。
- **借小艺**：系统应用全面 Skill 化 + 意图即服务的开发者叙事、双循环（内循环执行 + 外循环演进）的架构表述、CLI 风险分级 + 动态绑定到任务进程、HPIC 端云同级隐私、伴随式 AI 的屏幕感知形态。不借「把快慢路由交给同一个模型」，也不重蹈「探索性 GUI 智能体一年后下线」——GUI 兜底从第一天就要在路由层里，而不是一个独立的众测智能体。
- **自己做的差异化**：现场层、硬件信任根、屏幕语义、端侧记忆、群体技能学习、Agent 平台化。

## 10. 度量

用户愿意打开哪几类授权、打开后又关掉的比例；长程任务到达终态且可回放的比例；不可逆动作零误放行；主动触达被接受的比例；App 改版后技能自动修复的时长；全双工场景下的误插话率和 barge-in 时延。

一句话：Muse 在云端造了一台「安全的个人电脑」，小艺在系统里长出了一个「智慧大脑」，我们要在手机里造的是「安全的个人现场」。现场层、信任层、全双工前台是别人抄不走的；长时任务、技能演进、快慢系统是把现场用好的方法；harness 加层不推翻。
