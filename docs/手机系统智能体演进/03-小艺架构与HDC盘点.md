## 2. HDC 2025：HMAF 1.0 定框架

《鸿蒙智能体框架白皮书》（2025-06）的核心定义（官方口径）：

- **两类智能体**：系统级智能体（小艺）结合 OS 底层能力，通过系统级感知、记忆、工具能力协同其他智能体闭环复杂任务；领域智能体具有垂域知识与工具，大量由应用厂商孵化，称「应用智能体」，「源于应用、服务于应用、和应用伴生增强」。
- **小艺是中枢 / 调度员**：多模态系统级入口（小艺语音对话、导航条、小艺搜索、小艺建议、Chips 推荐）理解高阶意图，分发到对应鸿蒙智能体；通过鸿蒙 Agent 通信协议实现跨设备、跨应用多智能体协同。
- **交互范式**：从 GUI 向 LUI 全面演进，「点击操作变成一句话的事」。
- **开放平台**：50+ 鸿蒙系统插件、意图框架升级兼容 MCP、自然语言创建工作流、提示词自动优化；支持 LLM / workflow / 多 Agent（A2A）三种开发模式；一键上架小艺智能体市场，多设备多入口分发。
- **分发承诺**：亿级日活曝光，智能体可接入小艺对话、Chips、小艺建议等系统级入口。

2025 年这一版的重点是**生态框架**：定义谁调谁、怎么调、怎么协作；小艺本身的架构（模型、循环、记忆）在这一版没有公开细节。

## 3. HDC 2026：Agentic 自演进架构与「系统智慧大脑」

### 3.1 双循环（官方口径 + 媒体转述）

华为的表述（网易科技 2026-06-12、凤凰网、搜狐等多家一致转述）：

> 小艺变聪明的根本，在于全新的 Agentic 自演进架构。其核心是「双循环」机制。
> **内循环**负责单次任务的实时调度。依托上下文引擎，小艺能够理解指令的深层目的，自主决策需要调用哪些工具、以什么顺序执行，并在任务完成后将有效经验沉淀下来。
> **外循环**构建了「快慢自适应 — 记忆自学习 — 执行自动化 — 反思自迭代」的持续演进。面对简单问题快速响应，面对复杂任务进入深度思考模式，自主规划路径并逐步推进。小艺会持续学习用户的偏好和习惯；同时结合执行反馈持续调整策略，在跨应用协同和长周期任务中不断优化。

拆开看：

| 循环 | 时间尺度 | 职责 | 产出 |
| --- | --- | --- | --- |
| 内循环 | 单次任务 | 上下文引擎理解意图 → 决策工具与顺序 → 执行 → 沉淀有效经验 | 任务结果 + 经验条目 |
| 外循环 | 跨任务、跨会话 | 快慢自适应（路由）、记忆自学习（画像）、执行自动化（把重复流程固化）、反思自迭代（用执行反馈改策略） | 更新后的策略 / 记忆 / 自动化流程 |

**推断**：这与业界 code agent 的「运行时 agent loop + 离线 skill 提炼 / curator」是同构的——内循环对应一次 agent loop，外循环对应把轨迹变成可复用能力并调整路由策略。华为把「快慢自适应」放在外循环而不是内循环，说明快 / 慢的分流策略本身也是被学习和迭代的对象，而不是固定规则。

### 3.2 快慢系统（官方口径，来自 2026-07 小艺智慧大脑放量说明）

- **简单任务**（如「打开蓝牙」）由**快系统**直接执行。
- **复杂任务**路由到**慢系统**，经过「多轮 规划 → 执行 → 反思」调用 Skill，直到完成用户交代的任务。
- 官方举例：老版本对「明天早上 5 分钟一个的闹钟」直接创建，新版本经推理后完成任务；执行复杂任务时会出现「发现技能」「执行任务查询天气」等过程提示。
- 慢系统会「自动深度思考并不断规划、执行、反思」，当前 UI **不展示思考过程**。
- 配套「统一上下文服务」：问答、聊天、对话、任务风格统一，增强多轮连续性。

**推断**：快 / 慢的分流点在意图理解之后、执行之前；快系统大概率是意图框架的直接匹配 + 单步 Skill 调用（接近传统语音助手的意图槽路径），慢系统是带 Skill 发现的 ReAct 式多轮循环。华为没有说明分流是规则、分类器还是同一个模型的自判。

### 3.3 模型层：「万能插座」（媒体转述，爱范儿 HDC 2026 深度解构）

- 不押注单一模型，建模型接入架构，让 Pangu、DeepSeek 等灵活对接；「谁在哪个场景做得最好，小艺就用谁」。
- 举例：英文商务邮件路由到英文写作强的模型；运动数据分析路由到结构化推理强的模型。
- 同期开源 openPangu 2.0。

### 3.4 记忆体系：「鸿蒙记忆」（媒体转述，HDC 2026 早餐会分享）

四层记忆汇成全局动态画像：

| 层 | 覆盖范围 |
| --- | --- |
| 瞬时记忆 | 单次推理 |
| 短时记忆 | 单个对话窗口 |
| 长时记忆 | 用户的指令偏好和隐性习惯 |
| 全时记忆 | 伴随态的持续积累 |

- 记忆源不只是聊天记录：日历、运动健康、消费记录、图库等系统级数据都在内。
- 定位为 **AI OS 底座能力**，「不是小艺一个应用的私有功能」。
- 例子：「我这三年甘油三酯什么趋势」→ 跨时间调取体检报告数据给出曲线，并接健康智能体咨询。
- 「记忆沉淀 → 回到服务」：系统根据记忆中沉淀的意图模式判断什么时候主动弹出，把「意图即服务」从被动响应推向主动预判。

### 3.5 感知与执行：Skill 化（官方口径）

- **感知**：用户授权下可调用 **200+ 项系统级数据**（日程、实时位置、健康、近期文件、常用通勤工具等）；HarmonyOS 7 新闻稿另提「全天候智能感知引擎」（未公开定义）。服务从「应答式」升级为「预判式」。
- **执行**：**2100+ 项系统核心能力全面 Skill 化**——备忘录、日历、图库、文件管理、设置、蓝牙、联系人等系统应用封装为标准化技能；小艺可自主调度系统资源完成跨应用、跨设备任务；执行过程用户实时可见、随时介入 / 确认 / 修正。
- **生态**：500+ 伙伴精选 Skills、2000+ 鸿蒙智能体；接入方式包括 Agent、Skill、MCP、意图框架。
- **造工具**：调用「码上飞」文生代码 + 系统相机 / TTS，一句话生成可交互的小工具（如拍物学单词），不下载应用、不写代码。
- **规模**（官方）：小艺 DAU 1.8 亿，日均唤醒 30 亿次，过去一年日均 Agent 分发量提升 4.5 倍。

官方演示场景：
- 半马训练计划：拆意图 → 查比赛信息 → 调日程 / 运动健康 / 睡眠数据 → 协调网页搜索、运动健康 Coach、Health 等 Skills → 输出计划写入日历。
- 跨端取文件：手机小艺联动 PC 小艺（PC 合盖待机）找出文件 → 清单确认 → 文档管理 Skill 打包传输 → 跨设备通知。
- 出行：读日程会议地点 → 地图 Skill 实时路况算出发时间 → 定闹钟 → 预约打车。
- 聚餐：按人数口味生成菜单 → 叮咚买菜 Agent 一键加购 → 用户确认后下单。

### 3.6 HMAF 2.0 与开放平台（官方口径）

- 「意图即服务」：用户说需求 → 系统理解意图后直接匹配能完成的 Agent 或 Skill，跳过「打开 App → 找服务」。
- 复杂任务成功率提升至 **90% 以上**（官方数字，未给口径）。
- 开放 **20+ 项系统级 AI 能力**；**首次向开发者开放 GUI 操控能力**。
- **A2A 升级**：支持头部伙伴端侧、云侧 A2A 对接；端侧直连让伙伴 Agent 在设备本地协作（腾讯视频接入：让小艺设倍速、问剧情，不跳出当前界面）。
- **A2UI 协议**：Skill 不预定义界面，Agent 按指令复杂度动态生成 UI（轻卡片 ↔ 详细视图），同一 Skill 在手机 / 平板 / 车机渲染。A2UI 本质是流式 JSON 消息（`surfaceUpdate` / `dataModelUpdate` / `beginRendering` / `deleteSurface`）驱动声明式组件。
- Skill 上架打通华为账号鉴权；VibeCoding 沉浸式编程（自然语言描述 → AI 生成代码框架 → 审核反馈 → 一键发布）。
- 开发者文档目录（小艺开放平台）：开发 Agent / 知识库 / 工作流 / 卡片 / 界面 / 音色、小艺罗盘、上架审核规范、A2A 协议接入方案、智能体数字商品支付、**OpenClaw 接入**。
- AgentKit（Agent Framework Kit）：应用内通过 `FunctionComponent({ agentId, options: { title, queryText } })` 拉起半屏智能体；`FunctionController.isAgentSupport()` 检查可用性；需 HarmonyOS 6 / API 20+、真机、华为账号联网、中国境内。
- 天工计划投入 10 亿元，目标孵化 10000+ AI 元服务、1000+ 意图框架 / MCP、5000+ Agent。

### 3.7 安全：鸿蒙智能体安全框架与 HPIC（官方口径，《鸿蒙智能安全白皮书》V3.2）

- **智能体身份**：上架时生成全局唯一 AgentID；Agent 间基于华为账号统一身份的 OAuth 2.0 认证，保证跨 Agent 数据资产不被恶意访问。
- **行为风险分级访问控制**：HarmonyOS 提供「大模型亲和的 CLI 原子能力」，智能体借大模型理解指令并组装 CLI 命令；CLI 指令按高 / 中 / 低风险分级；调用时先校验 Agent 权限，通过后把所涉 CLI 权限**细粒度动态绑定到当前任务进程**，任务生命周期内遵循最小权限；**高风险行为（如删除应用）触发用户确认**，展示操作详情并等待明确授权。
- **动态沙箱与权限治理、Agent 安全互联**：作为框架的两个组成部分列出（细节未展开）。
- **HPIC（HarmonyOS Personal Intelligent Computing）**：在云上建立用户专属个人计算空间，「云侧 AI 的数据处理和端侧一样安全」。机制：身份与内容解耦——Oblivious Relay 可信三方代理 + OHTTP + HPKE 端到端加密，账户 ID、设备 ID、IP 三重盲化；匿名凭据基于盲签名、周期轮换；云端「无敏感数据」设计；云侧沙箱；CPU / NPU 远程证明保证机密域软件栈未被篡改。已通过中国泰尔实验室端侧 / 云侧 / 端云传输三项增强级安全检验。
- **模型内生安全**：安全对齐训练让模型分层管理可信用户指令与不可信外部数据、自主忽略注入攻击；智能体红队攻击模拟与对抗数据增强；可解释性探针监测神经激活信号，对不可信信息源导致的低质量决策做低成本预警。
- 小艺 Claw 成为首个获信通院国家级认证的终端厂商 Claw 类智能体（媒体转述）。

## 4. 产品形态与执行方式

### 4.1 入口

语音唤醒、长按导航条、长按电源键、拖给小艺（文本 / 图片 / 文件投喂）、小艺圈选、识屏对话、分屏问小艺（折叠屏）、双击导航条进入伴随式 AI、Chips 推荐、小艺建议、小艺搜索。

### 4.2 GUI 操控：小艺帮帮忙

- 官方定义：小艺 App 推出的**应用操控服务**；通过语音 / 文字指令完成购物、订机票、下载视频等任务；支持一张图 / 一句话 / 一次演示**教技能并保存为专属技能**；有定时计划任务。
- 执行方式：任务默认**后台执行**，屏幕下方彩条查看详情；部分应用会提示「当前正在使用屏幕分享」（说明后台执行走的是屏幕镜像 / 虚拟显示一类机制——**推断**，官方未说明是否为豆包式虚拟屏 + 事件注入）；原生鸿蒙 App 可后台隐藏执行，非原生 App（网易云、Chrome 等）走前台读屏 + 模拟操作。
- 限制：不支持桌面编辑、负一屏、小程序、元服务、卓易通等非原生应用；屏幕朗读模式下不可用；仅中文系统；不静默下载应用；受应用平台政策限制部分任务无法完成（微信「尚未接入」）。
- 媒体评测指出的问题（太平洋科技 2026-06）：触发词不明确（需要每次说「小艺帮帮忙」）；机型覆盖不齐（三折叠 Mate XTs 无）；持续 OCR + 端侧推理导致运行超十分钟明显发热。
- **走向**：2026-09 华为支持页明确该智能体为 HarmonyOS 6.0 探索性众测功能，HarmonyOS 7.0 新机型不再提供。结合 HDC 2026「首次向开发者开放 GUI 操控能力」和系统应用全面 Skill 化，**推断**华为的路线是：GUI 操控从独立的众测智能体收编为 HMAF 2.0 里的系统能力（Skill 优先、GUI 兜底、开发者可接入），而不是继续以单独产品形态存在。

### 4.3 伴随式 AI（Pura X Max，HarmonyOS 6.1）

- 双击导航条启动；在支持的鸿蒙 App 中，只要屏幕静止就开始识别内容，主动给出「总结 / 收藏 / 梳理脑图 / 生成待办 / 导航」等操作。
- 用户同意后主动识别钉钉、学而思等 App 的待办同步到系统日历；归集瑞幸 / KFC / 麦当劳取餐号、同程 / 携程票务酒店订单，时序化整理与提醒。
- 首批伙伴：滴滴出行、咪咕视频、知乎。
- 依赖持续屏幕 OCR 与端侧算力；「软硬芯云协同」（麒麟 9030 Pro）。
- 与分屏问小艺的区别：分屏是用户复制内容喂给小艺；伴随式是小艺主动、连续地读屏并提出动作。它是 HDC 2026「全时记忆」和「全天候智能感知引擎」的产品前身。

### 4.4 A2A 协作商用（Mate 80 起）

一句指令让小艺调起深圳航空（值机选座）、喜马拉雅、叮咚买菜、东方财富等应用智能体，「专业事交给专业 Agent」；HDC 2026 升级为端侧直连（腾讯视频不跳出当前界面）。

## 5. 与本仓库设计的对照

| 小艺 | 我们（[phone-assistant-automation/](../phone-assistant-automation/) + [02](./02-八个议题与Harness迭代.md) 的迭代） | 差别 / 启示 |
| --- | --- | --- |
| 内循环：上下文引擎 → 工具决策 → 执行 → 沉淀经验 | 单个 TaskRun 的 agent loop（深度后台） | 同构。我们多一层「非 LLM 中枢」持有任务与触发器，内循环只是执行体之一 |
| 外循环：快慢自适应 / 记忆自学习 / 执行自动化 / 反思自迭代 | 新增演进层（离线提炼 → 技能库 → 验证 → 回滚）+ 记忆层 | 小艺把快慢路由策略也放进演进对象；我们把快慢判定做成中枢的轻决策组件（Jev），并且要求技能演进有可核验反馈 |
| 快系统 / 慢系统由模型自判 | 中枢轻决策（Jev / 单 token 分类）判定后派发 | 我们把判定拿出模型循环，一是成本，二是「不可逆动作由不在执行循环里的模型判定」的安全考虑 |
| 四层记忆按时间尺度：瞬时 / 短时 / 长时 / 全时 | 五类记忆按性质与注入方式：瞬时状态 / 事件日志 / 事实 / 程序性 / 目标 | 两种切法可以叠加：时间尺度决定保留策略，性质决定谁能读、怎么注入 |
| 系统应用全面 Skill 化（2100+）+ 意图框架 + MCP + A2A | 统一能力注册中心（OS 底层 / 系统应用 / 自有 / 三方 / 自有 AI 能力，带时延 / 可逆性 / 敏感级元数据） | 方向一致。我们强调元数据驱动路由与回复时机，小艺公开材料未提到这一层 |
| GUI 操控：独立众测智能体 → 收编进 HMAF 2.0 | 三种执行体（结构化接口 / 后台虚拟屏 GUI / 云沙箱）由路由层选 | 印证「GUI 是兜底执行体而不是独立产品」；我们从第一天就放在路由层 |
| CLI 风险分级 + 权限动态绑定任务进程 + 高风险用户确认 | 许可组件：授权卡由中枢生成投递、一次性凭证、模型不在批准循环里；污染状态 | 小艺已做「分级 + 最小权限 + 确认」；我们要多做「谁弹确认卡」（不是模型）和「读了不可信内容后失去自动放行」 |
| 执行过程用户实时可见、可介入 | 控制表面：Goals 页 / 活动日志 / 审批卡 / 收件箱 | 一致；我们把它和全双工语音的关系表面明确分开 |
| HPIC：云侧与端侧同级隐私 | 云沙箱只做一条车道；端侧记忆端侧加密 | HPIC 解决的是「上云也安全」；我们的默认是「能不上云就不上」，两者互补 |
| 伴随式 AI：屏幕静止即读屏、主动建议 | 全双工 omni 前台 + 打扰管理器分级 | 小艺的主动是「弹卡片」；我们的主动多一个语音出口，因此必须有 speak_now / speak_at_pause / push / digest / hold 分级 |
| 入口：导航条、电源键、圈选、拖拽、Chips | 全双工语音为主入口 + 屏幕语义 | 小艺的入口矩阵是 OS 厂商才有的，值得对齐补齐 |

## 6. 开放问题（对华为公开材料而言）

- 双循环的实现：外循环的「反思自迭代」改的是提示、技能库还是路由策略？是否有回滚与灰度？
- 快慢分流由谁判定（规则 / 分类器 / 主模型），误分流如何纠正？
- 「复杂任务成功率 90%+」的任务集与口径。
- 小艺帮帮忙后台执行的机制（是否虚拟显示 + 事件注入）；HarmonyOS 7 上开放给开发者的 GUI 操控能力与之是否同一套。
- 「全天候智能感知引擎」的定义、功耗与隐私边界。
- 200+ 系统级数据的授权粒度与撤销方式。
