## 0. 已确认的口径与假设

| 项 | 约定 |
| --- | --- |
| 物理排布 | 三层物理块,tools 无法插入 SP 中间。当前 `SP → Tools → UAT`;目标 **`Tools → SP → UAT`**(Tools 移到最前,需 chat template 支持——自建集群可控,DeepSeek V4 / GLM 5.2 默认模板为 SP → Tools,见 06) |
| 分级 | 四级:产品级 / 会话级 / query 级 / loop 级;对领导讲三级(产品 / 会话 / 轮次),轮次内细分 query 与 loop |
| 会话级 | 横跨 SP(记忆快照、已安装应用)与 UAT(历史最近 10 轮);会话创建时确定、会话内不变;上次会话的缓存按已超时计,**会话首调必算一次** |
| 对话历史 | 全部在 UAT,分两段:会话级历史(最近 10 轮)+ 本会话 UAT;两段都是**完整 U/A/T,不折叠** |
| 动态上下文 | 从 SP 下沉到 UAT,随每轮 U 追加;精简 4.5K → ~2K(高频 skill desc 预置进产品级、记忆/设备只注入增量) |
| 前台应用 | 随 U 带入,可每轮加 / 变化时加,均不影响缓存;唯一红线是不进 SP |
| 预置 skill | 假设不频繁变化(日级攒批发布),先不展开 |
| Tools | 目标态固定工具集、全网静态,物理上排在最前,**成为产品级,会话首调即命中**;工具定义进 skill 的细节不强调 |
| 触顶 / 裁剪 | 先不做触顶假设;裁剪放"其他" |
| 驻留 | 沿用 11 的无驻留假设(会话内不失效);跨会话按失效计 |
| 核心量 | 实际推理量(miss)= 输入 − 命中 = 白算 + 新增;验收 = 白算归零 |

## 1. 页序

### P1 上下文组成对比:当前 vs 目标 ✅ 已完成 v1.1

- **要点**:Tools 移到最前成为产品级,动态上下文下沉并精简;
  上半两根结构条按四级着色(当前 SP → Tools → UAT,目标 Tools → SP → UAT),
  下半"行 = 调用、列 = 位置"的阶梯矩阵把 UAT 按 Q 和 loop 展开,当前 / 目标上下对齐,格色 = 缓存命运。
- **读法**:Q1 首调两边都是会话首调必算,目标少算一个 Tools;loop 内两边全命中;差别全在 Q2 起的每个 Q 首调。
- **数据依赖(待补,页面留虚框)**:
  ① SP·会话级块内容与长度;② 历史 10 轮均值 / p90;③ 预置 skill N 与长度;④ 目标 Tools 长度;⑤ SP 固定内部构成。
  逐项口径见 [14-上下文组成实测数据需求.md](./14-上下文组成实测数据需求.md)。
- 文件:[上下文组成对比.v1.1.slides.html](./上下文组成对比.v1.1.slides.html)(v1 留档 history/,差异:目标态 Tools 位于 SP 之后)

### P2 分级管理与四个改造动作

- **要点**:四级定义表(位置 / 内容 / 确定时机 / 缓存命运);改造四句:
  ①按变化频率分级、前缀区只放会话创建时已确定的内容;②动态上下文下沉 UAT;③动态上下文精简 4.5K→2K;④Tools 移到最前(Tools → SP → UAT),成为产品级。
- **说明点**:为什么 query 级与 loop 级分开列(新增内容不同、病灶只在 query 级、统计口径已分首调 / loop、loop 级白算恒为 0 是报警线)。
- **数据依赖**:同 P1。
- 状态:待做。

### P3 命中率模型:每次调用算什么

- **要点**:每调用 miss 的通式——
  会话首调 = 会话级(SP 块 + 历史 10 轮)+ U1(Tools 为产品级,首调即命中);
  Q 首调(n≥2)= 上轮回复 + Uₙ(query + 动态增量);
  loop 调用 = A + T。
  命中率 = 1 − miss / 输入;当前 vs 目标的 miss 公式并列,给 Qn 的一条式子(替代 v1 P5 的 ΔS(n),固定项按新 Tools 长度重算)。
- **数据依赖**:P1 的五项 + 各段实测长度。
- 状态:待做;v1 P5 公式的 7K 固定项(动态精简 2.5K + Tools 解除连带 4.5K)需按目标 Tools 实测长度与当前 Q1 的 Tools 首调必算重算。

### P4–P6 分场景账目:任务(25%)/ 问答(47%)/ 闲聊(28%)

- **要点**:沿用 v1 P2–P4 的版式(逐 Q、逐调用,当前 / 目标同位对照,命中 / 白算 / 新增三色),
  数字按新口径重算:Q1 计入会话级首调必算;历史 10 轮作为独立段计入当前的连带白算;Tools 长度取目标值。
- **数据依赖**:P3 公式 + 业务占比(47/28/25)+ 轮数分布(51/20/9/5.5/3.5/11)+ 各场景沉淀速率(问答 ~10.5K / 任务 8.5K→3.5K / 闲聊 ~1K)。
- 状态:待做。

### P7 按会话长度汇总 + 整体结论

- **要点**:v1 P6 + P7 合并——按 Q 数分桶的节省率 / 算力占比 / 节省贡献;整体降幅一句话;三句给领导(钱省在哪 / 体验好在哪 / 还能更好)。
- **数据依赖**:P4–P6 结果。
- 状态:待做。

### P8 统计闭环:点位与自动化

- **要点**:沿用 v1.2 单页,bounds 顺序改为新排布——
  当前 `[SP固定末, 动态末, Tools末, 历史10轮末, 本会话历史末]`,
  目标 `[Tools末, SP固定(含预置)末, 会话级末, 历史10轮末, 本会话历史末]`;
  标签增加 `first_call`(会话首调)以便把"会话首调必算"从白算里剔除。
- 状态:待做(改动小)。

### P9 会话级预热:把会话首调必算挪到用户开口之前

- **要点**:会话级是唯一"必算但用户开口前已知"的内容。两次预热:
  ① 会话创建时,后台空 query prefill `[Tools][SP 固定 + 预置][会话级 SP][历史 10 轮]`,首调 miss 从"会话级 + 历史 + U1"降到只剩 U1;
  ② ASR 识别期间,再 prefill 到当前前缀末尾——防长间隔后被逐出,并把上一轮回复(输出 token,从未作为输入算过)提前算进去,query 落地时只剩 U 本身。
- **版式**:时间轴"会话创建 → 用户开口 → ASR 完成 → 首 token",标两次 prefill 的位置与各自挪走的 token 量;右侧 TTFT 前后对比。
- **数据依赖**:会话级块 + 历史 10 轮长度;prefill 吞吐(token/s);ASR 平均时长。
- 状态:待做。

## 3. 术语表(全篇统一)

| 术语 | 含义 |
| --- | --- |
| 产品级 | 全网相同、版本发布才变:Tools(目标态排最前)、SP 固定、预置 skill |
| 会话级 | 会话创建时确定、会话内不变:SP 内记忆快照 / 已安装应用,UAT 头部历史 10 轮 |
| query 级 | 每个 Q 追加一次:U = query + 动态增量 |
| loop 级 | 每次工具往返追加一次:A 工具调用 + T 工具结果 |
| 首调 / loop | 一个 Q 的第一次模型调用 / 其后每次迭代 |
| 会话首调 | 会话的第一次模型调用,会话级内容在此必算一次(可预热) |
| miss(实际推理量) | 输入 − 命中,引擎逐调用实报 |
| 白算 | 曾算过、因前缀被改写而重算的 token(可根除) |
| 新增 | 本次调用首次出现的 token(必算) |
| 动态上下文 | 当前在 SP 内每 Q 重写的块(skills 3K + memory 1K + device .5K);目标态精简为 ~2K 随 U 追加 |
