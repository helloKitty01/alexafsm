## 1. 统一口径(必须遵守)

1. **单位一律为 token**,用与推理侧相同的 tokenizer;
2. 对 **chat template 渲染后的最终序列**计数(含控制 token),不是原始文本 / JSON;
3. 分布字段给 **均值 / p50 / p90**;固定内容给单值;
4. 注明样本范围(时间窗、会话数、调用数);
5. 有裁剪 / 压缩触发的会话请在 note 标注占比,避免污染分布。

## 2. 分级与模块定义

物理序:当前 `SP → Tools → UAT`;目标 `Tools → SP → UAT`。
下表按目标态分级列模块,"当前对应"一列说明现网里它在哪、怎么识别。

| # | 级 | 模块 | 目标态位置 | 当前对应 / 怎么识别 | 需要的数据 |
| --- | --- | --- | --- | --- | --- |
| A1 | 产品级 | **Tools 块** | 最前 | 现网 tools 参数渲染后的段落。抽不同机型 / ROM 的会话对比:**工具清单是否全网一致**;若不一致,给变体数与各变体流量占比 | 工具清单(名称 + 单个 schema 渲染后长度)、总长、是否按 ROM / 已安装应用变化;目标态元工具集若已定义,同样给清单与总长 |
| A2 | 产品级 | **SP 固定** | Tools 之后 | system prompt 中**所有用户、所有会话逐字相同**的部分。抽 ≥3 个不同用户、不同日期的会话做逐字 diff,公共部分即 A2;**diff 出来的差异片段要单独列出**(这是"伪静态"体检:日期、用户名、随机排序等) | 总长(已知 25929)、**内部构成拆分**(角色设定 / 原则 / 输出规范 / 安全合规 / few-shot / 其他,各多长)、diff 差异片段清单 |
| A3 | 产品级 | **预置高频 skill desc** | SP 固定之后 | 目标态新增,现网无对应。需要 skill 调用频次数据来定 N | ① 近 30 天 skill 调用频次分布(按 skill 排序的累计覆盖率:top-5 / 10 / 20 / 50 各覆盖多少调用);② 单条 skill desc 渲染后长度分布;③ 当前 skill search 的 top-1 / top-3 命中率(若有) |
| B1 | 会话级 | **SP·会话级块** | SP 尾部 | 现网 SP 中**同一会话内不变、跨用户不同**的部分(user.md 等),加上目标态要放进来的记忆快照、已安装应用列表 | user.md(已知 313);记忆快照长度分布;已安装应用列表(应用个数分布 × 每条渲染后长度 → 总长分布);**会话中途是否会更新**(若会,频率) |
| B2 | 会话级 | **历史 10 轮 UAT** | UAT 头部 | 会话创建时从上次会话载入的最近 10 轮完整 U/A/T。识别:会话第一次调用的 messages 数组中、本会话 U1 之前的全部消息 | 总长分布(均值 / p50 / p90);其中 U / A / T 各占多少;实际轮数分布(不足 10 轮的会话占比);**是否完整 U/A/T、T 是否有单独裁剪** |
| C1 | query 级 | **U(query 本身)** | UAT 追加 | 当前每轮 user 消息(不含注入) | 长度分布 |
| C2 | query 级 | **动态上下文(当前在 SP)** | 当前 SP 内每 Q 重写段;目标下沉进 U | 相邻两个 Q 的 SP 逐字 diff,变化片段即 C2。拆成 available skills / memory / device_info 三项 | 三项各自长度分布(已有粗值 skills 2877–3565 / device 259–310 / memory 假设 1K,需 memory 实测);**每轮相对上轮真正变化的比例**(决定目标态增量注入能压到多少) |
| D1 | loop 级 | **A(assistant,含 tool call)** | UAT 追加 | 每次 loop 迭代的 assistant 消息 | 长度分布;若含 reasoning,注明模板是否剔除历史 reasoning(见 06 §3) |
| D2 | loop 级 | **T(tool result)** | UAT 追加 | 每次 loop 迭代的 tool 消息 | 按类型分:skill 正文 load / 普通工具结果 / webSearch,各自长度分布(已有粗值 5K / 3K / 10K) |
| D3 | loop 级 | **最终回复 answer** | UAT 追加 | 每个 Q 最后一次 assistant 消息 | 长度分布(已有粗值 ~0.5K) |

## 3. 会话形态与引擎侧(用于 P2–P7)

| E6 | prefill 吞吐(token/s,目标机型与并发下) | P2 方案 A 时延换算 |
