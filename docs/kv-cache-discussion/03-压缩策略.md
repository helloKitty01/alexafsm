# 03 压缩策略：从远到近压缩的缓存代价与改进

## 事实：压缩必然全量 miss，无法避免，只能摊销

"从远到近"压缩改写的是可变区最前端的 token，其后（几乎整个对话历史）的缓存
全部失效。这在机制上无解——所以压缩策略的目标不是避免 miss，而是：

1. **降低 miss 频率**（低频、大幅度地压）；
2. **提高摘要质量**（miss 的真正代价是信息丢失，不是那一次 prefill）。

## 反模式：滚动摘要 / 每轮修剪

- 每轮更新一个位于前部的 summary 块：summary 每轮变 → 每轮全量 miss，最差方案。
- 每轮删一点最旧消息（滑动窗口逐步前移）：同样每轮 miss。

## 推荐:阈值触发 + 低水位 + 分代冻结

### 触发与幅度（hysteresis，双水位）

- 高水位触发：上下文达到容量的 ~75–80% 才压缩。
- 一次压到低水位：如 ~40%。避免"压一点 → 很快又满 → 再压"的抖动。
- 一次 miss 换后续几十轮 hit，成本上几轮即回本（见下方算账）。

### 分代冻结（generational）

压缩产物（摘要块）写入后**冻结不再改动**，成为新的稳定前缀的一部分；
下次压缩时，把"上一代摘要 + 其后的一段老历史"合并为新一代摘要。
效果：两次压缩之间的所有轮次，前缀完全稳定，全部命中。

```text
[L0/L1 稳定头] [G2 摘要(冻结)] [G1 摘要(冻结)] [原文历史…追加中…]
                     ↑ 下次压缩时才把 G1 + 一段原文合并成 G2'
```

### 从远到近的分层保真（不均匀压缩）

- 最远端：结构化摘要（目标/已完成/关键结论/待办/涉及的文件与 ID）。
- 中段：保留 assistant 的决策消息，把大体积 tool result 替换为
  "结果指针"（如文件路径、检索 ID）——**可恢复**，需要时重新读取。
- 近端（最近 K 轮）：原文保留，这是下一步决策的直接依据。

### 工程细节

- 压缩边界对齐消息边界，绝不截断 tool call / tool result 配对。
- 所有"重写历史"的操作（截断旧 result、替换占位符）攒到同一次压缩时一起做，
  一次 miss 付清所有账，不要分散执行。
- 压缩时机尽量选在子任务完成的自然边界，此时摘要质量最高、丢细节风险最小。

## 比压缩更优先：少往上下文里塞

- **文件系统作外部记忆**：大 tool result（网页全文、日志、大文件）落盘，
  上下文只留路径 + 摘要。可恢复，和摘要的不可逆丢失有本质区别。
- **子 agent 隔离**：探索/搜索类脏活交给子 agent 烧自己的上下文，
  只把结论带回主 loop。
- **工具输出自身精简**：分页、截断、摘要 + 引用，而不是先塞进来再压。

## 成本算账（示意）

设上下文 50k token，缓存价 0.1x：

- 不压缩：每轮 50k 全命中 ≈ 5k 等效 token/轮。
- 压到 20k：压缩轮 20k 全 miss（等效 20k），此后每轮 ≈ 2k。
- 约 5–6 轮回本，之后每轮省 60%。**结论：只要压缩后还能跑较多轮，
  成本上几乎总是划算；设计重心应放在摘要的信息保真上。**
