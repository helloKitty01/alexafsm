## 0. 两个必算口径（全稿统一叫法）

| 叫法 | 构成 | 数值（n≥2） | 决定什么 |
| --- | --- | ---: | --- |
| **首调必算** | 动态 3.5 + query 0.1 + 上轮 answer 0.25 | **3.85K**（页面显示 3.9K） | 该轮第一次模型调用的 prefill → **TTFT** |

## 1. 账目逻辑与目标（P2 底部两行）

**第一行 · 账目逻辑**

- ① 输入 = 已缓存 + 白算 + 必算。已缓存 = 前缀逐 token 一致的深度；白算 = 本该命中却因前缀改写而重算；必算 = 本次必要新增。
- ② **实算** = 白算 + 必算 = 输入 − 已缓存。prefill 真正计算的量，账单与 TTFT 跟它走。
- ③ **cache 命中率** = 已缓存 ÷ 输入。业界通用健康度；分母含必算，必算越多命中率越低，按业界口径一并报。

**第二行 · 目标与衡量**（演示会话 6 次调用）

| 目标 / 尺子 | 数值 | 说明 |
| --- | ---: | --- |
| 目标 ① 白算 → 0 | 88.2K → 0 | 验收线；目标态 loop 白算 > 1 块即报警 |
| 目标 ② 必算尽可能小 | 38.5K = 38.5K | 整轮必要新增，两边相同；下一步靠 available skills 升会话级、工具结果精简 |
| 成本看实算降幅 | 126.8K → 38.5K（−70%） | 省额 = 白算；Q≥2 首调 25.8–34.2K → 3.9K |
| cache 命中率 | 67% → 91%（全业务加权；演示会话 6 次调用为 63% → 89%，页面不显示） | 受必算拖累；长会话单轮到 95% 左右，1Q 83%，一半会话只有 1 轮 |

### 4b. 首调 TTFT 预估（P3 右列表）

TTFT ≈ 首调实算 × 46 ms/K（参考实测 14K prefill ≈ 640 ms），线性折算；loop 两边相同、不变。**预热后统一按 170 ms**：实时只剩动态 + query ≈3.6K ≈165 ms，加预热自身损耗取整。

| 轮次 | 当前首调实算 → TTFT | 目标 | 目标 + 预热 |
| --- | ---: | ---: | ---: |
| Q1（会话首调） | 15.0K · 690 ms | 9.1K · 420 ms | 170 ms |
| Q2 | 22.3K · 1.0 s | 3.9K · 180 ms | 170 ms |
| Q6 | 50.6K · 2.3 s | 3.9K · 180 ms | 170 ms |
| Q12 | 93.0K · 4.3 s | 3.9K · 180 ms | 170 ms |

**预热定义**：会话创建时 prefill 会话级 + 历史（5.5K）；每轮用户开口前（ASR 阶段）再灌上轮 answer，实时只剩动态 + query。**收益 / 代价**（参考实测）：14K 一次 640 ms → 6K 预热 320 + 8K 实时 380 ms，感知 TTFT −40%；两次 prefill 总算力 700 ms（+10%）；预热到开口之间要靠 TTL 保住缓存。只改 TTFT，不改账。

## 6. 三句话（P3，大数字 + 一句）

1. **会话数 10% / 算力 54%**（两行迷你横条）：6Q+ 的长会话只占 10% 的会话数，却吃掉 54% 的算力，贡献 65% 的节省；越长省得越多，Q2 −64% → Q12 −89%。
2. **3.9K**：会话级可提前算，首调时延与轮数脱钩。Q≥2 首调钉在 3.9K（当前 22–93K 随轮涨）；加预热后所有轮次 TTFT ≈ 170 ms。
3. **白算 → 0**：验收线；整轮必算 10.6K 是剩下的全部成本，available skills 3K 若升为会话级、首调必算 → 0.9K。命中率受必算拖累，长会话单轮到 95% 左右，加权 91%。

## 7. 口径边界（页脚已写）

1. −65%（全业务）/ −70%（演示会话）是**实算 token** 降幅；费用按实际计价折算，TTFT 由实测验证。
2. cache 命中率全业务加权 91%：会话首调 5.5K、webSearch 10K 是必算，一半会话只有 1 轮；长会话单轮到 95% 左右。**验收看白算归零，命中率按业界口径一并报。**
3. 前提是会话内缓存不被逐出。实测 21 次调用里 2 次 loop 全 miss 属引擎侧逐出 / 路由，需会话粘性 + TTL 配合并单独报警。
4. ≥11 轮按 12 轮计是下限口径，不外推。
5. TTFT 按 46 ms/K 线性折算、预热后统一 170 ms，待 E6 实测替换。
6. 未计入：available skills 升会话级、动态"只带变化"可再压必算，是下一步。上线后由日报（引擎 `cached_tokens` + 应用边界埋点）替换推演。
