# 18 · 三页汇报版（v3.2）账目与公式底稿

> `kv cache方案（汇报版）.v3.2.slides.html` P2 / P3 的数据底稿。全部数字由 [16](./16-数据基线-优化后.md) / [17](./17-数据基线-优化前.md) 的基线算出，页内 `BASELINE` 对象即同一份数；改基线一处、全稿同步。
> 单位 K token。口径：两边同内容只换排布；会话内缓存不被逐出；无裁剪；不计块粒度误差。

## 1. 恒等式（P2 底部一行）

- 输入 = 已缓存 + 白算 + 必算
- **实算** = 白算 + 必算 = 输入 − 已缓存（真实 prefill，账单与 TTFT 跟它走）
- 白算 = 本该命中却重算（Tools、会话级、历史、本会话已写内容被前缀改写连带）；排布改造只动这一项
- 必算 = 本次真新增（动态、query、tool call、工具结果、上轮回复）；**两边相同，不记成绩**
- 命中率 = 已缓存 / 输入（健康度，不是钱）
- 验收 = 白算 → 0；loop 白算 > 1 块即报警

## 2. 三类业务每 Q 的必算与沉淀

| 类型 | 占比 | 调用链 | 每 Q 必算（n≥2） | 当前方案下沉淀进 UAT |
| --- | ---: | --- | ---: | ---: |
| 问答 | 47% | 调① tool call → 调② webSearch 10 + answer | 3.28 + 10.2 = **13.48** | 0.03 + 10.2 + 0.25 = **10.48** |
| 任务 | 25% | 调① tool call → 调② SkillLoad 5 + 工具 2.5 + answer | 3.28 + 7.7 = **10.98** | 0.03 + 7.7 + 0.25 = **7.98** |
| 闲聊 | 28% | 调① answer | **3.28** | 0.03 + 0.25 = **0.28** |

3.28 = 动态 3 + query 0.03 + 上轮 answer 0.25。当前方案里动态在 SP 内原位重写、不进 UAT，所以沉淀不含动态；目标方案动态留在 U 里，输入每 Q 多 3K，已计入命中率分母。

加权：每 Q 必算 T(n≥2) = **10.0K**；沉淀速率 α = 0.47×10.48 + 0.28×0.28 + 0.25×7.98 = **7.0K/轮**；加权 loop 新增 = 0.47×10.2 + 0.25×7.7 = 6.72K。

## 6. 口径边界（页脚已写）

1. −59%（全业务）/ −71%（演示会话）是**实算 token** 降幅，费用按实际计价折算，TTFT 由实测验证。
2. 命中率全业务加权到不了 95%（89%）：会话首调 8.5K、问答 webSearch 10K 是必算，且一半会话只有 1 轮；长会话单轮才到 95%+。**验收看白算归零，不看命中率。**
3. 前提是会话内缓存不被逐出。实测 21 次调用里 2 次 loop 全 miss 20K+ 属引擎侧逐出 / 路由，排布改不了，需会话粘性 + TTL 配合并单独报警。
4. 未计入：动态"只带变化"可再压目标每轮实算，是上行空间。上线后由日报（引擎 `cached_tokens` + 应用边界埋点）替换推演。
