三句话

6Q+ 占当前算力

算力在长会话,不在会话数。6Q+ 只占 的会话数,却占当前算力 、贡献 的节省;每轮节省率单调上升,第 2 轮 −、第 6 轮 −;6–10Q 会话 −、11Q+ −。

Q≥2 首调必算

会话级可提前算,首调时延与轮数脱钩。Q≥2 首调只剩 必算(当前 – 随轮涨);Q1 首调 里 是会话级 + 历史,会话创建时已定,可在用户开口前预热,实时只剩 。收益 / 代价(参考实测):14K 一次 640 ms → 拆 6K 预热 + 8K 实时 = 320 + 380 ms,感知 TTFT −40%;总算力 700 ms(+10%),且预热到开口之间要靠 TTL 保住缓存。只改 TTFT,不改账。

白算 → 0命中率 →

白算归零是验收线,必算是下一步。白算由排布造成、可归零,本次收益全部来自它;必算是必要新增、两边相同,不记本次成绩,但它是剩下的全部成本,下一步压它(动态只带变化、工具结果精简)。cache 命中率按业界口径一并报:受必算拖累(会话首调 、webSearch 在分母),长会话单轮到 95% 左右,1Q ,全业务加权 。

加权总公式:整体实算降幅 = Σ(会话数 × 每会话节省)/ Σ(会话数 × 当前每会话实算),先汇总量再除;命中率同法(已缓存与输入分别汇总再相除)。≥11 轮按 12 轮计:当前侧首调输入到第 12 轮已 ~124K、128K 窗口填满,再往后必然裁剪,取下限不外推。前提:会话内缓存不被逐出(实测 21 次调用里 2 次 loop 全 miss 属引擎侧逐出 / 路由,需会话粘性 + TTL 配合,单独报警)。TTFT 按参考实测线性折算,待 prefill 吞吐实测(E6)替换。上线后由日报(引擎 cached_tokens + 应用边界埋点)替换推演。
