止血项:device_info 若每次调用刷新,任务型受害最大

对单轮会话的正确预期

单轮会话(-27%)的收益 = Tools 解除连带 + 新增底线内的优化;它的主要改善在时延(首调用现算量下降)而非总量。不要用单轮场景评估这项改造的价值。

读法:轮数分布把整体节省定格在 -53%;它不是均匀分布的——长会话(重度用户)节省 -64%,正是成本和体验痛点所在;单轮轻用户几乎无感知成本变化,但首响应更快。

收益结构一页话(给领导的三句)

  • 钱省在哪:整体 -53%;长会话(11%)节省 -64%、贡献一半节省额——重度用户的成本痛点被精准解决;
  • 体验好在哪:TTFT ∝ 现算量,稳态轮次首调用闲聊 -85% / 任务 -68% / 问答 -63%,越深的对话提速越明显;
  • 还能更好:两个放大器不在 -53% 内——device_info 止血(loop 若确在断,现状比建模更差、实际节省更大)、检索/skill 大块指针化(问答 -50%→~-80%)。

改造动作(对应收益来源)

① query 级(skills/memory/device)下沉消息流 → 消灭每轮重写;② Tools 解除连带(前缀纯静态);③ 裁剪改造:攒批 + 指针化,不再高频打断前缀;④ device_info 每 query 采样、loop 内冻结。
