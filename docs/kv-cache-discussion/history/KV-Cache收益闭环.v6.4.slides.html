问答的收益结构:两段式,且占比最大

排布改造只消灭"重复计算";10K 检索是每轮新增底线,占目标态 11.5K 的 87%——降幅封顶 -67%,但问答占流量 47%,绝对节省量是三类之最(轮 3 每轮省 23.5K),同时它的"新增底线"也是拉低整体降幅的主因。

再往下降:抬结构上限的两条手段

① 检索结果落盘 + 指针化:全文落盘,上下文只注入高相关段(10K→3~5K),稳态可再降至 ~-85%;
② 裁剪时 webSearch 结果退化为指针(可 re-fetch):问答沉淀 11.5K/轮,是 history 触顶的主要制造者,大块反复裁剪 = 反复打断前缀。

对单轮会话的正确预期

单轮会话(-28%)的收益 = Tools 解除连带 + 新增底线内的优化;它的主要改善在时延(首调用现算量下降)而非总量。不要用单轮场景评估这项改造的价值。

收益结构一页话(给领导的三句)

  • 钱省在哪:整体 -60%;长会话(11%)节省 -71%、贡献一半节省额——重度用户的成本痛点被精准解决;
  • 体验好在哪:TTFT ∝ 现算量,稳态轮次首调用闲聊 -88% / 任务 -80% / 问答 -67%,越深的对话提速越明显;调用怎么拆不影响算力、只影响时延;
  • 还能更好:两个放大器不在 -60% 内——device_info 止血(loop 若确在断,实际节省更大)、检索指针化(问答 -53%→~-85%)。

改造动作(对应收益来源)

① query 级(skills/memory/device)下沉消息流 → 消灭每轮重写;② Tools 解除连带(前缀纯静态);③ 裁剪改造:攒批 + 指针化,不再高频打断前缀;④ device_info 每 query 采样、loop 内冻结。
