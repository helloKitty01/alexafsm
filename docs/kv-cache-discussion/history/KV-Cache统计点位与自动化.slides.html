核心机制:断点归因——白算构成自动拆解,无需人工

边界:b₁ SP固定末 < b₂ 动态末 < b₃ Tools末 < b₄ history末 < b₅=prompt_tokens
断点:d = cached_tokens
miss = b₅ − d = 白算(b₄ − d) + 新增(b₅ − b₄)
白算 ∩ 各模块区间 → 自动拆出 [动态 | Tools | history] 三段

三条自动报警(防回退验收线)

① loop 调用白算 > 0:追加式本该恒零,出现即回归(device_info 刷新/序列化不稳);
② 改造后白算 > 1K/调用:违反"除新增外全命中"验收线;
③ 公式残差超限:实测每 Q 节省偏离 7+6.1(n−1) 过多 → 参数漂移(如 webSearch 变大),提示更新基线。

一句话:引擎给"断点",应用给"边界",两者相减自动完成 miss 的全部归因——收益不靠估算,每天以日报形式自证;改造上线前先跑一周,基线实测替换推演,灰度 A/B 直接出最终收益数。
