# 17 · 数据基线（优化前）

> 改造前物理序（动态仍在 SP）。四列，**从上到下 = 送给模型的顺序**。单位 K token。
> 长度全部为确定数，**与优化后（16）逐项相同**：Tools / SP / 会话级 / 动态等实测里前后差的几百 token 属内容改版，不是排布方案带来的，对比时统一取一个数。
> 对应 `token_breakdown.csv` before 侧的结构；账目见 [18](./18-三页汇报版账目与公式.md)。

`SP（固定 → 动态 → 会话级）→ Tools → UAT（历史 → U query → A tool call → T → A answer）`

| 序号 | 名称 | 解释 | 长度 |
| --- | --- | --- | --- |
| 1 | SP·固定 | 14 个 `##` 段。版本发布才变，本身可命中；**断点恒停在它末尾**，其后整段被连带白算。 | **28.9K** |
| 2 | SP·动态 | 写在 SP 中部的 available skills + MEMORY.md。每 Q **原位重写**，缓存从这里断，Tools + 全部 UAT 一起重算。 | **3K** |
| 3 | 会话级上下文 | SP 尾：user.md + DEVICE_INFO 等。会话内不变；排在动态之后，每 Q 被 #2 连带白算。 | **1.5K** |
| 4 | Tools | 12 个工具 schema，API 独立字段，chat template 拼在 SP 之后、UAT 之前。内容稳定，但在动态后面，每 Q 被连带白算。 | **5.9K** |
| 5 | 对话历史 1–10 轮 | UAT 头，上一会话载入的完整 U/A/T。会话内只追加；排在 Tools 之后，每 Q 首调被连带白算。 | **7K** |
| 6 | UAT-U query | 当轮用户原话。动态不在 U 里，这一条是纯 query。必算。 | **0.1K** |
| 7 | UAT-A（tool call） | 当轮 assistant 发出的工具调用（函数名 + 参数）。必算。 | **0.2K** |
| 8 | UAT-T（工具结果） | tool result。必算。下面三行是类型，当轮调了哪类就算哪类；与优化后同长。 | 按 8.1–8.3 |
| 8.1 | └ webSearch | 检索类大结果。 | **10K** |
| 8.2 | └ SkillLoad | skill 正文首次 load。 | **5K** |
| 8.3 | └ 正常工具 | OpenApp / exec / PersonalContextSearch 等业务工具返回。 | **2.5K** |
| 9 | UAT-A（最终 answer） | 该 Q 最后一条 assistant 回复。必算。闲聊无工具，整轮 A 约等于本行。 | **0.25K** |

Q≥2 首调实算 = 白算（Tools 5.9 + 会话级 1.5 + 历史 7 + 本会话已写 UAT）+ 必算（动态 3 + query 0.1 + 上轮 answer 0.25）。实测 Q 首调 miss 里白算占 90–99%，与此一致。
