# 基线模板 v2（0921 实测）

> 数据源：`结果分析/20260921/` 7 个 trace（Q1×3 + Q10×2 + Q11×2），promptKvCache 变体
> 提取脚本：`结果分析/20260921/_extract_segments.py`

## 物理顺序

```
SP正文(M2+M4) → Tools块(M1) → developer消息(M7) → user查询(M6) → 历史/当轮交互(M8+M9)
                                                                ↑ M5=此前所有消息累积
```

每个 query 自带独立 developer 消息（M7），无单独预载历史块。M7 的 skills 列表每 query 变化，是 cache 断点。

## Cache 行为

- **块粒度**：4096 tok/块（DS-V4），cache_read 均为 4096 整数倍
- **断点**：M7（developer 消息），新 query 的 skills 列表变化致断裂
- **同 Q loop**（如 q1-i2→i3）：miss ≈ 新增 M8+M9（前缀只增不改）
- **新 Q 首调**（如 q10-i2）：miss ≈ 上一轮回复 + 新 M7 + M6
