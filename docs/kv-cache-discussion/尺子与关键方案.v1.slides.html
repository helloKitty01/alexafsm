① 该命中 / 命中量
cached_tokens = d
前缀逐 token 一致的深度。目标态:产品级全网命中;会话级首调后命中(可预热提前算完);query / loop 只命中已写入的历史。
② 命中率 = 被 cache 的比例
命中率 = d / 输入
健康度。分母随业务和轮数漂,率折算不成钱。目标态随轮数上升(分母变大、分子几乎只增当轮新增);当前从 Q2 起被橙带压住。
③ 推理长度 = miss
miss = 输入 − d
真实 prefill,账单和 TTFT 跟它走。= 白算 + 新增。省的是 Q 首调里那条随轮数变长的橙带。
④ 验收
白算 → 0
白算 = miss − 新增。loop 白算恒为 0是报警线;会话首调的会话级块算新增不白算(可预热挪走)。

该命中什么(目标态纪律)

产品级 · 全网

Tools + SP 固定 + 预置 skill。任何用户任何会话都该命中,只在版本发布时全网重算一次。

会话级 · 首调后

SP 会话块 + 历史 10 轮。会话创建时已确定;首调算一次,其后全命中。跨会话按超时失效。

query / loop 追加区。已写入的 U/A/T 全命中;当轮新增(Uₙ / A+T)必算,这是成本底线。

方案 B · 减输入

高频 skill 预置

top-N 高频 skill 描述放进产品级前缀,日级攒批发布、不频繁变。available skills 不再每 Q 往 SP 里塞 3K。

效果:动态上下文 4.5K → ~2K 里,skill 段从 ~3K 压到引用;少一次 load 往返。N 由覆盖率曲线定(14 · A3)。
方案 C · 减新增

动态上下文只更新变化

记忆 / 设备 / 前台应用随 U 追加增量,与上轮相同则省略。不回改历史、不每轮重贴全量。

效果:不破缓存(本来就在 U 尾部);输入不再线性膨胀。前台应用"有变化再加"即此条。
怎么读后面的场景页:每页同时给命中率(健康度,目标随 Q 上升、当前从 Q2 被压住)和推理长度(钱,当前随 Q 线性涨、目标钉死在当轮新增)。方案 A 改善的是 Q1 / 每 Q 的 TTFT,不改变 P3–P5 的"无预热"账本;方案 B+C 直接改动态长度,会进账本。预热吞吐与 ASR 窗口见 14 · E6–E8。
口径:无触顶、无驻留(会话内);跨会话按失效。v1 ΔS(n)≈7K+6.1K×(n−1) 系数待 Tools / 历史 10 轮实测后回填。
