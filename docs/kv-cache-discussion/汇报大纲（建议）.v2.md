# KV Cache 优化：汇报大纲（建议）v2

> 三页汇报结构：全局数据基线 → 当前与目标方案及混合会话效果 → 全业务收益与轮数曲线。第一页保留备查，现场可从第二页开始讲。本文为制作大纲，暂不修改已有幻灯片；上一版大纲原位保留、不作改动。

## 已对齐的核心口径

- **skill preload：** 搜索引擎根据当前问题及必要上下文提前检索所需 skill，并在首次模型调用前注入所需内容，省去大模型生成 `skill load` 请求的调用。它不等同于把所有 skill 全量预置，也不等同于提前计算 KV 的缓存预热。
- **场景占比按 Q 统计：** 一个用户问题记为一个 Q，标注任务／问答／闲聊；一个会话可以包含多种场景。一次 Q 可以包含多次大模型调用。
- **资源收益按大模型调用记账：** 分别累加当前与目标方案下的全部模型调用，再汇总到 Q、会话和业务。允许两个方案的调用次数不同；不能只比较每次调用的平均开销，也不能把 Q 数直接当成调用数。
- **对比条件：** 完成同一批用户问题，任务效果相当，使用明确的模型、tokenizer、缓存条件及方案版本。数据标注为实测／目标／假设／待补，不能将推演写成已实现收益。

## 第 1 页｜全局数据基线

**本页职责：为全稿提供唯一参数来源。可以不口头展开，但必须保留，后续柱图、公式、曲线与指标均由此计算。**

### 布局

上方约 55% 为「当前／目标模块基线」；左下约 25% 为「运行时增量与调用路径」；右下约 20% 为「业务与会话分布」。详细来源可放备注，主页面保留参数 ID、值及状态。

### 内容 A：当前与目标模块基线

逐项列出当前位置与长度、目标位置与长度、变化频率、复用范围及数据状态：

- 固定系统规则与策略。
- Tools 定义：与运行时工具调用参数、返回结果分开统计。
- skill 描述／索引：与检索加载的 skill 正文分开统计；是否保留、预置多少由方案确定。
- 用户画像、设备信息、会话级记忆。
- 会话起始携带的历史上下文。
- 动态内容：当前全量长度、目标每次变化量。
- 运行中累积的 U／A／T 历史：由逐调用数据派生，不与起始历史重复计入。

长度统一为模型对应的 token 数；不同模型分别记录，不直接把字符数当 token。可复用、首次载入、每 Q 更新与每调用新增分别标注。

### 内容 B：运行时增量与调用路径

记录典型值和分布范围：用户问题、模型输出（含可取得的推理 token）、skill 正文、业务工具参数与返回、webSearch 返回、动态更新内容。另记录 skill preload 的覆盖率、检索失败／误检后的回退调用次数和额外注入量。

典型路径作为可替换的基线假设：

- **问答：** 模型生成 webSearch 请求，结果返回后模型回答，通常 2 次模型调用。
- **任务当前：** 模型生成 skill load 请求，加载正文后模型生成业务工具请求，工具返回后模型回答，通常 3 次模型调用。
- **任务目标：** 搜索引擎提前检索并注入 skill，模型生成业务工具请求，工具返回后模型回答，成功 preload 时通常 2 次模型调用。
- **闲聊：** 模型直接回答，通常 1 次模型调用。

上述是用于讲解的典型路径，不代表每个 Q 都如此。实际多工具、多 loop、重试及 preload 回退均按日志纳入。

### 内容 C：业务与会话分布

- 任务／问答／闲聊占比：分母为全部 Q 数。
- 会话轮数分布：分母为会话数，保留长会话尾部，不只给平均轮数。
- 各场景每 Q 模型调用次数分布，以及不同轮次的场景组合／顺序。
- 缓存可用性：轮间间隔、冷启动、淘汰、实例路由、版本变化、上下文裁剪等。
- 若需报告推理资源或费用，补充逐调用 GPU 时间／资源模型或实际计价；实算 token 降幅不能直接视作全部推理资源降幅。

## 第 2 页｜当前与目标方案：一段混合会话的效果对比

**本页结论：通过稳定复用减少白算、精简注入减少新增，并通过 skill preload 减少模型调用，最终降低完成同一任务的总开销。**

### 布局

- 顶部约 20%：当前／目标上下文排布及优化动作。
- 中间约 60%：Q1 问答、Q2 任务、Q3 闲聊的逐调用横向柱状图。
- 底部约 20%：实算／必算／白算、调用数及收益汇总。

### 上部：方案对比

将方案归为三个收益来源：

1. **白算趋近于 0：** 稳定内容前置，动态内容后置，历史只追加，并保证可复用缓存实际可用。
2. **必要新增尽可能小：** 动态只传变化，相同内容不重复注入，skill 与工具结果按任务需要精简。
3. **减少模型调用：** 搜索引擎提前检索 skill，省去模型主动发起 skill load 的调用。

整体收益直接比较当前与最终目标。若拆分各项贡献，按固定顺序与上一步做差，避免重复计入同一段收益。

### 中部：混合会话与柱状图

- **Q1 问答：** 当前、目标均展示「生成 webSearch 请求／收到结果后回答」两次模型调用。
- **Q2 任务：** 当前展示「生成 skill load／生成业务工具请求／收到结果后回答」三次调用；目标展示模型调用之前的搜索引擎 preload，以及后续两次模型调用。
- **Q3 闲聊：** 当前、目标各展示一次模型调用，体现前两轮历史在后续的复用。

该典型示例合计 **3 个 Q，模型调用数 6 → 5**，以 preload 成功且无额外回退为前提。调用数下降约 16.7%，不等于推理资源下降 16.7%。搜索引擎操作画成独立流程标记，不画成模型调用柱。

图形规则：

- 每条横柱代表一次模型调用的完整输入，所有调用采用同一 token 比例尺。
- 绿色＝已缓存，红色＝白算，蓝色＝必算。首次载入在蓝色内用纹理或标签区分。
- 按业务阶段对齐当前／目标；目标省去的 skill load 调用标「无需此模型调用」，不伪造一条命中率为 100% 的零成本调用。
- skill 正文、webSearch 结果及业务工具返回首次进入模型时计入必算，后续具备复用条件时转为已缓存；preload 不会让 skill 正文的首次处理自动免费。
- 目标注入内容变化时，按目标真实输入长度画柱，不强制两方案总长度相等。
- 各 Q 小计、全会话合计均覆盖其全部调用。当前数据和目标推演分别标识。

### 下部：概念与指标

讲解口径：必算＝本次必要新增、需新建 KV 的部分；白算＝本应复用却再次计算的部分；实算＝实际未命中的输入 token。

**输入 I＝已缓存 H＋白算 W＋必算 N；实算 M＝I−H＝W＋N。**

**命中率＝H／I；最低实算比例＝N／I；最高命中率＝1−N／I。** 理论边界针对给定输入和可复用条件，不跨方案固定分母。

底账需保证守恒：重复注入等可精简内容单列明细，不能宣传成不可避免的必要新增；冷启动与块粒度损耗标注清楚，未归因量不得直接认定为可消除白算。仅在历史不变且持续追加时，才可用输入长度差近似新增。

主指标展示：当前／目标累计实算、累计必算、累计白算，以及累计实算降幅。辅助展示模型调用数、输出／推理 token 和加权缓存命中率（ΣH／ΣI），不平均各次调用的命中百分比。

## 第 3 页｜全业务收益与对话轮数曲线

**本页结论：按 Q 描述业务构成，按每次模型调用计算开销，再按真实会话分布汇总，才能得到整体收益。**

### 布局

左侧约 60% 放收益曲线，右侧约 40% 放业务分布与加权结果；底部放总公式、数据状态及关键假设。

### 公式：先逐调用记账，再汇总

设方案 x 为当前或目标，s 为会话，q 为用户问题，j 为该 Q 内的模型调用；K(x,s,q) 为该方案该 Q 的实际调用次数。

```text
每次调用实算：M(x,s,q,j) = 输入 I(x,s,q,j) − 命中 H(x,s,q,j)
会话累计实算：C(x,s) = Σq Σ[j=1…K(x,s,q)] M(x,s,q,j)
整体实算降幅：R = 1 − Σs C(目标,s) / Σs C(当前,s)
```

两方案使用同一批会话／Q，调用次数可以不同。这样 skill preload 省去的模型调用、保留调用中变化的输入、缓存收益都会自然进入总账，不能再额外加一次「省掉调用」收益。

若按会话分组推演，g 表示「轮数＋场景组合／顺序」分组，p(g) 为会话占比：

```text
整体实算降幅 = 1 − Σg p(g) × C(目标,g) / Σg p(g) × C(当前,g)
```

场景占比按 Q 统计，用于构造或校验这些会话组合，不直接充当会话权重。只有场景占比和轮数分布时，需明确各轮场景分配假设；正式结果优先用实际会话序列，纳入 preload 覆盖率与回退路径。

若要给出**整体推理资源降幅**，为每次调用取得一致口径的资源量 G（如 GPU 秒，或按输入长度、命中长度、输出／推理 token、模型及运行条件校准的资源估计），将上式中的 M 换成 G 后求和。仅有 token 数据时，分别报告未命中输入、输出／推理 token、调用数变化，不把这些不同指标直接相加成一个资源百分比。搜索引擎检索的新增成本另列，端到端净收益时纳入。

### 收益曲线

- 横轴：会话轮数 n。
- 纵轴：截至第 n 轮的**累计实算降幅**，先展示可计算、可核验的指标；有 G 的测量或校准后，另给累计推理资源降幅。
- 三条细线：典型任务、问答、闲聊会话；一条强调线：按业务 Q 构成及场景顺序假设计算的混合会话。
- 每个曲线点包含前 n 轮全部模型调用、首调成本及目标新增输入；不按各轮降幅作简单平均。
- 右侧结合真实轮数分布，展示整体加权结果和长会话节省贡献。业务构成相同但长会话占比不同，整体收益也会不同。
- 曲线从第一页参数生成。不能预先承诺单调增长、固定每轮成本或直接延用旧稿的「69% 下限」；缓存失效、裁剪、工具结果大小及 preload 回退均会改变曲线。

### 收尾与验收

理论推演说明收益机制与潜力，真实分布给出业务预期，线上同口径对照验证实际收益。验收同时观察累计资源开销、首字／端到端时延、任务成功率与 skill 检索质量。
