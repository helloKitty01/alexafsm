# KV Cache 优化：汇报大纲（建议）

> 讨论稿｜建议 4 页 PPT。主线：这笔账怎么算 → 我们改什么 → 一个会话省多少 → 整个业务省多少。本文只确定叙事与布局，示例数字不代表线上实测。

## 第 1 页｜现在到底在算什么？——输入拆成三份

**结论：输入很长，不代表每次都需要重算；优化要减少的是实算。**

- **布局：** 顶部一句结论；中间一条横向堆叠柱，绿色「已缓存」、红色「白算」、蓝色「必算」；用括号圈出红色＋蓝色，标注「实算」；底部放账目公式与优化目标。
- **概念：** 已缓存＝直接复用；白算＝本应缓存复用却重复计算；必算＝本次必要新增，需要新建 KV 的部分（首次载入单独标注）。重复追加相同内容不能视为不可优化的必要新增。
- **账目：** 输入＝已缓存＋白算＋必算；实算＝白算＋必算。
- **比例：** KV Cache 命中率＝已缓存／输入＝1−实算／输入。实算／输入是未命中率。
- **理论边界：** 给定输入方案，最低实算比例＝必算／输入，最高缓存命中率＝1−必算／输入。
- **目标：** **白算 → 0；在任务效果不下降的前提下，必要新增尽可能小。**

## 第 2 页｜我们怎么优化？——复用已有内容，减少重复注入

**结论：两类动作，分别减少白算和新增输入。**

- **布局：** 左右两栏，底部一条优化前后结果柱。
- **左栏「白算 → 0」：** 用上下文排布前后图解释稳定内容前置、动态内容后置、历史只追加；结合缓存驻留与路由，让可复用前缀实际命中。
- **右栏「必要新增尽可能小」：** 用「整份重复注入 → 只带变化」解释相同内容不重复追加、动态信息只传变化、按任务加载所需内容。
- **边界：** 白算归零是理想目标；线上需计入冷启动、缓存淘汰等损耗。输入精简后，应重新计算分母与理论边界。

## 第 3 页｜一个多轮对话能省多少？——历史越长，复用价值越明显

**结论：历史不断累积，缓存稳定后，后续调用主要计算新增。**

- **布局：** 左侧 75% 为横向堆叠柱状图，纵向排列 Q1—Q4，每轮各画「当前／优化后」两条；右侧 25% 放累计实算、节省量与降幅。所有柱表示完整输入、使用同一尺度，延续绿／红／蓝配色。
- **示例假设：** 首次载入 10K，每轮必要新增 2K；每轮一次模型调用；当前每轮全部重算，目标历史完全复用；无裁剪、淘汰。仅演示消除白算，不叠加输入精简收益。
- **逐轮实算：** 当前为 12K、14K、16K、18K；目标为 12K、2K、2K、2K。
- **会话总账：** **60K → 18K，减少 42K，实算降幅 70%。** 首轮成本完整保留；后续用有代表性的真实会话替换示例，并纳入工具循环的全部调用。

## 第 4 页｜全业务能省多少？——按真实流量加权

**结论：单个会话省 70%，不代表全业务省 70%；整体收益取决于业务结构与实际缓存可用性。**

- **布局：** 顶部总公式；左下两组业务分布对比；右下列数据需求与验证方式。
- **公式：** **整体实算降幅＝Σ（会话数量 × 每会话节省量）／Σ（会话数量 × 当前每会话实算量）**。按「场景类型 × 对话轮数」分组，每个会话计入全部模型调用；先汇总量，再算比例，不直接平均各组降幅。
- **示例：** 沿用第 3 页假设，单轮节省为 0，四轮节省 42K。按会话数，80% 单轮＋20% 四轮，整体降幅约 **39%**；20% 单轮＋80% 四轮，约 **67%**。
- **需要的数据：** 场景与轮数联合分布、每轮模型调用次数、历史与工具返回长度、必要新增规模，以及轮间间隔、冷启动、淘汰和路由带来的实际命中情况。不能只用平均轮数替代分布。
- **结果口径：** 理论分析给潜力，真实流量加权给预期，线上对照给实际收益。主指标先用实算 token 降幅；费用按实际计价折算，首字延迟通过实测验证，同时确认任务效果不下降。
