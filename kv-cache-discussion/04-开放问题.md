# 04 开放问题

待确认 / 待讨论的问题清单，随讨论更新。

## 待确认的系统事实

1. **UAT 具体指什么？**（用户画像 / 验收环境信息 / 其他？）
   它的变化频率决定放 L1 还是 L2。
2. **交互形态**：单 query 单次响应，还是多轮会话 + 会话内 agent loop？
   多轮会话才存在"检索内容原位刷新 vs 追加"的问题。
3. **工具/skill 目前如何注入？** 是进 API 的 tools 参数，还是拼在 prompt 文本里？
   每个 query 检索出的工具集合变化有多大？
4. **推理侧**：调用商用 API（哪家？决定断点机制）还是自建 vLLM/SGLang
   （决定是否可用 logits masking、是否需要会话一致性路由）？
5. **当前压缩的触发条件与幅度**：每轮做还是阈值触发？压缩后保留比例？
6. **有没有度量 KV cache 命中率？**（API 返回的 cached_tokens 字段 /
   自建推理的 prefix cache hit metrics）没有度量就无法验证任何优化。

## 待讨论的设计取舍

- 检索去重的粒度：条目级 ID 去重 vs 语义去重（后者可能引入不确定性，慎用）。
- 分代摘要的层数上限：摘要的摘要会不会失真过快？
- 结果指针（落盘 + 路径）的存储生命周期与会话恢复。
