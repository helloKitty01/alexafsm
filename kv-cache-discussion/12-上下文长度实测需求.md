# 12 上下文模块长度实测需求

## 目的

替换 11 中的假设值(Tools/L2 等),锁定收益测算的输入参数。
请基于内部实际线上数据统计,按下方 schema 返回。

## 测量口径(必须遵守)

1. **单位一律为 token 数**,使用与推理侧相同的 tokenizer;
2. 对**渲染后的最终序列**计数(即 chat template 拼接完成、含控制 token 的
   实际送入模型的序列),不是对原始文本或 JSON 计数;
3. 分布字段给 **均值 / p50 / p90**;固定不变的模块(如 L0)给单值即可;
4. 注明样本范围(时间窗、会话数、请求数)。

## 输出 schema

```json
{
  "meta": {
    "tokenizer": "模型名/tokenizer 标识",
    "sample_window": "如 2026-08-20 ~ 2026-08-26",
    "num_sessions": 0,
    "num_requests": 0
  },
  "modules": {
    "L0_system_static":  { "tokens": 0, "note": "system prompt 产品级静态部分" },
    "tools_block":       { "tokens": 0, "note": "工具全集渲染后的 Tools 块" },
    "L1_session":        { "mean": 0, "p50": 0, "p90": 0, "note": "用户级/会话级固定加载内容" },
    "L2_query_slot":     { "mean": 0, "p50": 0, "p90": 0, "note": "每 query 重写的槽位:skill search 结果+知识+用户信息" },
    "user_msg_per_query":{ "mean": 0, "p50": 0, "p90": 0, "note": "每轮 user 消息(query 本身,不含 L2)" },
    "assistant_per_iter":{ "mean": 0, "p50": 0, "p90": 0, "note": "每次 loop 迭代的 assistant 消息(含 tool call)" },
    "tool_result_per_iter": { "mean": 0, "p50": 0, "p90": 0, "note": "每次 loop 迭代的 tool result" }
  },
  "session_shape": {
    "queries_per_session":    { "mean": 0, "p50": 0, "p90": 0 },
    "iters_per_query":        { "mean": 0, "p50": 0, "p90": 0, "note": "每 query 的模型请求次数(loop 深度)" },
    "context_total_tokens":   { "mean": 0, "p50": 0, "p90": 0, "note": "会话结束时上下文总量" },
    "input_tokens_per_request": { "mean": 0, "p50": 0, "p90": 0 }
  },
  "optional_cache_stats": {
    "available": false,
    "cached_tokens_per_request": { "mean": 0, "p50": 0, "p90": 0 },
    "note": "若引擎已返回 cached_tokens 则填,用于直接校准命中基线(现估 25K/37K)"
  }
}
```

## 补充说明

- `L2_query_slot` 是最关键的待测项:它决定 query 切换点 miss 的固定项;
- 若某模块无法单独拆出,可给"包含关系 + 合计值"并在 note 里说明;
- 有裁剪/压缩逻辑触发的会话,请在 note 标注其占比,避免污染分布。
