02现状架构：分层意图正确，但 L2 是致命重写点

现状四层结构（从前到后）

L0 产品级 system / agent 关键原则 + 工具全集（tools 参数）　稳定 ✓
L1 用户级 固定加载的用户相关信息，与 query 无强相关，更新覆盖多轮对话　低频 ✓
L2 query级 按 query 检索的 skill / 知识 / 用户信息　每个 query 原位重写 ✗
L3 loop级 UAT（user / assistant / tool）消息流，本身追加式　却被 L2 连带全部失效

排布原则：变化频率必须从前到后单调递增，“原位重写”区绝不能排在“追加式”区之前——L2 恰好违反。

问题 ①　失效范围大，且随对话轮数线性增长

每个新 query 的 cache miss 量 = |L2| + |L3 全部历史|。对话越长浪费越大，而长对话恰恰是最需要缓存的场景。

问题 ②　检索内容与 query 的相关性绑定丢失

L2 是单例槽位，内容与它服务的 query 无显式对应，且物理上与当前 query 隔着整个历史，注意力利用效率最差。

问题 ③　历史证据被覆盖，时间线断裂

L2 每轮覆盖式更新，上一轮检索的 skill / 知识被冲掉。第 N 轮依赖第 N-2 轮的检索结果时证据已丢失；去重也无从谈起。

病灶只有一个：最易变的 L2 被放在了 UAT 历史之前

03目标方案：取消 L2 槽位，query 级内容下沉进消息流

目标排布（L0 → L1 → UAT 流，全程 append-only）

L0 产品级 system 关键原则 + 工具全集 + 全量 skill 索引（名称+一句话描述，静态）
L1 用户级 会话开始加载后冻结；中途更新攒批执行（低频事件，代价可接受）
UAT 流 query 级内容随各轮消息渐进进入：检索增量/环境增量随 user message，skill 正文以 tool result 追加——只追加，不修改

原 L2 的三类内容去向：知识/用户信息 → 随当轮 user message 注入；skill → 索引进 L0 + 正文按需 load；环境上下文 → 增量随消息注入。

效果：每轮前缀 = 上一轮的严格超集

没有任何区域被原位重写，缓存全程命中，只为当轮新增内容付 prefill 成本。

相关性与历史同时修复

  • 证据与 query 物理相邻、显式绑定，无需推断对应关系
  • 每轮 query 和它的证据一起留在时间线里，历史可查、可审计
  • 旧条目历史可见 → 条目级 ID 去重才得以成立
核心原则：上下文从前到后，变化频率单调递增；重写区永远不排在追加区之前

04渐进式加载：两条通道把 query 级内容送进消息流

通道一 · 被动注入（系统检索，随当轮 user message）

<turn_context>
  <env>首轮全量快照，后续只注入相对上轮的增量</env>
  <retrieved>仅未注入过的条目（ID 去重，固定排序）</retrieved>
  <skill_hint>检索 top-1：高置信给正文，低置信只给名字</skill_hint>
</turn_context>
<query>用户原文，永远放在消息最后</query>
  • 序列化完全确定性：标签顺序、排序规则固定，空块省略
  • 会话级状态仅两个：env_snapshot（算增量）、injected_ids（去重）
  • 一旦发出永不回改，重写统一攒到压缩时刻

通道二 · 主动加载（模型按需拉取 skill）

assistant: load_skill("deploy")
tool:      [skill 正文，以 tool result 追加进消息流]
  • L0 只放静态 skill 索引，正文由模型判断按需加载
  • 从“系统猜 top-k”变成模型自己决定要什么
  • 已加载 skill 在会话内持续可见，不重复检索

05压缩策略：miss 无法避免，只能摊销

反模式（每轮全量 miss）

  • 每轮滚动更新一个位于前部的 summary 块
  • 每轮删一点最旧消息（滑动窗口逐步前移）

推荐：阈值触发 + 双水位 + 分代冻结

  • 双水位：达到 ~80% 容量才压，一次压到 ~40%，避免“压一点→又满→再压”的抖动
  • 分代冻结：摘要块写入后冻结不再改动，成为新稳定前缀的一部分；两次压缩之间全部轮次命中
  • 自然边界：尽量在子任务完成时压缩，摘要质量最高
  • 所有重写历史的操作攒到同一次压缩，一次 miss 付清所有账

从远到近分级保真（可恢复优先于有损摘要）

内容压缩处理恢复方式
env 旧增量直接丢弃，摘要给当前快照无需恢复
retrieved 正文退化为 ID 指针按 ID 重拉
已加载 skill退化为“名称+已加载标记”load_skill
大 tool result落盘，留路径+摘要重新读取
远端对话结构化摘要（目标/结论/待办）—（有损）
近端 K 轮原文保留—
压缩的真正代价是信息丢失而非那一次 prefill——设计重心放在摘要保真与可恢复指针上
