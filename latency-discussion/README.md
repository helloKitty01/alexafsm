## 时延方程（分析框架）

每个请求的端到端时延：

```text
T ≈ Σ_{i=1..N} ( T_检索 + TTFT_i + n_out_i × t_decode + T_安全校验 + T_工具执行 )
```

- `N`：loop 次数，是**乘数**，减一次 loop 省下整个单 loop 成本（5~11s）。
- 其余各项是单 loop 内的**加数**。

代入当前实测值（TTFT 1300ms、增量 30ms/token、安全校验 500ms）：

| 阶段 | 典型值 | 备注 |
| --- | --- | --- |
| TTFT | 1300ms | prefill 占比待测，KV cache 命中后可望降到几百 ms |
| 增量生成 | 100~300 token → 3000~9000ms | **单 loop 内最大项**，常被低估 |
| 安全校验 | 500ms | 固定税，可分级/并行/缓存 |
| 工具执行 | 数百 ms ~ 数秒 | 因工具而异 |

反直觉结论：**单 loop 的大头不是 TTFT 而是增量生成**。
300 token 的工具调用光解码就 9s，是 TTFT 的 7 倍。
参数从 300 token 压到 50 token 一项省 7.5s，超过任何 TTFT 优化。

## 优先级（收益 × 落地成本）

| 序 | 项 | 对应原始问题点 | 预期收益 | 落地成本/风险 |
| --- | --- | --- | --- | --- |
| 0 | **埋点测量**：每请求拆解 loop 数分布、每 loop 各阶段耗时与 token 数 | 全部 | 所有优化的前提 | 低 |
| 1 | 参数 token 压缩（变量方案 / schema 改写 / 短句柄） | 2 | 单 loop 省数秒 | 设计已有；新语法有模型学习成本 |
| 2 | 安全校验分级 + 并行 + 缓存 | 3 | 单 loop 省最多 500ms | 纯框架改动，无模型风险 |
| 3 | 并行工具调用 + 高频序列合并为复合工具 | 4 | 减 N，每减一次省 5~11s | 需日志挖掘定位合并对象 |
| 4 | KV cache 排布落地（既有讨论） | 5 | TTFT 1300ms → 数百 ms | 设计已有 |
| 5 | skill 混合预加载（高置信被动注入） | 1 | 省 1 个 loop | 需检索置信度标定 |
| 6 | 模型路由 / 换模型评测 | 5 | 增量 token 时延 | 须以"正确率 × 时延"评测，正确率反噬 loop 数 |
| 7 | 快慢双系统 | 6 | 高频任务整体快一个量级 | 长期项，依赖轨迹数据积累 |
